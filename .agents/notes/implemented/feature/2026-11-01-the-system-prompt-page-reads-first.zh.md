# Agent Note：系统提示词页面先是用来读的

Status: implemented

## Problem

负责人点出这个页签的三个毛病，而每一个都源于同一个错误：这一页是按「编辑器」做的。

- **点卡片直接进编辑器。** 想读链条，却被丢进一个文本编辑器，于是浏览也像一次未保存的改动。
- **翻译开关没有作用。** 页面显示的是路径、字节数和状态词，三者本来就是读者的语言；一个在原文与译文之间切换的开关，没有东西可切。
- **新建只能建一个文件。** 列表把项目行整个过滤掉了（`row.scope !== 'project'`），于是链条的项目那一半不可见——而创建动作挑的是「第一个缺失的用户级候选」，永远建不出真正放进仓库的那些文件。

## 这五个问题的答案

1. **目的是什么。** 回答两件事：模型收到哪些文件、按什么顺序；某个文件不对时该改哪一个。
2. **给谁看。** 排查「我写的规则为什么没生效」的人需要顺序、作用域、状态、大小与路径；想在改之前先看清链条的人也是同一个读者。
3. **给谁改。** 同一个人，但是**有意为之**的第二步。这些是普通 Markdown 文件：有些是读者的全局偏好，有些是仓库的约定。
4. **改什么位置。** 恰好是那一行点名的文件，并且说明清楚：绝对路径加作用域（用户级根目录 / 项目目录），于是改 `~/AGENTS.md` 不会被误当成改仓库的。
5. **怎么交互。** 列表（只读、宿主加载顺序、整条链）→ 详情（路径、作用域、在提示词里的贡献、大小、占预算份额、文件正文）→ **编辑** 或 **删除**；**新建** 弹出一个按路径与作用域命名的候选菜单。

## Decision

- **整条链都列出来。** 不再过滤项目行；每行的备注里写明作用域，于是用户级与项目级不必靠第二列区分。
- **卡片打开只读详情**（`InstructionDetail`），编辑与删除在详情里。编辑器只能经由「编辑」到达。
- **新建是一个选择**，列出每个存在但缺失的候选，带路径与作用域。
- **这个页签的文本开关删掉。** 工具栏保留搜索与视图切换；这里没有可翻译的东西。

## Alternatives considered

- **保留一键进编辑器，另加预览开关。** 否决：破坏性的默认还在——第一次点击仍然替读者决定了模式。
- **把列表分成「用户级 / 项目」两段。** 暂时否决：共享列表渲染器画的是一张清单，而分组头每组多一行；备注里的作用域已经回答了这个问题。若链条将来长到十几个文件，值得重看。
- **保留「默认建一个文件」的创建动作。** 否决：它替读者挑了一个没要求的文件，而项目候选——要进版本控制的那些——根本到不了。

## Consequences

- 浏览链条不会改动任何东西；编辑是读者主动迈出的一步。
- 读者第一次能从这一页创建项目里的 `AGENTS.md`。
- 用户文档里的页面描述随之更新。
