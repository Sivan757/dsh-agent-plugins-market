# Agent Note：详情弹窗的行与文档正文

Status: implemented

## Problem

详情弹窗的展开行与文档正文和原型不一致，而且差别是结构性的，不是外观性的：

1. **行的形态就不对。** 原型的详情行是一条三列带——名称、单行摘要、贴右端的箭头——装在一条带边框的分组里，带悬停底色、展开时染色的表头、以及藏在一根细线后的正文。平台的 `DisclosureRow` 是 24px 的单行流式行，箭头**在标题之前**且只在悬停时出现，而且它既不画悬停底色也不画展开底色。从外面套样式改不了箭头的位置、撑不开行高、也补不上那两层底色。
2. **六个表面各画一套。** 套件详情、用户条目详情与 LSP 详情各自拼自己的分组与正文类，于是行的宽度、高度、内边距与正文底色彼此都不一样。
3. **frontmatter 被重新呈现，而不是照原样展示。** `MarkdownDocument` 把文档的 YAML 渲染成 `元数据` 标题下的定义列表，而原型是把它按原文放在渲染正文之上。同一个组件还支撑每个编辑器的预览窗格，于是预览与它正在预览的文件不一致。
4. **详情的概览写错了事实。** 用户条目详情写着 `根目录` 而没有最近变更，原型写的是磁盘路径与文件的最后修改；它的文档分组的标题是 `技能` / `命令` / `代理角色`，而不是 `技能文档` / `命令文档` / `角色定义`。

## Decision

- **一个共享的行组件 `ui/DetailRows.tsx`。** `DetailRows` 画带边框的分组外框，`DetailRow` 画那条带：`minmax(110px, max-content) · minmax(0, 1fr) · 14px`、9px/12px 内边距、等宽半粗名称、单行省略的摘要、关闭时向右展开时向下的右端箭头、悬停 `interactive-bg-hover`、展开时 `state-business-tertiary`，正文 12px/14px，藏在一根 `border-l2` 细线之后、底色是悬停填充。它的样式表带的是原型的数值，三个调用点因此不会再各自漂移。
- **行用原型自己的几何，而不是平台的。** 一条 42px、三列、箭头在右端的带，与平台那条 24px 流式行本就是两种控件；插件的弹窗是它自己的界面，而原型就是评审它时对照的那份基准。
- **`MarkdownDocument` 按原文展示 frontmatter。** 原文块放在渲染正文之上，用等宽、带边框、`markdown-code-block` 底色的盒子——每个编辑器的预览窗格现在也一样，预览因此对文件诚实。
- **`frontmatter()` 返回它匹配到的原文块**，消费方不必再解析一遍文档。
- **详情的概览写原型写的事实。** 用户条目详情报告磁盘路径与条目文件的最后修改，文档分组按页面种类取标题。两个时间戳都来自文件系统——套件详情取检出目录，面板条目取各自的条目文件，在面板列表组装处统一打戳。

## Alternatives considered

- **保留 `DisclosureRow` 并从外面叠类。** 否决：`rowClassName`、`titleClassName`、`chevronClassName` 碰到的是它的皮，不是它的骨。箭头靠前、24px 固定行高、以及缺失的悬停/展开底色，都是组件自己的决定，而每一条都正是评审者看得见的差别。
- **把 frontmatter 渲染成 YAML 树。** 否决，改为原文块：树会把同一批键重新呈现成文件从未有过的形状，并且丢掉注释、引号与顺序——而那恰恰是去看 frontmatter 的理由。
- **用户条目详情保留 `根目录` 并去掉最近变更。** 否决：用户条目的路径就是文件自身的位置，原型把它命名为磁盘路径；而「上次什么时候改的」正是这个弹窗无法从卡片回答的那一件事。
- **相对时间文案写死在弹窗里。** 否决：分桶取自宿主的 `relativeTime`，两个表面给同一个文件定时间才会一致；词语本身留在本插件的词典里。
- **每次读取面板时为每个条目文件做一次 stat。** 采纳：面板列表本来就要读每个文件的文本，所以这只是既有读取旁边多一次系统调用，却让两个来源——用户文件与套件文件——走同一条代码路径。

## Risks

- 这个共享行是详情唯一的行形态，将来需要前置图标的新行只能扩展 `DetailRow`，而不是在外面拼。
- 按原文展示 frontmatter 意味着嵌套结构的 frontmatter 不再有折叠视图；这个块有多长，文件的头部就有多长。
- 面板列表现在会为每个条目文件做一次 stat，条目数量异常大的面板会多付一次系统调用。
