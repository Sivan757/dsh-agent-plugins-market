# Agent Note：重连中的行会说已经断了多久

Status: implemented

## Problem

负责人清单里有一句面板只能回答一半：「断开不知道为什么重连连大几十秒连不上」。行上已经说了第几次（`第 2/5 次`）、下次多久后重试（`45 秒后重试`）和最后的错误，所以「多久一次」和「还有多久」都有了。没有任何界面说**这次断线已经持续了多久**——正是这个数字把「它在反复重试」变成「它已经断了一分半」。

## Decision

- **连接那句话带上已经过去的时间。** `mcpConnectionNote` 读 `connection.since`（supervisor 本来就记录），在次数与倒计时之间补上 `已断开 46 秒`（超过九十秒则 `已断开 3 分钟`）。不足一秒则不说，刚断的行不谎称断线。
- **仍然只有一句话。** 次数、已断开、下次重试、最后错误：四个事实，一句话，按读者提问的顺序排列。

## Alternatives considered

- **另起一行「已断开」或一个徽章。** 否决：每次重绘都会重复，而卡片只有一行是有原因的；这个事实属于已经在报告重连的那句话。
- **一个实时跳动的计数器。** 否决：面板本来就按 supervisor 自己的计时器安排下一次读取，数字会在真有变化时刷新；第二个计时器只会让它动起来而已。
- **永远显示秒。** 否决：超过九十秒读者是按分钟想的，而「已断开 187 秒」是让人自己去除法。

## Consequences

- 长时间断线一眼就能与刚断区分开，不必打开详情。
- 详情的连接句与卡片的备注用的是同一句话，两者不会漂移。

## Verification

- `packages/market-ui/test/mcp-connection-wait.test.ts` 钉住秒（46 秒）与分钟（3 分钟）两种形态，以及不足一秒时不追加任何内容。
- `packages/market-bundle/test/integration/client-mcp-detail-actions.test.ts` 钉住「重连已停止」那句，现在会传入行自己的时钟，避免把 epoch 时间戳读成几百分钟的断线。
- 四个类型检查、`check:refactor` 与全量测试通过。
