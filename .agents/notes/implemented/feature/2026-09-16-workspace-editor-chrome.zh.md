# Agent Note：六个编辑器的弹窗外壳

Status: implemented

部分被[编辑器外壳清理记录](./2026-09-16-workspace-editor-chrome-cleanup.md)取代：编辑器不再有副行与字段提示，条目正文由真正的编辑器承载，身份行移到窗格之上以保持两栏齐平。

## Problem

工作台的卡片与详情已经按原型重画，编辑器却停在上一版自有的外壳上。把它们与原型自身的实现逐页对照后，翻出五处此前没被截图核对到的形态差异：

1. **没有标题副行。** 原型每个编辑器都在标题下方说明这个弹窗在做什么——新建时写清落盘目标，编辑时写 `<名称> · <路径>`，MCP/LSP 写清声明落在哪个文件。面板编辑器只有一行标题，其中一个还在这格里放了一句无关的话。
2. **两个窗格没有文档身份。** 原型左窗格的头里写着正在编辑的文件名（`SKILL.md`、`<名称>.md`），右窗格标注预览是实时的；面板编辑器只显示两个朴素词。
3. **底部没有提示。** 原型会说明保存之后会发生什么——新建时是 `创建后立即生效，可在列表里停用`，编辑时是 `未保存的改动会在关闭时丢失`——而且新建时按钮就叫 `创建`。
4. **少一个字段。** 命令的「参数提示」写在 frontmatter 里，原型在名称旁给了它一个控件；面板编辑器没有地方放它，只能手改 YAML 才能设置。
5. **服务编辑器只是光秃秃的新增表单。** 没有副行、没有底部提示、提交按钮不是主操作样式，而且名称输入框浮在模式切换之上，而不是和传输方式一起落在原型放它们的身份行上。

## Decision

- **一套表单样式表持有字段几何。** `ui/form.module.css` 承载原型的编辑器原语——12px 半粗的次级色标签，12px 输入框配 7/9 内边距、8px 圆角与 1px `border-l2` 边，240px 等宽编辑框（其后换成真正的编辑器，见文档编辑器记录），分段控件画成一条带边框的轨道，虚线只读框，行编辑器配扁平 24px 破坏性按钮，以及 26px 带边框的「再加一条」动作。编辑器的字段是由这张表样式化的原生控件，而不是平台 `Input`（后者是 14px 文字配发丝 `border-l4` 边的另一种控件）；面板自己的搜索框与卡片仍用平台组件。
- **六个编辑器共用一个头部形态。** 只有标题：说明落盘目标的副行已从所有编辑器移除，因为标题、窗格 chip 与表单自身的字段已经说明了这个弹窗会做什么。
- **两个窗格各带一颗 chip。** 编辑窗格显示文档自身的文件名；预览窗格显示 `实时`，因为预览是随每次按键由草稿渲染、而不是保存后才渲染。
- **底部提示说的是后果，不是机制。** 新建时说明条目立即生效、可在列表里停用；编辑时说明未保存的改动会丢失。提交按钮新建时为 `创建`，编辑时为 `保存`。
- **命令编辑器把 `名称` 与 `参数提示` 配对。** 参数提示是真实的 frontmatter（`argument-hint`，同时接受 camelCase 别名），通过与文本域同一份文档读写，因此两种视图不可能互相矛盾。
- **面板文案用原型的写法。** `名称` / `文档` / `命令正文` / `系统提示词` 取代带括号的标签；原型写成提示的那些说明直接删除而非搬位置；条目的文档标签改为编辑器的无障碍名称，不再占一行可见行。
- **服务编辑器用同一套外壳，并多一行控件。** `名称` 以及 MCP 的 `传输方式` 由 `ServerConfigEditor` 通过 `nameField` 渲染在模式相关正文之上——身份字段在表单与 JSON 两种视图下都保持可见，MCP 的名称输入框占据真实的栅格单元，而不是浮在模式切换之上。OAuth 变成带 `OAuth` 图例的 `fieldset`，把复选框与 scope 输入框包在一起。
- **服务表单按原型纵向堆叠。** `命令`、`URL`、`工作目录` 与各行的编辑器都跨两列；只有名称/传输方式这一对使用两列行。
- **来源编辑器写出它的固定事实。** 编辑态显示只读的 `来源 ID` 与只读的 `作用域`（`本地目录 · N 个套件`），分段文案改为原型的 `Git 仓库` / `归档包` / `本地路径`，底部是朴素的 `移除来源`。
- **`ServerConfigEditor` 扩了名称槽，而不是再加一个编辑器。** 服务编辑器本来就共用一份由单个 JSON 文档支撑的结构化表单；缺的只是身份字段放在哪里，所以由该组件接收这个字段，而不是让调用方各自复制它的栅格。

## Alternatives considered

- **在编辑器正文里继续用平台 `Input`。** 否决：把一个 14px 发丝边控件摆在 12px `border-l2` 控件旁边，正是表单看起来像两套系统拼起来的原因。编辑器是一套表单语言，而原型的几何就是评审者打开截图对照的那份基准。
- **保留带括号的标签、不加提示。** 否决：原型那句说明放在字段下方比塞进标签更易读，而一个承担校验规则的标签没法同时承担文档用途。
- **按原型给角色表单加 `工具` 选择器。** 否决：原型那颗控件是只有两个选项的演示（`全部` / `只读`），背后没有产品语义——本面板在 frontmatter 里存的是一个任意 `tools` 列表，把其中一个选项映射上去就等于发明一个 executor 并未实现的含义。改为写出实际生效的路由。
- **让条目编辑器在保存时重命名条目。** 否决：用户内容条目以文件名为主键，名字就是身份；编辑器改为显示将要写入的路径、并让名字保持固定，而不是提供一个存储层无法兑现的编辑。
- **给 MCP 与 LSP 在卡片上加入口编辑。** 暂不采纳：既有服务的配置就在它的详情弹窗里就地编辑，那里拿得到服务已解析、已脱敏的配置；再加一个编辑器会造出一条校验信息更少的路径。
- **把来源编辑器的字段提示塞进它的 `description` 槽。** 否决：提示应当待在它所解释的字段下方——原型正是这么放的，来源编辑器本来也有两处这么做。
- **为新建弹窗再抄一份服务表单。** 否决：`ServerConfigEditor` 已经拥有 JSON/表单的双形态、各行的编辑器，以及与详情弹窗共用的有效性契约；抄一份只会与它漂移。

## Risks

- 这张表单样式表按设计只服务编辑器：加在编辑器之外的面板字段沿用平台几何——对工具栏是对的，对弹窗内部是错的。
- 副行把 `~/.agents` 写死为用户内容根，这是默认值；设置了 `DSH_AGENTS_HOME` 的部署在新建流程里会看到默认路径——那一步客户端拿不到绝对路径。
- `ServerConfigEditor` 的 `nameField` 是可选的，将来漏传的调用点会退回旧的单列传输方式位置；现有两个调用点都传了。
- 条目编辑器「名称与第二个字段配对」只作用于新建态、并以 render prop 表达，因此将来要加短身份字段得由调用方加，而不是共用编辑器。
