# Agent Note：一个对象一个名字，页签说自己装了什么

Status: implemented部分被[系统提示词笔记](../bug-fix/2026-10-31-the-tab-is-the-system-prompt.zh.md)取代：页签叫「系统提示词」而不是「规则」。本笔记其余部分（套件作为单元、服务页一个名词、创作页副标题）仍然有效。

## Problem

对九个分段做信息架构复盘后发现：同一个对象有好几个名字，而好几个页签名的却是别的东西。

- **可安装单元在读者要做决定的三处叫「插件」。** 搜索框、空行、归属标签与卸载对话框都说「插件」（英文更是 `plugin` 与 `Plugin` 两个键不一致），而文件其余部分与 CONTEXT.md 全都叫它**套件（suite）**。在卸载确认框前，读者分不清要移除的是一个套件还是整个扩展。
- **规则页签叫「系统提示词」**，而这个词在同一行还指另外两个东西（专家编辑器的正文框、输出风格的注入）。三份文档与 locale 文件自己的注释早已把它叫「规则」。
- **服务页签内部有三个名词**：页签叫「连接器」，删除对话框与每条状态句却叫「服务」；页签叫「语言引擎」，里面有「语言引擎服务」与「服务器」。
- **三个创作页的副标题在复述卡片自己的归属标签**（「插件带来的只读，自建的可改」），从不说这一页装的是什么——而那正是技能、快捷指令、专家唯一能显出区别的地方。
- **首次进入报告了一个没人做过的搜索**：空市场说「没有匹配的插件」，而唯一的出路是一个只有图标的刷新按钮。
- **32 个键（64 行）渲染不到任何地方**，工作区文档还描述着一个代码树里并不存在的「收纳页签」控件。

## Decision

- **套件就是可安装单元，处处如此。** 搜索占位、空行、卸载标题与描述、归属标签、连接器的来源标签、输出风格的来源标签都写「套件 / Suite」；「插件」只留给这个扩展本身。
- **页签叫「规则」。** 页面内文案跟随（规则页面不可用、读取规则链失败），专家编辑器的正文框改为「角色指令」，于是一个说法不再指名两个控件。
- **每个服务页签内部只用一个对象名词。** 页签仍是集合（连接器 / 语言引擎）；行是 MCP 服务或语言服务器，副标题说明对象与这一页对它做什么。
- **创作页副标题说对象，不说可编辑性**：「模型按需读取的能力说明」「输入 /名称 调用，可带参数」「可委派的子代理角色」。归属已由标签承担，铅笔本来就只出现在可编辑处。
- **首次进入要说出下一步动作。** 空市场说「还没有套件：点右上角 ↻ 获取列表」；筛选或搜索落空时仍是「没有匹配的套件」。读取成功的零连接器说「没有连接器」，因为没人搜索过。
- **删掉渲染不到的东西。** 32 个死键从两本词典里删除，工作区文档里关于收纳的那一章换成真实存在的排序行为。

## Alternatives considered

- **可安装单元继续叫「插件」、来源叫「套件」。** 否决：来源页已经用「来源套件」称呼来源，套件这个词已被占用；一个对象两个名字正是要修掉的缺陷。
- **把页签也改名成「规则」与「语言服务器」。** 否决：页签是集合，而「语言服务器」（行）放在叫「语言引擎」的页签下，正是两个词该承担的区别。只改了页面内文案。
- **把文档描述的收纳控件做回来。** 暂时否决：它需要新组件与独立的设计评审；文档现在与产品一致，真要恢复可以按设计重建。

## Consequences

- 读者在市场里看到的词，和文档、CONTEXT.md、套件详情里用的是同一个。
- 规则页签可以用三份文档给它的名字找到。
- 同一个说法（系统提示词）不再指向两个控件。
- 首次进入会告诉读者该按哪里。
- 64 行不可达文案与一章描述不存在控件的文档消失。

## Verification

- 在 `market-dev` 对构建产物实测：页签行读作 … 连接器 规则 输出风格 钩子 语言引擎；市场占位是「搜索套件…」；技能卡片标签读作「套件」；四个副标题如约。
- `packages/market-ui/test/client-locales.test.ts` 的常用名配对与页头字数预算保持通过；LSP 缩写改挂在创建动作上，因为 20 字的副标题装不下它。
- 四个类型检查、`check:refactor` 与全量测试通过。
