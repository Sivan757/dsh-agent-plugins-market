# Agent Note：每个可撰写的面都能起草，靠同一次调用

Status: implemented

## Problem

五个面持有「可撰写文档」——技能、快捷指令、专家角色、输出风格、系统提示词的一段——而每一个都打开一个编辑器，要求人从空白页写起。产品其实知道这份文档该长什么样（格式是固定的：frontmatter 键、面向模型的正文），却仍然要人凭记忆去拼。

## Decision

- **一条起草路由，不是五条。** `POST /api/agent-plugins/ai-draft` 接收「哪个面 + 想要什么」，回答成品。客户端从不发送提示词、模型名或系统消息，因此部署的模型不会被用来做产品没有描述过的事。
- **每个面共用同一个字段组件。** `AiDraftField` 在任何面都是同一行：说你要什么、按下起草、在你本来就在看的编辑器里复核答案。它是建议而不是写入：不保存，不喜欢的草稿只值一次撤销。
- **模型是部署自己的默认模型。** 插件在调用时通过 `agentDefaultModel` 解析它，也就是宿主用于辅助工作的同一个选择。插件不自选模型、不持凭据、不做兜底：没有默认模型的部署会被告知这一点，而不是被塞进一个它没选过的东西。
- **与翻译共用同一次调用。** 路由解析、最省力档位、流式读取与终态失败的映射都收进一个模块（`market-translation/runtime/host/auxiliary-model-call.ts`），因为翻译出于同样的理由做同样的调用；起草只增加自己的边界、提示词与答案形状。
- **限流就是限流。** 提供方回 429 或用量上限消息时，跨出为 `ai-provider-limited`，字段用读者的语言说明额度用尽、编辑器未被改动。缺少默认模型则回 409 并给出自己的句子。
- **服务配置不在范围内。** 从一句话起草 MCP 或语言服务器声明产出的是配置而不是散文，复核方式也不同。

- **预设是「先建议、再批准」。** `POST ai-preset` 接收意图与管理器正在展示的行，模型回答名字、理由和选择。每个 id 都要通过所提供行的校验，重复项折叠，数量有上限；管理器在创建之前把三者都摆出来，然后走它自己的创建路径。一个什么都没选中的答案按「无法处理」拒绝，而不是变成一个空预设。

## Alternatives considered

- **每个面板各写一套提示词与调用。** 否决：五个会漂移的地方，而每个面的格式知识本来各自只有一处。
- **把起草当作一次 agent 循环。** 否决：这是没有会话、没有工具、没有日志的辅助工作；用 agent 轮次只会更慢、更贵、更难限界。
- **浏览器直接调用提供方。** 否决：等于把凭据放进页面，并让页面里任何脚本都能花掉部署的额度。
- **把共享助手放进 market-bundle。** 被架构规则否决：翻译不能导入 bundle，因此助手必须放在两边都能取到的地方。

## Consequences

- 五个面获得了起草行，而没有五份实现。
- 每按一次就是默认路由上的一次模型调用，上限 1500 输出 token、60 秒。
- 这个功能需要配置好的默认模型；没有时它会如实说明，而不是含糊地失败。

## Verification

- `ai-draft-routes.test.ts` 同时覆盖建议路由（多 5 条）：不在提供列表里的 id 会被丢弃；带代码围栏的答案可解析；什么都没选中的答案被拒绝；空意图或空候选列表不会触达模型；提供方限流保留自己的代码。

- `packages/market-bundle/test/integration/ai-draft-routes.test.ts`（6 条）：成品会报出产生它的路由；每个面有自己的格式规则；未知面、空意图、超长意图在调用模型之前就被拒绝；缺少模型是 409；提供方失败是 502；限流是 `ai-provider-limited`；GET 与跨源写入被拒绝。
- `packages/market-ui/test/ai-draft-field.test.ts`（3 条）：发送的就是意图；答案带着模型名进入编辑器；没有可问的内容时按钮保持禁用；失败出现在告警行。
- 在 `market-dev` 实测：技能与输出风格编辑器里都出现该行，请求确实到达部署的模型，提供方的 429 渲染为「模型的用量额度已用尽或被限流…」且编辑器未被改动。本次会话没有观察到成功的起草，因为部署的模型路由正在限流；成功路径由路由测试与 `createLlmDraftPort` 走同一条翻译已在用的装配链覆盖。
- 全量测试 2535 通过，门禁干净。
