# Agent Note: 横跨六个面的通用翻译层

Status: implemented

## Problem

市场渲染的上游 catalog 以英文撰写，因此 `zh` 部署看到的是中文界面里嵌着英文数据。套件描述，技能、快捷指令、专家三者的描述，以及 MCP 每个工具的说明，全都原样进入面板。[描述本地化 note](2026-10-03-description-localization.md) 只补上了一个面上的一个字段；同一个缺陷在其余各面渲染的每一条描述上依然存在。

catalog 不归我们编辑。一个 source 是别人仓库的 checkout，每次更新都会刷新，所以翻译不能写回 manifest。它必须放在 catalog 旁边，在输出的路上应用。

这层提供无需用户 key 的翻译路径，但网络和 provider 仍可能失败。原文必须始终可读。进入模型上下文的提示词与工具描述是另一份产物，不参与界面翻译。

## Decision

本地化是共享渲染层，不是某张卡片独有的逻辑。翻译单元指明一个字段。Provider 链翻译其中的正文，缓存记录答案。各个面在显示译文的同时保留作者身份标识。

### 一条单元，六个面

单元携带面、稳定实体 id、角色（`description` 或 `document`）与源文本。持久缓存按实体、文本、目标和链标识取键，同一字段可跨重启复用。内存文本索引让同文在不同实体或角色间共享已知答案；它不是持久的全局文本索引，新实体的首次读取仍可能调用 provider。每批的条数与字符数、并发批数都有上限，正文分段由[三态阅读决策](2026-10-06-translation-reading-and-lifecycle.zh.md)拥有。

| 面       | 译文                     |
| -------- | ------------------------ |
| 市场     | 套件描述                 |
| 技能     | 技能描述                 |
| 快捷指令 | 命令描述                 |
| 专家     | 角色描述                 |
| MCP      | 每个工具一行             |
| LSP      | 无 —— 该条目没有描述字段 |

### 有序回退链

Provider 按固定顺序运行：Google Translate、Microsoft Translator、用户的默认模型。第一个有效答案胜出，抛错、超时或返回条数不符时尝试下一家。两家公开端点不需要用户 key；默认模型是额外的回退，可以接受领域词汇提示，但不保证质量更高。都没有答案时显示上游原文。

Google 的硬超时为 3 秒，Microsoft 为 15 秒，模型为 30 秒。链通过独立的 Promise 竞速推进回退，不依赖 provider 响应取消信号。超时 provider 的迟到结果不能替换已经选定的答案。失败的 provider 被熔断，重新开启翻译、清空缓存或重启后允许重试。调用方取消不计为 provider 失败，并直接停止整条链。公开端点不提供可用性或延迟保证。

### 缓存与键

译文以目标 locale、单元的面、id、角色与原文，以及 provider 链的标识，共同做 SHA-256 摘要作为缓存键。按内容寻址意味着重写了文本的实体会重新翻译，而只是提升版本号的实体保留译文。条目不过期；设置卡里有一个清空整个缓存的按钮，下次打开面板会重新翻译。

键包含 provider 链标识，因此更换链后不会静默供出旧链的结果。每条记录另加升级标记，只是在增加状态以复现这个自动未命中。记录仍保存实际作答的 provider，供运维检查。

### 哪些文本需要翻译

`needsTranslation` 按目标语言检查汉字与拉丁字母的主导关系，而不是只因出现一个汉字就拒发。`zh` 目标翻译含拉丁字母且汉字不占主导的文本；`en` 目标翻译任何含汉字的文本，包括以英文为主而夹有中文的正文。这是中英启发式判断，不是通用语言识别；混合语言文本仍有边界。判空可以 trim，存储与返回的原文、译文不因此裁剪。

### 遮蔽

Provider 可能改变技术文本。发送前，遮蔽层用占位符替换行内代码、URL、尖括号片段、`${VAR}` 引用，以及固定术语表中的词。术语表包括 `MCP`、`LSP`、`DSH`、`CLI`、`API`、`JSON`、`HTTP`、`URL` 和 `SDK`。还原时，每个受保护的占位符必须恰好出现一次，正文结构标记必须完整且有序。

[Provider 适配器](../../../../src/runtime/host/translation-providers.ts)对符合条件的标记损坏执行一次非递归修复。源文本必须包含 AST 标记，答案去掉标记后必须仍有非空白正文。全空白、仅标记的答案，以及无 AST 标记的普通描述，不进入修复。适配器按原段落的标记重新拆出 text 叶节点，重新遮蔽后交给同一家 provider 翻译，再在本地拼回原标记。它不从损坏答案中猜测缺失文字或标记。

每次外层 provider 调用的修复预算最多为 60 个非空 text 叶节点，分成最多 3 个子批次，每批最多 20 个。这是应用侧保护预算，不是厂商限制。所有子调用共享原信号与外层 provider 时限，不延期。单个叶节点可以自然省略，但受保护内容不能丢失，重组后的整段必须仍有正文。

在原时限内正常返回的混合结果保留已验证的条目。无效描述、无正文的结构化答案、修复失败或超预算的条目返回空槽，由本地化器按文本退避，显示原文，不缓存为成功，也不立即转交下一家。全部条目失败时走整批回退。时限耗尽仍触发整批回退，调用方取消则终止整批，两种情况都不保证保留本次尚未返回的有效条目。修复不保证 provider 总能给出有效答案。

### 渲染：翻译正文，不改名称

名称从不翻译。它是用户输入、搜索、排序、复制、并与上游文档对照的那个标识，收集器不会为它产出任何单元，因此两种视图渲染的是同一个字符串。描述没有这重身份，所以直接渲染译文，作者原文只隔着面板视图开关的一次按下。

### 设置与作用域

界面字典决定目标：以 `en` 开头的偏好解析为 `en`，其余与缺席解析为 `zh`。`interfaceLanguageTranslates` 仅决定开关默认值，不能拒绝显式开启的英文目标。生效开关控制显示与新工作，关闭保留已完成缓存。此处的语言门禁与生命周期由[三态阅读与翻译生命周期](2026-10-06-translation-reading-and-lifecycle.zh.md)部分取代；本记录仍拥有 provider 顺序、持久键和模型隔离。注入模型的提示词与工具描述始终保持作者语言。

## Alternatives considered

**在客户端翻译。** 因分层被否。`src/client/**` 不得 import `node:**`，也不持有持久缓存；浏览器侧翻译器会在每次页面加载时重新调用 provider，且无法跨重启记住结果。浏览器这一半渲染 node 这一半算好的译文，不自己算。

**只做两个免费机器翻译端点。** 被否：术语保真度是通用机器翻译引擎的弱项——`skill`、`suite`、`surface` 回来的译法前后不一致，专有名词在两次调用之间漂移。用户自己的模型留在链上，作为可以被告知如何呈现本领域词汇的那一档；只有部署配置了它，链才会走到它。

**把 provider 从缓存键里去掉。** 被否：键就只剩内容，换了引擎的部署会永远继续供出旧引擎的文本。手工失效或靠版本号失效是伪装的版本标记；把 provider 标识折进键里让未命中自动发生。

**按来源分片缓存。** 暂缓：单文件每次 flush 整份原子重写，清空按钮提供显式回收。分片会引入多文件迁移与并发写问题；是否值得应由可复现的写入成本测量决定，而不是沿用旧 catalog 的体量。

## Consequences

没有可用答案时，界面保留作者原文，不阻塞首屏。持久缓存命中时不调用 provider；缓存缺失或损坏时不能承诺零调用。名称不参与翻译，因此搜索、排序、复制、斜杠调用和名称的 `aria-label` 保持作者文本。

代价是：

- **公开端点无 key，因此没有承诺。** 限流或端点下线会静默降级到下一级，既不通知用户，也没有「当前生效 provider」的读数可供诊断。
- **翻译质量取决于 provider。** 遮蔽层保护技术内容与固定术语，模型可以接受领域词汇提示，但不能保证它的译文总是优于机器翻译。
- **被阻断的端点会消耗超时预算。** 熔断防止后续批次继续尝试同一家；没有任何一级承诺固定响应时间。
- **缓存随 catalog 增长。** 按内容寻址的键只增不减；清空按钮是用户把增长归零的那一环，而单文件每次 flush 都要整份重写。
