# Agent Note：卡片是一个区域，只有一个打开控件，并且用文字说出状态

Status: implemented

部分取代[卡片键盘守卫笔记](../bug-fix/2026-10-30-card-controls-answer-their-own-keys.zh.md)：那道守卫不再需要，卡片已无键盘处理；该笔记的三处命名决定仍然有效。

## Problem

无障碍评审在共享卡片上留了两条结论，它们来自同一个决定：卡片被画成了按钮。

**按钮里装着控件。** 卡片带 `role="button"`，里面却有开关、编辑器和最多两个图标动作。ARIA 1.2 把按钮的后代视为表现型内容，辅助技术可能把这些控件压平进卡片名字；而且每张卡本身是一个 Tab 停点、控件又是若干停点（连接器界面每行三个）。

**状态只由颜色承载。** 卡片状态就是前缘一条 3px 边条，没有文字、没有描述。分不清边条颜色、或者根本看不见的读者，从这一行得不到任何状态。

## Decision

- **卡片是区域，名字才是它的控件。** `ResourceCard` 不再接收 `role`、`tabIndex` 或 keydown 处理器。指针仍然可以点卡片任意位置打开，而 `CardIdentity` 把条目名字渲染成真正的 `<button data-card-open>`，并阻止自己的点击冒泡，保证一次按下只打开一次。旁边那些控件是打开控件的兄弟，而不是某个按钮的后代。
- **删除 `interactiveCardProps`。** 它存在的理由就是把卡片做成按钮；留着它等于邀请这种形状回来。
- **状态也说成文字。** 条目提供 `stateLabel` 时，`ResourceCard` 在身份行渲染一个视觉隐藏的说明；连接器、语言引擎与市场界面用它们详情对话框里已有的同一个助手提供（`已停用`、`运行中`、`未安装`）。

## Alternatives considered

- **保留 `role="button"`，另加 `aria-description` 说状态。** 否决：压平嵌套控件是更大的缺陷，描述解决不了。
- **把整行身份条都做成打开控件。** 否决：那一行还带着版本徽章与出处标签，它们不属于「打开这个条目」。
- **把状态渲染成可见徽章。** 暂时否决：边条是设计好的提示，而 971 张未安装卡上再挂一枚徽章只是噪音；隐藏的文字服务需要它的读者，不改变视觉语言。

## Consequences

- 打开一张卡是一个 Tab 停点，名字就是条目名；控件是各自独立的停点与名字。
- 读屏在控件之前先听到这一行的状态。
- 每个列出条目的界面自己负责它需要的状态词；不提供的界面保持沉默，而不是猜一个。

## Verification

- `packages/market-ui/test/resource-surface.test.ts` 断言卡片没有角色、没有停点，名字按钮能打开、点卡片仍能打开、打开控件不会重复触发，以及提供的状态标签出现在隐藏元素里。
- `packages/market-ui/test/market-section-render.test.ts` 断言市场三种状态各自带着文字（已启用 / 已停用 / 未安装）。
- `packages/market-ui/test/resource-surface-parity.test.ts` 在两个界面上钉住「区域」契约。
- 在 `market-dev` 对构建产物实测：120 张卡既无角色也无停点，打开控件读作「mattpocock-skills」，被停用的那张带隐藏文字「已停用」；聚焦打开控件按 Enter 打开了该套件详情。
