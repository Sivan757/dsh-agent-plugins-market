# Agent Note：演示走查改掉的四件事

Status: implemented

## Problem

演示 profile 走查给出四条意见，每条都有截图：AI 辅助是一行一次性输入，而读者期待的是可继续调整、可换模型的会话；过滤条并非每个面都给出三条件；钩子面根本没有配置入口；预设管理器带着解释性段落、半空的标签栏，而且同一个输出风格在两个页面上讲了两套说法。

## Decision

- **草稿可以升级成会话。** `POST ai-session` 把任务写成会话的第一条消息，回答会话 id 与所属工作区。读者点开会话，改需求、像任何会话一样换模型，然后发送。行内起草保留给快速场景，会话是迭代的路径。
- **过滤条保留每一个声明的切签。** 零计数的切签仍是读者学会去问的问题，隐藏它只会让各个面在自家语法上互相矛盾。钩子面拿到了这一对（它的行可能来自套件，也可能来自读者自己的 hooks.json），语言引擎面拿到了它从未渲染过的工具栏，输出风格面在没有用户风格时显示「用户 0」。
- **钩子可以配置，AI 负责填表。** `POST user-hooks/draft` 给出事件与命令，`POST user-hooks/save` 把条目追加进读者自己的 `~/.agents/hooks/hooks.json`。追加会顺着文件既有的形状合并，并拒绝完全重复的条目；表单始终可改，所以模型是助手而不是作者。
- **管理器不再自我解释。** 两段静态说明连同弹窗副标题一起删掉，标签栏分享剩余宽度，短的一行也铺满整条。输出风格卡片不再显示 SessionStart 提示：它显示管理器对同一条件说的同一句话（未抓取的文本不会注入任何内容）。

## Alternatives considered

- **只保留行内起草。** 被走查否决：调整需求与更换模型是读者最常做的两件事，一次性输入里两件都做不到。
- **由插件在 GUI 里直接打开会话。** 否决：插件无法命令宿主外壳的选中状态。会话被创建并广播，提示语点名它所在的工作区，这是「已经开着」的诚实说法。
- **让模型重写整份 hooks.json。** 否决：文件是读者的，所以写入只追加一条并按形状合并。让模型重发整份文件会丢掉注释和手写的行。
- **继续按计数过滤切签。** 被走查否决：它让两个面在「第三个条件是否存在」上互相矛盾。

## Consequences

- 新增两条路由与一个契约文件；钩子写入器是本插件唯一一处往读者自己的文档里追加内容的地方。
- 从插件开的会话带的是服务器所在工作区（面板有实时会话时则用它自己的工作区），id 每次新建都重新生成，所以第二次起草不会覆盖第一份记录。
- 管理器少了两段说明，标签栏也不再停在半路。

## Verification

- 在 `market-demo`（link 本仓库、自带默认模型的 profile）实测：
  - 点名八个面都给出三条件（技能 158/158/0、快捷指令 22/21/1、连接器 5/2/3、语言引擎 1/1/0、输出风格 1/1/0、钩子 1/1/0、系统提示词 1/项目0/用户级1）；
  - 以「每次我用 Bash 修改文件后，运行一次 prettier」起草钩子，返回 `PostToolUse` 与 `git diff --name-only --diff-filter=ACM | xargs -r npx prettier --write`，写入 `~/.agents/hooks/hooks.json` 后「用户」切签读作 1；
  - 会话路由 18 ms 与 143 ms 各返回一个不同的 `session-<uuid>`，两份记录都以任务为第一条消息；
  - 预设管理器不再渲染解释段落，标签栏的页签铺满整行（752 px 的栏里 730 px 的页签）；
  - 输出风格卡片显示「未捕获」、抓取动作与管理器那句话，且没有 SessionStart 提示。
- 全量 2559 测试通过，门禁干净。
- 走查后已清理：测试钩子文件与探针会话都已删除，读者自己的数据与走查前一致。
