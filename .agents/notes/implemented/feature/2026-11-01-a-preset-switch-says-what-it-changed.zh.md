# Agent Note：切换预设会说清改了什么

Status: implemented

## Problem

上一轮让预设可以携带输出风格，而选中这样的预设会改变会话的回答方式。这个改变是静默的：确认提示只说「预设已选中」，真实但无用。管理器也没说一个预设覆盖了什么，读者得逐个面点开才知道它带不带风格、列了几个提示词文件。

## Decision

- **确认提示点名风格。** 选中携带风格的预设时报告 `已切换预设 · 输出风格改为 {style}`，否则用普通那句。名字取自 id 指向的清单行，于是它与输出风格面显示的是同一段文字。
- **管理器说明覆盖面。** 预设条下面一行：`开启 18 个套件 · 未带输出风格 · 列出 3 个提示词文件`。
- **计数用页签自己的单位。** 第一版统计每一个开着的行，于是它印出 `132 项能力`，而旁边那个面的筛选页签写着 `已启用 18`——读者无法与下面那行对上的摘要，比没有摘要更糟。现在这一行只数已安装的套件，也就是市场面统计的单位，两者一致。
- **守卫留在原处。** 新的选择路径保留「已修改」时的确认，也照旧关闭菜单；新增的只有确认文案。

## Alternatives considered

- **什么都不说，靠输出风格面呈现。** 否决：刚切换预设的人不会盯着那个面，而悄悄改变模型的回答方式，正是这个界面本该消除的意外。
- **把计数放在每个预设胶囊上。** 否决：同一时刻只选中一个预设，三组数字贴满每个胶囊是噪音；用一行说明当前那个即可。

## Consequences

- 会改变风格的预设，在改变的那一刻说出来了。
- 管理器不必点开某个面就能回答「这个预设覆盖什么」。

## Verification

- 在 `market-dev` 实测：管理器那行读作 `开启 18 个套件 · 未带输出风格 · 列出 3 个提示词文件`，市场面的筛选页签读作 `全部 29 · 已启用 18`，两者对得上。
- `packages/market-bundle/test/integration/client-extension-presets.test.ts` 仍钉住「已修改时先确认」与「选择未变时不发请求」；预设相关测试与全量测试通过。
- 四个类型检查与 `check:refactor` 通过。
