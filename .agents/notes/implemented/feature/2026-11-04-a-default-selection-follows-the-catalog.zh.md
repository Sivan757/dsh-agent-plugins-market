# Agent Note：默认选择跟随目录

Status: implemented

## Problem

在市场里安装套件或技能，运行中的会话收不到。会话保留着自己的选择，而那个选择是会话启动时取的一份 id 快照，于是目录里后来才出现的资源根本不在其中。症状很具体：会话处在默认预设时什么都没有变化，手动切一次扩展预设，新内容就出现了——因为切换会写一份新的选择。

这是核心功能。插件做的其它事情都是对目录的读取；一次到不了会话的目录变更，等于一个装什么都没装的插件。

## Decision

- **不指名预设的选择跟随实时目录。** 目录变更之后，刷新计算出目录现在提供的行，把它们并入已提交的选择，并提交这份选择。正是这次提交授予这些行、把它们注入，并在面板里显示它们：授予、注入、显示是一步，而不是可能互相矛盾的三步。
- **被关闭的行以同样的方式被撤出。** 捕获就是读成 id 的全局开关集合，所以目录关掉一行，会把它从当初捕获它的那个会话里移除，而不只是从之后新建的会话里移除。缺了这一半，几周后恢复的会话仍在运行读者早已关掉的套件，而每个界面都显示它是关的。
- **授予在读的时候拿捕获对照开关。** 撤出不能等下一次刷新：恢复的会话在任何读取之前就应用它已提交的捕获，而这份捕获的 hook 在会话启动时就跑。因此 `extensionResourceEnabled` 接收「这份选择是什么」——捕获还是预设——捕获不授予任何目录已关闭的行。已存的 id 由下一次刷新修剪；在那之前它们什么也不授予。
- **清单里没有的 id 不算被撤出的行。** 修剪只移除目录明确标为已关闭、不可用或全局托管的行。一次不完整的读取绝不能缩小选择，这就是刷新比较整个 id 列表而不是比较长度的原因。
- **指名预设的选择不跟随目录。** 预设是一个选择；后来装的套件不会在读者背后自己加入。点名了全局已停用行的预设仍会授予它：开关决定的是捕获的含义，而不是读者显式钉住的清单。
- **从旧版资源过滤器捕获的选择被冻结。** 那些过滤器本来就是这个工作区自己的开关，重新推导集合会把它们重新打开。选择里用 `frozen` 记着这件事，窗口与门禁仍按捕获时的样子读它。
- **提交在维护槽之外进行。** 在刷新的维护块里提交会等待它自己所在的那次维护，所以刷新把选择交出来，等槽位空出来再提交。

## Alternatives considered

- **每次刷新都重新推导整个选择。** 否决：那会把旧版过滤器关掉的资源重新打开，也会在清单读取途中丢掉已提交的行。撤出刻意不是这件事：它只移除目录标为已关闭的行，保留清单里没有的每一个 id，且不碰冻结的捕获。
- **在恢复时就提交修剪后的选择，赶在会话启动之前。** 否决：恢复本身跑在会话自己的启动维护里，在那里提交会等待它所在的这次维护。让捕获对着开关读，才是让开关立刻生效的做法；在槽位之外的下一次目录刷新才会重写 id。
- **让面板隐藏门禁拒绝的东西。** 否决：管理器渲染的是预设草稿，不是已提交的选择，藏起来只会让读者看到第三种状态，而插件本来只需要维持两种状态同步。
- **记录读者关掉的行（排除清单）。** 核对产品后否决：管理器里没有「在默认选择下关掉某一行」这条路，开关改的永远是预设草稿。没有这样的意图要保留，就没有要排除的东西。
- **应用有效选择但不提交。** 否决：面板会把新行显示成「关」，会话却注入了它，下一次刷新又与上一次不一致。一次提交让存储状态、门禁与注入保持一致。
- **只刷新注入内容，选择不动。** 否决：选择就是注入的输入，它必须一起动。

## Consequences

- 安装套件或技能会在下一次目录刷新时到达运行中的会话，不需要切预设。
- 处在预设上的会话不受同一次安装影响，这正是预设的意义。
- 选择文档可能多一个可选字段（`frozen`），默认选择会随目录一起增减。
- 全局关掉的行在捕获过它的会话里停止运行，而点名同一行的预设继续运行它。两半都由同一个函数读出，显示与门禁不可能各说各的。

## Verification

- 测试（真实 agent、真实会话状态、真实 apply 路径）：
  - 默认选择会授予并应用目录新增的资源，不需要切预设；
  - 预设选择不会授予它，而清单里仍然列着它；
  - 旧版过滤器保留它自己的捕获（冻结），全局停用的行仍然不在任何隐式选择里；
  - 早于开关关闭的捕获会停止授予该行，随后的刷新把 id 撤出；
  - 点名同一行的预设继续授予它；
  - `extensionResourceEnabled` 把捕获读成开关集合、把预设读成它自己的清单；
  - 已安装套件的 hook 行报告套件自己的开关，而不是常量。
- 全量 2661 通过，`check:quick` 与 `format:check` 干净。
- 本次改动没有做 GUI 实测，行为由集成测试覆盖。
