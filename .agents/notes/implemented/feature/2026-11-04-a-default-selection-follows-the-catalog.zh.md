# Agent Note：默认选择跟随目录

Status: implemented

## Problem

在市场里安装套件或技能，运行中的会话收不到。会话保留着自己的选择，而那个选择是会话启动时取的一份 id 快照，于是目录里后来才出现的资源根本不在其中。症状很具体：会话处在默认预设时什么都没有变化，手动切一次扩展预设，新内容就出现了——因为切换会写一份新的选择。

这是核心功能。插件做的其它事情都是对目录的读取；一次到不了会话的目录变更，等于一个装什么都没装的插件。

## Decision

- **不指名预设的选择跟随实时目录。** 目录变更之后，刷新计算出目录现在提供的行，把它们并入已提交的选择，并提交这份选择。正是这次提交授予这些行、把它们注入，并在面板里显示它们：授予、注入、显示是一步，而不是可能互相矛盾的三步。
- **指名预设的选择不跟随目录。** 预设是一个选择；后来装的套件不会在读者背后自己加入。
- **从旧版资源过滤器捕获的选择被冻结。** 那些过滤器本来就是这个工作区自己的开关，重新推导集合会把它们重新打开。选择里用 `frozen` 记着这件事，窗口与门禁仍按捕获时的样子读它。
- **提交在维护槽之外进行。** 在刷新的维护块里提交会等待它自己所在的那次维护，所以刷新把选择交出来，等槽位空出来再提交。

## Alternatives considered

- **每次刷新都重新推导整个选择。** 否决：那会把旧版过滤器关掉的资源重新打开，也会在清单读取途中丢掉已提交的行。
- **记录读者关掉的行（排除清单）。** 核对产品后否决：管理器里没有「在默认选择下关掉某一行」这条路，开关改的永远是预设草稿。没有这样的意图要保留，就没有要排除的东西。
- **应用有效选择但不提交。** 否决：面板会把新行显示成「关」，会话却注入了它，下一次刷新又与上一次不一致。一次提交让存储状态、门禁与注入保持一致。
- **只刷新注入内容，选择不动。** 否决：选择就是注入的输入，它必须一起动。

## Consequences

- 安装套件或技能会在下一次目录刷新时到达运行中的会话，不需要切预设。
- 处在预设上的会话不受同一次安装影响，这正是预设的意义。
- 选择文档可能多一个可选字段（`frozen`），默认选择会随目录一起增长。

## Verification

- 测试（真实 agent、真实会话状态、真实 apply 路径）：
  - 默认选择会授予并应用目录新增的资源，不需要切预设；
  - 预设选择不会授予它，而清单里仍然列着它；
  - 旧版过滤器保留它自己的捕获（冻结），全局停用的行仍然不在任何隐式选择里。
- 全量 2547 通过，门禁干净。
- 本轮浏览器自动化不可用，行为由集成测试覆盖，没有 GUI 实测。
