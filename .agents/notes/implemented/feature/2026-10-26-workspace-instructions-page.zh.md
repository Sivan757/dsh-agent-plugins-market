# Agent Note: 指令页面读取宿主链条，而不是自己重写一遍

Status: implemented

## Problem

所有者要求做一个页面，管理 `AGENTS.md` 与 `AGENTS.local.md`，覆盖 `$DSH_HOME`、`$DSH_AGENTS_HOME` 与会话的项目链条，并尽量贴合宿主的扫描规则。

这些规则并不简单，而且每一条都决定模型读到什么。两个用户级根目录属于同一个候选组，因此内容相同的文件只注入一次，且以宿主主目录为准。项目链条先向上爬到第一个含 `.git` 的目录，再向下走到会话目录。同一个目录里基础文件先于本地覆盖文件加载。组内去空白后内容相同的文件会合并。整段基线有字节预算，超预算时先省略较宽的文件，只截断最具体的那个；另有单文件上限，会把文件从所有可观测数组里一次性抹掉。

第二份实现必然与第一份漂移，而且漂移是无声的：页面显示某文件已加载，而提示词里其实没有它，用户就去改错文件了。

## Decision

页面通过惰性 `import(...)` 调用 `@deepseek-ai/dsh-agent-instructions`，也就是拥有这些规则的模块。发现、加载顺序、去重、渲染与两个字节预算都是该模块的答案，原样返回。

宿主的三个导出承载这个答案。`discoverBaselineInstructionFiles` 返回实际存在的候选及其加载顺序和提示词使用的显示路径。`loadBaselineInstructions` 返回渲染后的文本以及 `omitted` 与 `truncated` 两个数组。`renderAgentInstructions` 可用但未使用，因为加载结果本身已经包含它会产出的内容。

每一行的状态从这份答案按固定优先级读出：

1. 出现在 `truncated` 里就是已截断。这一条排在最前，因为渲染器在什么都放不下时会退化成一行通知，于是被截断的文件可以既不在正文里，又仍在 `truncated` 里。
2. 正文里有 `Instructions from: <displayPath>` 头就是已加载。
3. 出现在 `omitted` 里就是超出预算。
4. 其余情况是文件存在但没有任何贡献。它的大小在两种原因之间做判定：超过单文件上限，而这一条不会出现在任何数组里；或者与组内更早且已被承载的候选重复。

去重绝不靠自行比对内容。文件存在却三处都没有时，分两步解释。先看大小：超过单文件上限就报这个上限，因为宿主在读取阶段就丢掉它，哪里都不报告。否则宿主对那种状态剩下的规则就是候选组内去重，于是这一行报成重复组内最早存在的候选。组内没有更早的候选就没有可重复的对象，这一行保持中性的“未注入”。

单文件上限用文件大小来命名，而不是报成重复。宿主在读取阶段按字节上限丢弃文件，并不把它加入任何数组（`packages/context/agent-instructions/src/files.ts` 的 `readBounded` 守卫及其调用方），所以大小是页面唯一的证据。为此多一次 `stat` 是值得的：看到“超过单文件上限”的用户能动手处理，看到“未注入”的用户不能。

有两条规则是镜像实现的，因为宿主没有导出它们，而且只用于提供创建行。`findProjectRoot` 未导出，因此 `projectRootOf` 复述了 `.git` 爬升规则，把标记视为存在而不管是目录还是链接工作树写出的文件，并在一路没有标记时返回 `cwd`。显示路径的转义规则对首段与命名空间同名的项目路径加 `./` 前缀（`./agents-global/AGENTS.md`），这条只为合成行复述。被发现的行走的始终是宿主自己的 `displayPath`。

发现过程可能抛出，因此每次调用都包在 try/catch 里。标记探测只要失败原因不是 `ENOENT` 或 `ENOTDIR` 就会向外传播，`.git` 的符号链接环会抛 `ELOOP`。返回载荷把这条消息作为错误状态带回，页面渲染它，而不是让整个界面挂掉。

写入按候选定位，从不按路径。`saveInstruction` 与 `deleteInstruction` 在服务端重新推导链条，只接受属于它的 `{ scope, directory, candidate }` 三元组，因此请求无法创建本会话不加载的文件。绝对目录被拒绝，上级目录只在那个位置创建，写入是原子的，超过单文件上限的文本被拒绝，因为这样的文件永远不会被加载。删除时会报告链条上 stat 到同一个文件的其它名字，以及被删除的这一项本身是不是链接，因为链条上可以有两个名字指向一个文件。

两个字节上限是插件的配置字段 `instructionMaxBytes`（65536）与 `instructionMaxSourceBytes`（1048576），文档写明“保持与宿主 agent-instructions 行一致”。只有取宿主的值，页面描述的才是模型实际收到的链条。

## Alternatives considered

**在本插件里重写发现与渲染。** 这样可以对着手写预期做测试，也不需要可选 peer。但宿主一改规则就会分叉，而且分叉是看不见的：页面报告的链条并不是模型收到的链条。所有者要的正是宿主规则本身，而宿主已经导出了拥有这些规则的函数。

**只回传宿主渲染结果，不提供逐行状态。** 这样做正确，但对页面无用：用户需要先知道列出的候选里哪一个没进提示词、为什么，才能决定改哪个文件。

**对每个候选各渲染一次以检测重复，把渲染器当预言机。** 对重复问题准确，但每次读取要渲染 N 次，每次都要重读全部文件。渲染结果本身已经说明它保留了谁，而单文件上限只需额外一次 `stat`，逐候选渲染什么也换不来。

**不做大小判定，直接把不在任何数组里的文件报成重复。** 对超过单文件上限的文件是错的，宿主把它悄悄丢掉。页面会告诉用户文件与另一个重复，真实原因却是它太大。

**在两个用户级根目录里提供 `CLAUDE.md` 与本地覆盖文件。** 那两个名字在那里不是候选。给出这样的行会创建宿主永不加载的文件，比什么都不提供更糟。

**通过 `ctx.fs` 写入，而不是直接用文件系统。** 宿主文件系统服务自带版本守卫与它自己的 provider 规则。这个页面编辑的是用户自己的、不属于任何 provider 工作区的文件，而宿主原子写入工具已经提供了这里需要的崩溃安全替换，插件写用户文件本来就走这条路。

**给页面自己的字节上限，而不是配置字段。** 常量会把某一次部署的选择固化进插件，页面于是可能描述一个宿主行并不使用的预算。宿主把这两个上限文档化为配置。

## Testing

`packages/market-bundle/test/integration/instructions.test.ts` 导入已发布的包并用它作预言机，绝不用手写预期。九个用例覆盖链条、截断优先级、单文件上限、重复的本地覆盖、没有文件时的创建行、把 `.git` 文件当标记、没有标记的树、探测失败、关闭的预算以及按会话读取。另外六个覆盖写入：带上级目录的创建、用户级写入、绝对与未知目标、超限正文，以及符号链接删除的两个方向。

`packages/market-ui/test/client-instructions-panel.test.ts` 在 jsdom 里渲染面板：链条顺序与每个状态一个标签、两个总量下的预算条、不可用状态、带省略与截断说明的预览、触及保存路由的编辑往返、在缺失行上的创建，以及删除后的别名提示。

`packages/market-ui/test/client-workspace-tabs.test.ts` 改为八个页签，并断言指令页签渲染自己的面板。

## Consequences

页面报告宿主的答案，因此宿主改规则时这里不用改。代价是可选 peer：`@deepseek-ai/dsh-agent-instructions` 声明为可选 peer 并带精确的 dev 镜像，没有它的 profile 得到的是点名通知而不是页面。换成必需 peer，会让整个插件在没有它的 profile 里装不上，而代价只是一个页签。

插件自己的 `@deepseek-ai/dsh-home-paths` 依赖通过 pnpm override 解析到 0.2.1-rc.3。支持范围匹配不到 0.2.1 预发布版，因为 node-semver 只接受与比较符同一 major.minor.patch 的预发布版，而宿主包精确 peer 到 0.2.1-rc.3。该依赖对消费者保持范围，override 让本仓库这棵树解析到它构建所依据的基线。

读取会带上每个已存在文件的正文，好让编辑器从磁盘上的内容开始。这相当于每个已存在的行多一次文件读，受单文件上限约束，而且宿主为它渲染的每个文件本来就读过一次。

指定会话时页面按会话目录读取，否则按宿主进程目录读取。目前没有客户端界面会提供会话 id，因此设置页报告的是进程目录，并在路径下方说明。路由与它的测试已经接受会话，所以将来接线只是一个 prop，不是重新设计。

## Related

这个页面是宿主 `packages/context/agent-instructions` 所拥有加载规则的读取与编辑界面，它的两个字节上限对应那一行的 `maxBytes` 与 `maxSourceBytes`。它遵循[仓库说明](../../../../AGENTS.md)里的复用规则：先用宿主能力，再考虑自建。
