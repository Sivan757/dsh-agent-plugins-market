# Agent Note：文档编辑器在切换按钮后只显示一个视图

Status: implemented

## Problem

文档编辑器把源码与渲染结果并排放着，这个布局与它周围的表单相互为难。

1. **两栏把弹窗的整个宽度都花在一份文档上。** 编辑器 408px 宽，旁边是同样宽的预览，而这个弹窗还要在它们上方放下名称字段、命令的参数提示，以及角色的运行配置。
2. **两栏栅格是产品里的另类布局。** 插件里的其他编辑器——MCP、LSP 与来源弹窗——都是单列表单，文档编辑器为了保持两个框齐平而破坏了这个形态。
3. **预览在每一次按键时都重新渲染整份文档。** 编辑器里敲一个字，旁边的 Markdown 就跟着重新解析、重新渲染，无论作者是否需要。
4. **长文档在半个弹窗里读不舒服。** 预览在一条 408px 的栏里滚动，宽的代码或表格要么折行要么被裁掉。

## Decision

- **一次只显示一个视图。** 弹窗显示编辑面，标题旁的分段控件把它换成渲染后的草稿。两个视图都占满弹窗宽度，300px 高的文档只排版一次、阅读一次。
- **切换控件骑在文档自己的标签行上。** `编辑 Markdown` / `预览` 落在标出正文的哪一行（`文档`、`命令正文`、`系统提示词`）的右端，用服务编辑器画 `表单` / `JSON` 的那条带边框轨道；当前一侧带 `aria-pressed`，打开编辑器总是停在编辑视图。
- **预览按需渲染。** 作者在编辑视图里打字时什么都不重新渲染；切到 `预览` 时渲染当前草稿，切回编辑视图时文档与光标历史原样保留。
- **编辑器维持同一种表单形态与同一个顶部间距。** 身份行、带切换控件的文档标签行、正文、底部——与服务编辑器相同的纵向次序。宿主 Modal 的 20px 弹窗间距与正文上边距按「标题下有一句说明」设定；这些编辑器没有说明，因此编辑弹窗自带 12px 间距并清掉正文上边距，标题到第一个字段相距 12px。

## Alternatives considered

- **保留两栏并让各自独立滚动。** 否决：两栏仍然是两栏——上方的名称字段、参数提示与运行配置字段还是要排在只有文档编辑器在用的栅格上。
- **一个隐藏预览但保留分栏的开关。** 否决：藏起一半之后，可见的那一半也只有一半宽，这正是最初的问题。
- **用防抖的实时预览替代切换按钮。** 否决：它把重新渲染的工作挂在计时器上，宽度也照样被劈成两半；想看草稿的作者点一下就能看到。
- **在弹窗标题那一行放标签条。** 否决：那一行由宿主弹窗持有，控件放进表单内部能让弹窗自己的正文与底部保持完整。

## Risks

- 渲染后的草稿离作者一次点击远，而不是始终可见；粘贴后直接保存、不切视图的作者不会看到它的渲染效果。
- 分段控件上的 `aria-pressed` 向辅助技术传达状态；将来若出现第三个选项，需要改用 radiogroup 或 tablist。
