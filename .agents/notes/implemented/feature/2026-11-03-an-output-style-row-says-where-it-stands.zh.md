# Agent Note：输出风格的一行会说自己处于哪一步，并给出下一步

Status: implemented

## Problem

输出风格面是一份「选择」，读起来却像一份「清单」：套件风格的卡片只写「套件」加一句话，没有状态词，也没有控件。于是装好的风格看起来是死的——「插件装了却没激活，也没有内容」——而抓取与选用这两个动作都藏在那一行的弹窗里。那一行的描述还是服务端拼出来的一句英文。

## Decision

- **每一行说出它在这个面唯一的选择里的位置**：使用中、未选用，或未捕获。
- **把它推进下去的动作就在那个词旁边。** 从未抓取过的行在卡片上带「抓取文本」；抓取过的行带开关，开关就是选用。风格是单选，所以开关的含义是「选这个」，不是「开或关」。
- **套件行携带类型化的提示，而不是文案。** `OutputStyleRow.hint` 是 `'suiteSessionStartCapture'` 或不存在，客户端映射到 `outputStylesSuiteCaptureHint`。服务端无法表达面向读者的文字。
- **处理器属于渲染面。** 第一版把 `onToggle` 与 `isOn` 放进了每个条目对象里，而渲染器是从渲染面的 props 读它们，结果一个开关都没画出来。处理器已移到渲染面，并由一条「按预期行为写」的测试抓了出来。

## Alternatives considered

- **抓取与选用继续留在弹窗里。** 否决：这正是本轮从连接器列表移除的形态——状态词说明了问题，修复动作却藏在一层点击之后。
- **在未抓取的行上画一个禁用的开关。** 否决：禁用控件表达的是「你不能」，不是「先抓取」。抓取按钮说出的是实际的下一步。

## Consequences

- 这个面在扫视时回答「这个风格在生效吗」，在同一张卡上回答「我接下来做什么」。
- 将来的选择类界面把处理器交给渲染面，而不是交给条目。

## Verification

- 在 `market-dev` 实测，按顺序：该行显示「未捕获」+「抓取文本」→ 抓取后显示「未选用」+ 开关（`aria-checked=false`）→ 按下开关后显示「使用中」（`aria-checked=true`）。
- `packages/market-ui/test/client-output-styles-panel.test.ts` 钉住两件事：未抓取的行提供抓取并调用 `captureOutputStyle`；已抓取行的开关调用 `selectOutputStyle`。
- 全量测试通过（2519）。
