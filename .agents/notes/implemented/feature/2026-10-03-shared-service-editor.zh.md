# Agent Note: 服务新建与编辑共用表单

Status: implemented

## Problem

专家编辑器的模型配置边框、视图切换边框与文档边框紧贴，因为间距加在宿主内容容器，而不是实际的相邻元素上。服务弹窗虽然共用字段渲染，但外框、身份位置与策略数据不同：MCP 新建不能设置编辑时提供的超时。占满宽度的底栏提示也会把创建按钮挤成两行。

## Decision

EntryEditorModal 显式组织纵向布局和文档分组。模型配置到文档区域间隔 16px，工具栏到编辑器间隔 8px。底栏操作不收缩，按钮文字不换行；说明文字允许换行。

ServerConfigModal 统一 MCP/LSP 新建与编辑外框。两种模式都使用 ServerConfigDetail 和 ServerConfigEditor，身份、传输方式、字段、高级设置与 JSON 顺序一致。名称只在创建时可修改。MCP 新建通过现有 server-config 接口的 create=true 读取默认策略与后端，并在一次添加请求中提交配置和策略。JSON 与表单共用按服务键组织的文档，包含策略；改名保留两部分。非法文档或身份键不匹配时不能静默重建为空配置。

创建与编辑使用相同的策略解析器及宿主后端限制。串行创建在写入前校验两部分，先保存策略覆盖，再通过现有原子文件写入器发布声明。声明发布失败时恢复原覆盖；回滚也失败时报告两个错误。这不是跨文件事务：两次写入之间中断可能留下未使用的覆盖，但不会发布缺少所请求策略的新声明。后续同名创建会替换残留覆盖。

[工作区面板决策](2026-09-06-workspace-tabs-user-panels.zh.md)继续持有资源存储与组织规则，[弹窗外框](../bug-fix/2026-09-29-dialog-chrome-and-mode-switch.zh.md)继续持有宿主控件几何与固定编辑器高度。本决策补充服务创建策略及相邻分组间距，不取代这两项决策。

## Alternatives considered

**修改宿主分段控件边框。** 控件本身没有问题，缺的是相邻盒子的间距。局部分组修复原因，无需覆盖宿主内部样式。

**只复用字段组件。** 同一个组件缺少策略数据时仍会生成不同表单。共用外框和新建默认数据使输入项与能力一致。

**先添加服务，再从浏览器发第二个请求保存策略。** 第二次请求失败会留下不符合用户设置的已启用服务。先策略后声明复用现有存储，保证两次写入都完成前服务不可发现，无需引入事务层。

## Consequences

添加接口接受可选策略；不传策略的调用方保留原契约。没有新增依赖或存储格式。只读资源与宿主后端限制继续生效。单元测试覆盖表单一致性、JSON/改名保留、校验、默认值、重复创建、发布失败与回滚失败。独立 DSH web profile 安装当前链接构建后，已验证真实 GUI 的新建与编辑：MCP 超时在创建、重开与修改后保留，LSP 扩展名映射和配置实际落盘。专家新建与编辑在桌面及 390px 宽度下间距为 16px 和 8px，没有横向溢出。取消/创建按钮保持单行。操作验证期间浏览器控制台没有警告或错误；后续空闲检查记录到 ERR_NETWORK_IO_SUSPENDED 和一次连接重试。测试命令特意不实现 MCP/LSP，因此该证据覆盖配置操作，不代表协议握手成功。
