# Agent Note：筛选条回答「什么需要我处理」，而不是「谁声明的」

Status: implemented

## Problem

对九个页签的筛选条做产品评审，发现一个机械缺陷和一个模式。

**连接器的筛选条渲染了两次「全部」。** 面板迁到共享渲染器后 `MCP_FILTERS` 仍带着 `'all'`，而渲染器自己会追加一个 `all` 段：两个值都是 `all` 的段、重复的 React key、重复的 DOM id、两个都显示为选中，而且从「全部」按方向键向右无效——焦点走到第二个 `all` 上，值没变。

**多数页签在复述卡片上的标签。** 连接器、语言引擎、技能、快捷指令、专家条上的「用户/插件」重复了每行都印着的标签；系统提示词的「已加载/内容重复」在一份最多两行的列表上只点名七种状态里的两种，而「已加载」恰好藏起了读者打开这一页要找的截断行；钩子的「可运行」在没有受限项时等于「全部」，而「受限」又与它所找到的行上的警告措辞矛盾。同时两个状态界面都无法筛出「需要点一下」的行，尽管两份 payload 各自带着没人渲染的分状态合计。

## Decision

- **状态界面按状态筛，不按归属筛。** 连接器与语言引擎把「用户/插件」换成「需处理」：失败、降级、缺凭据、来源缺失（MCP），以及挂载失败、配置冲突、缺组件（LSP）。「已禁用」保留为可逆状态的切面。
- **短到能一眼扫完的列表不设页签。** 系统提示词与钩子删掉整组筛选；标签与告警已经写清每行的状态。
- **没有切面就不渲染筛选段。** 只有一个「全部」页签的条只是说了等于没说的装饰，所以 `ResourceSurface` 在界面没提供筛选时不渲染 `SegmentedControl`、不给 `tabpanel` 角色、也不留空面板。
- **同一维度只用一套词。** 输出风格的「自建/来自套件」改为「用户/插件」，与其它界面一致；市场来源胶囊改读「全部来源」，一列里不再出现两个不同数字的「全部」。
- **删掉死掉的 LSP 视图模型。** `lsp-status-view-model.ts` 在生产里没有调用方；筛选、计数与分页都在渲染器，而按卡片自身状态匹配取代了比较译文。

## Alternatives considered

- **保留「用户/插件」再加「需处理」。** 否决：七个连接器配三个页签，筛选条比列表还宽。
- **保留状态页签、靠标签说明。** 只在系统提示词与钩子接受这个取舍，因为列表很小；状态界面保留「需处理」，因为状态列表就是用来扫问题的。
- **用 CSS 藏掉只有一个的「全部」页签。** 否决：那个页签仍然占着面板 id、aria-labelledby 和一个读者能到却看不见的键盘停点。

## Consequences

- 真实 profile 上的连接器现在读作 全部 5 · 需处理 3 · 已禁用 0，需要点一下的行只差一次按键。
- 没有筛选的界面工具栏不再有一段只有一个页签的条。
- 两个看似未翻译的提示键和一个死视图模型消失，词典里只留真正会渲染的内容。

## Verification

- `packages/market-bundle/test/integration/client-view-models.test.ts` 钉住「需处理」是失败/降级切面、「已禁用」是停用切面。
- `packages/market-ui/test/client-instructions-panel.test.ts` 断言界面不提供筛选时不渲染页签条。
- 在 `market-dev` 对构建产物实测：市场 全部 1000 · 已安装 29 · 未安装 971；连接器 全部 5 · 需处理 3 · 已禁用 0；语言引擎 全部 1 · 需处理 0 · 已禁用 1；系统提示词与钩子不渲染页签；输出风格读作 全部 · 用户 · 插件。
