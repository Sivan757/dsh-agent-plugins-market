# Agent Note: a recommendation you can judge

Status: implemented

## Problem

负责人拍下了市场的「推荐要安装的套件」对话框：按钮旁一条红色的 `This operation was aborted`，并提了四件事——最近是不是改坏了推荐；周围那些冗余说明；对话框只会「整个接受」，没有一行是读者能读了再丢掉的；以及 AI 按钮该落在动作行的哪一侧。

那句英文背后藏着两处失败。第一处是对话框自己的：那句话是浏览器给 `AbortError` 的原文，来自辅助调用 60 秒的预算，而客户端没有对应的句子，就照抄了出来。第二处是提供方的：这个 profile 里宿主侧的调用被直接拒绝，`magpie-responses API error (400): Anyrouter: prompt_cache_key is required`。两处都不是最近改插件造成的：`AI_ANSWER_LIMITS.timeoutMs` 与宿主的辅助调用路径都早于这一轮，而插件不得修改宿主。

还有第三个事实让第一处失败比它本可以发生的更容易发生。一次安装推荐向服务端要市场自己的行、上限 1000，把每一行都写进提示词，然后让一个只准写 900 token、只有 60 秒的模型从里面挑。

## Decision

- **推荐只给出被用途触及的行，绝不给整个市场。** 路由先按用途里的词（中文按两字切片）匹配套件的名称、描述与 id，再补到 `AI_PRESET_LIMITS.modelCandidates`（120）为止。窄用途拿到短清单，宽用途仍有大选择面，一千个套件的市场不再变成一千行提示词。
- **每个被给出的行都带一句说明。** 候选多了一个可选描述，进提示词前压成一行，模型因此按事实挑选，而不只看名字。
- **答案是读者能判断的一份清单。** 每个被推荐的行渲染成名称、描述和一个复选框；答案到达时全部已勾选。应用只发送仍被勾选的行，全都不勾时应用按钮禁用。
- **AI 动作排在动作行最左端。** 对话框的按钮顺序是 生成建议 / 取消，出结果后是 应用 / 取消：AI 动作是这一行的第一颗按钮，排在人工动作之前。这已成为所有提供 AI 动作的对话框的常设规则。
- **超出预算的调用是自己的失败。** 辅助调用标记超时，模型端口抛出 `ai-timeout`，路由以 504 作答，对话框经共用的 `aiFailureText`（诊断块现在也用它）用读者的语言说「模型这次没能在时限内答完，可以直接重试」。
- **说明文字每个对话框只留一句。** 两段长提示收成「说明用途，模型从扫到的市场套件里挑选；安装仍需你确认。」及其预设版；意图字段有了自己的标签（用途/Purpose），不再借用对话框标题当 aria-label。

## Alternatives considered

- **保留 1000 行的提示词，只把超时调长。** 否决：拖慢的是提示词；调长预算等于让读者的钱花在模型读它永远不会选的行上。
- **只用精确关键词过滤市场。** 否决作主机制：措辞与市场不一致的用途会一无所获。先排序再补满上限，既保住召回，也把提示词有界。
- **先让模型只给 id，答案回来后在浏览器里补描述。** 否决：读者在应用之前就要判断这一挑，而描述正是做出这一挑的依据，属于提示词；事后补等于摆出两套事实。
- **保留单一的「应用」，把选择列成文字。** 负责人直接否决：不能改的推荐就是命令。
- **把 AI 动作放到尾端挨着取消。** 否决：负责人把 AI 置首定为标准，理由成立——AI 按钮是这个对话框存在的理由，读者扫一行时应当先遇到它。
- **在插件里修好提供方的拒绝。** 否决：`prompt_cache_key` 属于宿主的提供方路由；插件不得修改宿主，所以对话框如实转述提供方的话，能不能跑由读者的环境决定。

## Consequences

- 答得太慢的推荐现在以读者的语言把超时报成「可重试」，而不是照抄浏览器。
- 这个 profile 里提供方的拒绝仍然可见、仍然是提供方自己的句子：在该路由补上它要求的参数之前，这一面作不了答；对话框不再用一句笼统的失败把它藏起来。
- 排序是词面的：描述里没有出现用途用词的高相关套件可能排低，掉出 120。匹配行之后仍按市场自己的顺序补齐，所以宽用途保留完整选择面。
- `AiSelectionModal.onApply` 多了读者保留下来的 id，预设在 canonical 闭包、市场的收窄，都从这份选择出发，而不是模型的原答案。
- 超时这一族现在能在路由层测：`ai-draft-routes.test.ts` 钉住 504 与 `ai-timeout`，排序那一例钉住 400 行的市场到达模型时是一份有序、有界的清单。

## Verification

- `pnpm run test` 全绿：302 个文件、2712 个测试，其中 `packages/market-bundle/test/integration/ai-draft-routes.test.ts`（12 个用例：排序且有界的候选、504 与 `ai-timeout` 的映射、原有的接受与拒绝用例）与 `packages/market-ui/test/preset-ai-suggestion.test.ts`（应用后的选择仍构造出与改动前相同的预设闭包）。
- 在 `market-demo` 现场：对话框以「用途」为意图标签，页脚两颗按钮且 生成建议 在前，说明只有一句；提交后作答的是提供方的拒绝，显示在标题下方（红色块），不落在页脚行。这个 profile 里无法把对话框自己的作答流程走通，因为提供方拒绝了辅助调用；这一点如实记在上文，作为环境事实，不当作通过用例。
