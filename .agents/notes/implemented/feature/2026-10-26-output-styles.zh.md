# Agent Note: 输出风格只注入抓取到的文本，绝不在读取时运行程序

Status: implemented

## Problem

所有者点名要一个输出风格页签。输出风格是一段有名字的指令文本，用来改变模型的回答方式：简洁、解释式、以提问教学。在 Claude Code 里它是一个设置项，其文本会进入系统提示。

这件事不止是一个文本框，原因有三。

第一，来源的可信度不同。本仓库自带的风格在这里被评审过；用户自建的风格是他自己的；市场套件交付的风格，是该套件提供的程序在会话启动时的输出。

第二，套件风格不运行那个程序就读不到，而页面不应该在有人滚动列表时去运行套件程序。

第三，选中什么会改变该工作区的每一次回答，所以人必须能在它生效之前看清究竟什么会进入提示。

## Decision

一个风格是一条记录：`{ id, label, description, body, source }`，`source` 取 `user` 或 `suite`。每个工作区只选中一个，单独存放，并作为一段系统提示注入。工作区初始未选择任何风格，因此不渲染任何段；插件本身不带风格。

**插件不自带任何风格。** 风格来自声明了它的市场插件，或来自用户自己在 Agent 布局根下编辑的 Markdown 文件。插件曾自带三个，现已移除：风格是插件作者对"模型该怎么回答"的表态，而不是目录本身的表态。

**自建风格是 `<Agent 布局根>/output-styles/<名称>.md`** 下的 Markdown，frontmatter `description:` 加正文。名称按文件名词干校验，解析后的路径还会确认落在风格目录内，所以创建动作写不到目录之外。

**套件风格只抓取，绝不在读取时运行。** 页签列出每个声明了 SessionStart 命令的已启用套件，并计算一个指纹：套件地址、manifest 版本、根目录与确切的命令。要选中它必须先抓取，抓取通过既有的有界试运行执行一次：用户主目录、声明的超时上限 60 秒、每条流 32 KB。文本从 `hookSpecificOutput.additionalContext` 取，钩子直接打印散文时也接受。

抓取结果与产出它的指纹一起保存。套件变了就不再匹配，于是该行显示抓取已过期、不注入任何内容，并提示重新抓取。这条防的就是"重放没人再确认过的文本"，也正是要指纹而不只是一个"抓过一次"标记的原因。

指纹刻意不哈希钩子脚本自身的字节。那意味着每次列表读取都要读任意可执行文件，而一个只改了脚本、没改声明也没升版本的套件，会在下次有人抓取时被发现，而页面始终提供这个动作。这里把这个取舍写下来，免得有人以为是疏漏而补一个内容哈希。

**这一段按 agent 注册，绝不全局。** 选择属于工作区，每个 agent 在一个工作区里运行，子 agent 可能跑在另一个工作区，全局注册会把父级风格塞给子级。`agent/created` 在该 agent 自己的作用域上装一段，`agent/disposed` 释放。

注册时用 `interpolate: false`。风格是作者文本：宿主默认会解析 `{{...}}`，遇到不认识的变量会直接让提示组装失败，而引用提示变量的风格正好会踩到。

顺序固定为 490。宿主给部署人格前缀 0、计划策略 500、团队策略 600，所以风格属于这类行为指令，并排在从 1000 开始的工具描述之前。比最近的命名槽位低十，是为了避开那个具体取值：顺序相同时会退化成按名称的码元序，风格的位置就会取决于它叫什么。

**渲染出来的文本是标题加原样正文：**

```text
## Output style: <label>
<body>
```

标题属于这段文本，因为宿主只用空行拼接各段、自己不加标题，没有它两段指令会连在一起。

正文不套 `<system-reminder>`。这是 `docs/reference/prompt-injection-conventions.md` 的 R7 条：系统提示段本身已经带着系统权重，所以它用 Markdown 标题、绝不用框架，套框架等于给权重再加权重。那种框架属于持久的工作区指令消息，那里要告诉模型这段文本是上下文而不是长期指令。

转义与按贡献者归属的形态都来自合并后的 `runtime/surfaces/prompt-frame.ts`，而不是另抄一份。`escapeFrameBody` 把 `</system-reminder>` 中和掉，并且是幂等的，所以对一个不含框架的正文应用它只多一次扫描、渲染结果完全相同；这里仍然调用它，是为了让抓取到的套件正文无法把闭合标记偷偷带进提示，并且同一段文本将来被放进框架时同样安全。

`attribute()` 渲染每个贡献者一个 `### <标题>`，这里刻意不用在风格本身。它解决的是多个贡献者要可分辨的问题（R5 条），而每个工作区只选中一个风格，所以"外层 `##` 段 + 每个风格一个 `###`"什么也分不开。它还会把风格嵌进一个不指向任何贡献者的标题之下，为了满足一个面向多贡献者的形态而多出一层。`##` 标题直接点名这一个贡献者，正是约定里描述的单贡献者形态。

这里不用 `escapeEntry`：这一段里没有任何强调块，风格正文是模型就地阅读的散文，不是被回显进标记里的名字。

渲染函数放在 `market-runtime` 而不是 contracts 包：架构门禁禁止 contracts 引用 runtime，而页面也绝不能自己重写这条规则。页面并不需要重写。页面渲染的是服务端给的 `injected` 字符串，从不自行重建，所以预览在构造上就是那一段文本，而不是靠两份实现互相吻合。有两个测试钉住这一点：服务侧断言 `injected` 等于 `renderOutputStyleSection` 的输出、也等于 `sectionText`；面板侧断言 `<pre>` 与载荷里的 `injected` 逐字节相等，包括转义后的标记。

**状态是独立文档**，位于 `output-style/<sha256(工作区).slice(0,24)>.json`，内容为 `{ version, workspace, styleId, captured? }`，在宿主文件锁下读改写并原子落盘。它是标签页布局的兄弟而不是其中一节：一个文件一个写者，才能避免两个界面互相覆盖。读取是宽容的：不可解析的文档、或者指向已不存在风格的 id，都解析为默认选择，因为对一个看不见的提示贡献来说，这是安全的方向。

## Alternatives considered

**每次读取都运行套件的 SessionStart 钩子，让文本始终最新。** 这样就没有过期状态和抓取动作了。代价是页面一打开就运行第三方程序，既没有用户动作也没有次数上限，而影响每次回答的文本会变成上一次运行打印的东西。显式抓取正是整条安全性质。

**把任何声明了 SessionStart 钩子的会话都当成输出风格。** 更好辩护，但错：多数 SessionStart 钩子是在为会话加载上下文，不是风格，页面会邀请人们把项目的启动说明当作回答风格注入。只有被人抓取过的套件才成为风格，而预览显示的就是他们同意的内容。

**把选择塞进工作区策略文档。** 文件更少。那会让一个文档服务两个所有者，策略写入与风格选择会在同一份字节上竞争，必然丢一个。标签页布局出于同样理由做了同样的选择。

**只注册一个全局段，每次组装时读工作区。** 只注册一次而不是每个 agent 一次。可一旦子 agent 跑在别的工作区就错了，而且宿主组装提示时不等待磁盘读取，工作区必须在装段时就确定。

**把钩子脚本的字节也哈希进指纹。** 能在不升版本的情况下发现脚本被改。代价是每次列表读取都读一个任意可执行文件，而这正是"抓取动作始终可用"已经覆盖的情形，还会让套件自己的缓存文件被算成风格变化。

**为了与工作区指令一致，把正文套进 `<system-reminder>`。** 看起来像插件对自己已经放进系统提示的文本格外谨慎。但那种框架告诉模型这是上下文，正好削弱了它本该是指令的东西，而且 R7 条明确禁止。

**把风格渲染成外层 `## Output style` 加内层一个 `### <名称>`，为了与套件指令段对称而复用 `attribute()`。** 对称，但会把风格嵌进一个不指向任何贡献者的标题之下。`attribute()` 回答的是多贡献者问题；一个被选中的风格就是一个贡献者，外层只是多出一层什么也分不开的结构。

**把渲染放在 contracts 包，让服务端和页面都能调用。** 这是最初的形态，架构门禁拒绝它：无状态的 contracts 记录不得引用 runtime，而合并后的框架助手在 runtime 里。把渲染移到 runtime、让页面显示服务端的答案，既合规又更强，因为一份实现不可能与自己不一致。

**选中套件风格时由页面隐式抓取。** 一次点击而不是两次。它把运行程序藏进一次选择里，并让没人预览过的文本进入提示，而这正是本功能要防的事。

页签行新增一个键，既有的 stow 与 workspace 测试随之移到九个页签。

## Consequences

页面能承诺提示收到什么，因为预览与提示共用同一个函数，而且预览是服务端的答案，不是客户端自行重算。

套件风格需要一次显式动作，从没抓取过的人，提示里不会有套件文本。套件变化后停止贡献，直到有人重新抓取，这正是想要的方向：工作区少一个风格，而不是多一个没人审过的。

对于只改脚本、没改版本与声明的套件，指纹要等到下次抓取才会发现。页面始终提供这个动作，而这一行也不会声称一个它没见过变化的套件是最新的。

除了有人主动请求的抓取，这里在请求期不运行任何东西。风格目录在每次读页面时读一次；文档读取发生在每次读页面和每次创建 agent 时。
