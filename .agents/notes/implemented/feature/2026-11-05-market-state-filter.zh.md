# Agent Note：市场可按已启用与已停用筛选

Status: implemented

## Problem

市场列出每一个套件，却没有办法把清单缩到「已开启的套件」或「已关闭的套件」。有上百个源的读者只能逐行读状态词，才能挑出自己真正要处理的那几个。

[一个筛选，两个界面从同一张表取](2026-11-03-one-filter-both-surfaces-draw-it.zh.md)留下了「谁提供了这一行」这个来源筛选，并去掉了状态筛选，理由是卡片的边条与状态词已经说得出套件的状态。这条理由对除市场以外的每个面都成立：这里读者问的不是某一行，而是要把哪些行先处理掉。

## Decision

- **市场的状态分支写在共享的筛选表里。** `ui/surface-facets.ts` 按工作区页签在来源用词旁边声明状态用词，并导出一个两个界面都调用的入口：`surfaceCuts(key, t, providerOf)`，先来源分支、后状态分支，顺序固定。
- **状态分支按行的状态匹配。** `active` 是已启用分支（已启用 / enabled），`disabled` 是已停用分支（已停用 / disabled）。列出来但未安装的套件是 `absent`，两个分支都不属于它：它仍在「全部」下可见，分支只把清单缩到已安装且开着或关着的那部分。
- **这张表多了一个入口，预设管理器调用的就是它。** `surfaceCuts(key, t, providerOf)` 是来源分支与状态分支的合集，两个界面调用的都是它：预设管理器的市场面与市场页面。`surfaceProviderCuts` 仍然是其它面板用的「只有来源分支」的构造器，它们的分支因此不变。两个界面调用同一个函数、读同一张表，就不会对「什么算筛选」有分歧。

本记录取代[一个筛选，两个界面从同一张表取](2026-11-03-one-filter-both-surfaces-draw-it.zh.md)中的一个条款：对市场而言，「状态筛选全部移除」不再成立。该记录的其它条款继续有效：来源筛选（谁提供了这一行）、一张表只存在于一个模块里，以及两个界面不得对「什么算筛选」有分歧。变动的只有入口这一点：这张表多了 `surfaceCuts`，预设管理器从调用 `surfaceProviderCuts` 改为调用它。其它每个面仍然只画来源筛选，不画状态分支。

## Alternatives considered

- **给每个面都加状态分支。** 否决：这正是那条记录否决过的统一筛选，而负责人要的是市场的筛选，不是到处都有的筛选。
- **让市场页面自己造分支。** 否决：两个界面就会对「什么算筛选」有分歧，而这正是共享表要防的事。
- **给市场新增文案。** 否决：卡片本身已经通过 `enabledLabel` 与 `disabledLabel` 说出「已启用 / 已停用」，分支必须用行所用的同一批词。
- **再加一条「未安装」分支。** 否决：未安装的套件是 `absent`，想要它们的读者会按名字找；第三条分支回答的是市场自己的计数已经回答过的问题。

## Consequences

- 市场的工具栏带着「全部 / 已启用 / 已停用」，预设管理器的市场面带着同样的三条。
- 「单一来源不画筛选」这条规则，只在来源筛选上继续成立：一个来源只有一个、状态却有两个的面，现在会画筛选。

## Verification

- `packages/market-ui/test/surface-facets.test.ts` 钉住这张表：市场两条状态分支的顺序、分支匹配的状态、自己没有状态的行，以及其它每个面仍旧只有来源分支。
