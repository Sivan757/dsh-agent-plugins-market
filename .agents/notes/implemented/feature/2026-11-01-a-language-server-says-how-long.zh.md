# Agent Note：语言服务器会说自己启动用了多久

Status: implemented

## Problem

MCP 一侧已经会报告失败尝试的耗时；语言引擎一侧仍然回答不了「为什么它已经启动三十秒了」。永远启动不完的、和立刻失败的，读起来一样：一个状态词、一句原因，没有数字。LSP 详情里也没有放它的位置。

## Decision

- **挂载路径自己计时。** `mountWith` 包住插件挂载与它的 `await()`——读者体验到的「仍在启动」就是这段等待——并把 `mountMs` 放进它返回的失败诊断。`LspMountDiagnostic` 与 `LspStatusEntry` 各多一个可选字段，`deriveState` 把它带到套件行与直连行。
- **卡面说秒、详情说毫秒。** 启动超过一秒时，卡面在原因后补 `· 2.0s`；概览格多一格 `挂载用时  2 毫秒`；`复制诊断` 的文本带 `mountMs: 2`。
- **复制里的成因会被截断。** 语言服务器的解析失败会把整个搜索过的 PATH 附在后面——两千来个字符——所以诊断块现在把每条成因截到 300 字。面板仍然显示完整句子，复制保留一条消息能承载的部分。

## Alternatives considered

- **给整趟 reconcile 计时。** 否决：一趟慢不能说明哪个服务器慢，而且这趟的上限是挂载队列，不是服务器。
- **只在日志里报告耗时。** 否决：与 MCP 那条笔记同样的理由——提问的人正看着面板。
- **在源头缩短 PATH 消息。** 否决：那句话在有人问「宿主到底搜了哪些 PATH」时确实有用；有长度预算的是复制。

## Consequences

- 卡住的服务器与命令写错的服务器可以区分开。
- 即使某条成因带着环境转储，复制的文本仍然可读。
- 成功的启动仍然没有耗时（与 MCP 侧同一条已记录的后续）。

## Verification

- 在 `market-dev` 用一个临时的、命令不存在的直连服务器实测：行读作 `失败 · 找不到命令`，详情显示 `挂载用时  2 毫秒`，复制文本在成因前有 `mountMs: 2`。临时的 `~/.agents/lsp.json` 已删除，行在下次启动后消失；2 毫秒对「命令解析不到」是正确值，卡面也正确地在一秒以下不显示秒数。
- `packages/market-bundle/test/integration/lsp-status.test.ts` 钉住诊断的耗时到达行。
- `packages/market-ui/test/client-diagnostics.test.ts` 钉住成因截断。
- 四个类型检查、`check:refactor` 与全量测试通过。
