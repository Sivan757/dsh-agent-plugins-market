# Agent Note：卡片的实时交互与工作台的查询容器

Status: implemented

## 问题

上一轮按截图核对改造成果，而没有对照原型自身的实现，于是静态图表达不了的东西全部漏检：hover 显形、操作簇的预留宽度、过渡、来源条浮层的层级，以及减少动效偏好。回头读原型源码，还翻出一处一直不可见的缺陷：

1. **窄容器分支在市场页从未生效。** 工作台里的响应式规则全是 `@container` 查询，而声明过的容器只有 `panel.module.css .shell`；用户内容面板复用了它，市场页却渲染自己的根元素 `.market`，没有声明 `container-type`。真实设置列宽 564px 下，市场页一直落在基线上：一行一张 552px 的卡、固定 122px 行高、操作簇另占一列而不是隐藏。
2. **只有次要图标会隐藏。** 共享层只淡出 `.revealOnHover` 子元素，于是启停开关与主操作（安装）留在屏幕上，旁边的图标却消失了——半个操作簇，也和原型画的不一样。
3. **MCP 与 LSP 卡片完全没有操作。** 原型给两者都加了卡片级启停开关，而后端其实两处都支持：MCP 是 `McpServerOverride.enabled`，LSP 是 `setLspServerEnabled`（路由已有，只是没有客户端调用方）。
4. **栅格几何偏离了原型。** 260px 轨道、10px 间距、固定 110px 行高与预留两行描述，都是为了绕开失效的容器查询，同时还把来源名从网格视图里去掉了。
5. **工具栏与页头也和原型分叉。** 视图切换是两个按钮而不是一个「报告当前模式」的切换钮，搜索框没有字形，新增按钮的宽度还跟着语言变。

## 决策

- **市场页补上它本来就假设存在的容器。** `market.module.css .market` 增加 `container-type: inline-size`，于是和其余页面一样，由设置列宽而不是视口决定布局。
- **卡片几何用原型的数值，并写在真正生效的位置。** 基线是宽容器下的 `auto-fill minmax(280px, 1fr)` 与 122px 行高；窄容器分支改为强制两列 `minmax(0, 1fr)`、4px 间距、行高随内容。描述封顶两行而不预留两行，所以单行描述的卡就是更矮的卡，网格行高等于该行最高的一张。
- **操作簇是一整组，也整组隐藏。** 窄容器下它脱离文档流、贴到身份行右端，身份行按固定值预留宽度（88px，只有开关的 MCP/LSP 用 46px），于是操作簇宽度与开关状态无关。整簇在 hover 或 `:focus-within` 时一起淡入——开关与主操作都在内。断点以上只淡出次要图标，这正是原型自己的两层规则。
- **来源行在两种视图里都写出处。** 来源名不再被网格视图隐藏；它在计数之前先省略，因为这一行是用来扫计数的。
- **MCP 与 LSP 卡片带上真实的启停开关。** MCP 走新增的 `set-mcp-server-enabled` 路由进入 `McpService.setServerEnabled`：拆开 source 限定的套件 id，写入 `enabled` override——套件自己的 `mcp.json` 仍归来源所有，刷新也不会覆盖用户的选择。LSP 复用已有的 `lsp-servers/enabled` 路由。两个面板同时补上「已禁用」过滤项（停用条目保留在数据里而不是被滤掉），于是被关掉的服务找得到，标签上的数也等于点开后看到的条数。
- **开关表达的是启用，不是健康。** 失败或降级的条目仍然是启用的：左边条与状态胶囊已经报告了故障，而把开关关掉正是用户停掉一个起不来的服务的方式。
- **MCP 与 LSP 卡片用状态胶囊取代状态圆点**，与另外四个页面和原型一致。旁边那颗归属标签单独包在容器里，窄网格下由它隐藏，因为来源行已经写出套件名。
- **视图切换只留一个按钮。** 它显示当前模式并带按下态底色，名称说明点击的去处，所以不 hover 也能读出当前模式。搜索框用宿主 `Input` 的图标槽，页头的增删动作换成与卡片同几何的扁平 24px 图标按钮，页头宽度因此不再随语言变化。
- **只说归属。** 卡片与套件详情写 `用户` / `插件`；`用户级` / `项目级` 两个字符串直接删除，而不是留着不渲染。
- **来源条折叠态既裁剪也抬层。** `clip-path` 框住 6px 的外溢，又不像 `overflow` 那样把 hover 浮层一起剪掉；折叠态 hover 时取 `z-index: 20`，浮层才盖得住卡片。
- **动效尊重系统偏好。** 卡片颜色过渡与操作簇淡入在 `prefers-reduced-motion: reduce` 下关闭。

## Alternatives considered

- **保留 260px 轨道与 10px 间距，不补容器。** 否决：这些数值本就是为绕开缺失的容器而存在的，代价是网格丢掉来源行与随内容收尾的行高。补容器是修因，之后原型数值才用得上。
- **在 `ui/ResourceCard` 里做统一容器，而不是加在 `.market` 上。** 否决：`ResourceCollection` 是它所样式化的栅格的后代而不是祖先；容器必须位于表面根之上，而市场页的根是唯一没有复用 `.shell` 的那个。
- **任何宽度下都只隐藏图标、让开关常显。** 否决：这读起来像半个操作簇，也不是原型画的样子——开关同样是操作。
- **让 MCP 开关镜像 `state === 'connected'`。** 否决：这把启用与连通混为一谈，并且恰好在最要紧的场景里让控件出错——一个起不来的服务没法被关掉，因为拨动开关会变成「启用一个已经启用的服务」。
- **客户端复用既有 `set-mcp-override` 路由并自行拆开限定套件 id。** 否决：限定 id 的格式归服务端所有，把分隔符复制到客户端就是两边漂移的起点。新路由与既有 `lsp-servers/enabled` 对称，后者本来就接受复合 id。
- **像 MCP view-model 原来那样把「已禁用」的行从数据里滤掉。** 否决：那样标签上的计数与它背后的行来自两段代码。现在同一个判断同时产出两者。
- **用本地 CSS 复刻原型的 6px 筛选段圆角与 4px 标签圆角。** 否决，改用宿主 `Pill` 与 `Tag`：平台的胶囊几何与色调板才是这个界面显得原生的原因，而本地重写还要重新挣得 token 已经提供的暗色行为。
- **工具栏保持 700px 换行。** 否决：该阈值会在真实的 564px 列宽下把工具栏折成两行，而原型从不如此；让搜索框吸收挤压更合适，换行阈值下移到 480px，即分段控件真的会溢出的宽度。

## Risks

- 身份行现在预留固定 88px，所以将来某个操作簇更宽的表面必须改这个预留值（或者选只有开关的 46px），而不是让栅格自己量。
- MCP 的启用 override 按 source 限定的套件写入，所以两个来源里的同名 server key 各自独立可切；将来若 source id 改名，其 override 记录会像既有 `mcp-overrides` 记录一样变成孤儿。
- 每种语言新增两个文案键与两条过滤提示，随既有的双语一致性测试。
