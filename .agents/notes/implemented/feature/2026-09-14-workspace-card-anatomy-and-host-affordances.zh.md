# Agent Note: 工作台六页统一卡片句法并接入宿主示能

Status: implemented

由[卡片的实时交互与工作台的查询容器](2026-09-16-workspace-live-card-affordances.zh.md)、[六个编辑器的弹窗外壳](2026-09-16-workspace-editor-chrome.zh.md)与[详情弹窗的行与文档正文](2026-09-16-detail-row-and-document-body.zh.md)修订：让窄容器规则真正生效的容器、整簇显隐、MCP/LSP 的启停开关，以及编辑器的副行、窗格 chip、字段提示与底部提示。

## Problem

六个页面（市场、技能、命令、代理角色、MCP 服务、LSP 服务）共用同一个设置工作区，却既不共用卡片、也不共用弹窗档位与编辑器：

1. **六套卡片句法。** 套件卡是 `名称 + 版本 / 描述 / 来源 · 维度 + 布局标签 / 计数行`；技能命令角色行是 `名称 + 来源徽章 / 描述 / 操作`；MCP 卡是 `圆点 + 名称 + 工具数 / 端点`；LSP 行是 `圆点 + 名称 + 来源 + 状态胶囊 / 命令`。高度随内容浮动，同一行对不齐，同一件事（来源、计数、状态）有三种画法。
2. **三种操作位置。** 市场在右上、条目在右下、MCP 与 LSP 卡片没有操作；市场的尾部操作列还吃掉每张卡 92px 文本宽。
3. **五档弹窗宽度。** 添加源 500px、条目编辑器 720px（且是 `max-width`，会随内容缩水）、MCP 与 LSP 详情 720px、套件详情 800px、共享 `DetailModal` 基准 1120px。同时并存两种外壳：有的标题栏一个关闭、底部再来一个取消。
4. **三个页面共用一个编辑器。** 技能、命令、角色渲染同一个 Markdown 表单，预览与编辑的切换夹在提示与文本域之间。
5. **七处自绘了宿主已导出的组件：** 开关、确认框、状态圆点、标签体系、展开行、JSON 展示、筛选胶囊。

## Decision

- **一套卡片句法，由共享层持有。** `ui/resource-card.module.css` 定义盒模型、行网格（网格 `'id act' / 'body body' / 'foot foot'`，列表 `'id foot body act'`）以及所有页面共同填充的槽位类（`rowId`、`rowBody`、`rowFoot`、`rowActions`、`name`、`desc`、`monoLine`、`provenance`、`count`、`countValue`、`iconBtn`、`revealOnHover`）。页面只负责行内槽位样式。`data-resource-state` / `data-resource-view` 上的属性选择器让这一层在样式表顺序无关的前提下压过各页面的单类规则。
- **一个操作簇，放在身份行。** 次要图标操作（刷新、编辑、删除）、未安装套件的主操作与启用开关共用身份行右端的同一个簇。它只占身份行，正文行与来源行因此各自整宽，描述不再被挤压。在窄容器的网格里它脱离文档流、由身份行预留宽度，整簇（含开关与主操作）在悬停或 `:focus-within` 时淡入。MCP 与 LSP 卡片带同一个启用开关，不必进详情就能停掉一个服务；重试与重新授权仍留在详情底部。
- **来源行在两种视图里都写出处。** 它先给出归属套件（与身份行同一套等宽字体），再给出用户扫视的计数；套件名会在计数之前先被省略。用户内容卡片对插件提供的条目显示归属套件，对用户自撰条目显示磁盘路径。
- **确定的尺寸。** 宽容器下 `auto-fill minmax(280px, 1fr)` 列加 122px 行高，列表行 56px，断点按面板容器查询——插件始终渲染在可伸缩的设置列里，原先的 `@media` 断点在真实环境从不命中。设置列只给资源列表约 560px，280px 轨道在那里只排得下一列；因此窄容器分支强制两列 `minmax(0, 1fr)`、间距 4px、行高随内容，于是单行描述的卡就是更矮的卡，网格行高等于该行最高的一张。描述封顶两行而不预留两行，三行从顶部堆叠（`align-content: start`），描述到来源行恒定 4px。每个渲染资源栅格的页面都必须落在查询容器里——用户内容面板由 `panel.module.css .shell` 提供，市场页在 `.market` 上自行声明。
- **每一行都带上自己的区域类。** 只带槽位类的正文会被网格自动排进第一个空位——没有操作的卡片那个空的 act 列——于是 MCP 或 LSP 的端点跑到名称旁边、名称被压成 “j…”。现在每个正文都带 `rowBody`。
- **只留一种截断方式。** 用两行 `max-height`，也就是 `market.module.css` 早已记录过的、嵌套滚动合成器不会画出边界的那种；`panel.module.css` 里同义的 `-webkit-line-clamp` 已删除。
- **在宿主 `Modal` 上收敛三档：** `sm` 460（确认）、`md` 640（添加来源表单）、`lg` 880（详情与编辑器），单一外壳：标题栏、可滚动正文、固定底部。
- **详情保留能力、拿到结构。** 套件详情保留技能内容懒加载与按表面开关，并渲染 `插件套件 · <来源>` 副行、只写名称的标题（版本交给状态带）、原型那四格概览——来源套件、布局、作者、以及检出目录的最后变更（载荷以 ISO 时间戳给出）——以及「每个表面一个分组」，行用共享的 `DetailRow` 且摘要压成一行；套件没有的表面整组不出现，校验诊断始终渲染、无问题时就地给出通过说明。JSON 走宿主 `JsonTree`。新增 `ui/UserEntryDetail.tsx`，让技能、命令、角色也拥有套件早就有的「就地阅读」界面。
- **条目编辑器改双栏。** 源码与预览并排，模式切换删除，标题按页面区分（`新建技能` / `新建命令` / `新建代理角色`）。副行写出落盘目标或正在编辑的文件，两个窗格头各带 chip（文档文件名，预览侧是 `实时`），frontmatter 说明落在文本域下方，底部写明保存的后果，命令的 `参数提示` 在新建行与名称配对。
- **宿主组件替换自绘实现：** `Switch`、`StateDot`、`Tag`、`Pill`、`DisclosureRow`、`JsonTree`、`RiskConfirmation`（卸载现在需要勾选确认）。删除 `ui/ToggleSwitch.tsx`、`ui/StatusIcon.tsx` 与 `SourceBadge` 导出，并清掉工具栏从未渲染过的筛选图标函数及其遗留下的失效 CSS 规则。
- **仓库来源条保持既有行为。** 胶囊、两行折叠、悬停浮层、选中来源才出现的改名控件、以及重复的 `全部`，全部与线上一致；折叠态另用 `clip-path` 框住 6px 外溢，并在悬停时取 `z-index: 20`，让浮层盖在卡片之上；同时修正了与调用方 chip 顺序矛盾的那句模块注释。

## Alternatives considered

- **各页面继续持有自己的卡片样式。** 否决：正是六套句法构成了问题，而重复的几何正是它们能漂移的原因。共享槽位层让「等高、同行」成为代码性质而不是评审纪律。
- **移除来源也改用 `RiskConfirmation`。** 否决：那个对话框唯一的勾选框是**确认**，而移除来源问的是**选择**（删除受管克隆还是保留）。把两者并进一个控件会静默丢掉这个选择，因此移除来源继续用带文件勾选框的普通确认。
- **照原型给 MCP 服务详情加只读 `mcp.json` 行。** 否决：服务详情的配置本来就能通过 `ServerConfigDetail` 就地编辑，旁边再放一条只读 JSON 会多出第二份非权威视图。只读 JSON 行留在它该在的地方——没有编辑器的**套件**详情。
- **搜索框改用宿主 `SearchBlock`。** 否决：它是带行数上限的**搜索结果**块，不是输入框。
- **把来源条的前导 chip 改名为 `全部来源`。** 否决：来源条的 `全部` 统计全部套件，筛选行的 `全部` 统计当前作用域，只有在未选来源时才重合；改名是纯粹文案变动，背后没有缺陷。
- **统一到 `-webkit-line-clamp`。** 否决，选择 `max-height`：市场里已有的注释记录了该裁切盒在周围页面重新滚动时会画出边界。
- **给详情底部加安装与卸载。** 采纳，但只透传卡片自己的处理函数，让详情不会变成第二个决定「安装意味着什么」的地方。

## Risks

- 六个页面现在共用一套行网格，将来某个页面特有的布局需求必须通过槽位表达，而不是覆盖盒模型；共享层的属性选择器是有意压过单类规则的。
- 套件卡的操作簇从尾部列移到身份行，对老用户是一处小幅视觉位移。
- `Switch` 是受控的且 `label` 必填，渲染点无法再交付没有可访问名的开关；两个调用点沿用了原本作为 title 的启用/停用文案。
- 卡片变小了（122px，对照原先内容驱动的约 150–200px），超过两行的描述现在会被截断，而过去它会撑高卡片。
