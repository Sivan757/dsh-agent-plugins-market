# Agent Note：英文界面做了一次审计，结论是保持原样

Status: implemented

## Problem

本地化从来没有从另一侧验证过。此前每一轮都在写文案的同时翻译，但没有人把产品切到英文看一遍：缺失的翻译会静默回退到中文源，而英文标签比中文长，正是最容易撑坏一行页头或一个窄控件的那类文本。

## 审计发现了什么

把宿主切到英文，在 `market-dev` 里走完九个页签。

- **产品自己的文案里没有中文。** 屏幕上唯一的 CJK 是两个来自中文套件的描述——用户内容，按原样显示是正确的。
- **没有控件被截断。** 所有被判定为截断的元素要么是容器（来源胶囊按设计可滚动），要么是仅供读屏的 span，要么是卡片上的套件 id——它本来就有宿主的悬停卡显示全文。
- **几何没有移动。** 每个面板页头都是 28px，每个工具栏都在 y=162（市场 218，因为它的来源胶囊）。与中文那轮完全一致，说明更长的英文标签没有让任何一行重排。

## Decision

- **把它钉住，而不是复述它。** `client-locales.test.ts` 新增一条断言：`en` 与 `extensionPresetsEn` 里没有任何键含 CJK 字符。人工走查证明当前状态，测试阻止下一次翻译静默回退。
- **其余不动。** 审计没有发现可修的缺陷，为了显得有产出而编造一个改动，比报告「干净」更糟。

## Alternatives considered

- **再加一条检测「中文渗进英文界面」的断言。** 否决：我们的文案只来自这两本字典；直接写字面量而不走键的界面由 AGENTS.md 的双语规则与评审覆盖，不是字符类能抓的。
- **把每个页签的英文截图入库。** 只用于审计过程，不入库：可复现的证据是量出来的几何数字。

## Consequences

- 新的英文字符串若含中文，会立刻让测试失败。
- 下一次本地化问题可以从「另一种语言能渲染、能放下」起步。

## Verification

- 实测：九个页签全英文——产品文案无 CJK、0 个被截断的控件、页头 28px、工具栏 162/218 与中文一致。之后已把宿主语言恢复为中文，因为该设置属于宿主级而非 profile 级。
- `packages/market-ui/test/client-locales.test.ts`（5 条）在新断言下通过。
- 四个类型检查、`check:refactor` 与全量测试通过。
