# Agent Note：集合读作一份知道总数的列表

Status: implemented

## Problem

无障碍评审留下的两个缺口，都关于界面「说了什么」而不是「长什么样」。

**集合没有列表语义。** 它只是一片装着 `<article>` 卡片的区域，没有 `role="list"`、没有总数、没有位置。而界面是自翻页的，光看 DOM 读者无法知道自己在五个还是一千个里，也不知道当前这张卡排第几。

**只有三个界面用文字说出了状态。** 卡片状态是前缘那条 3px 边条，所以文字很重要；市场、连接器、语言引擎提供了，而技能/快捷指令/专家、钩子、预设管理仍只有边条。

## Decision

- **集合是列表，总数是命中集合。** `ResourceCollection` 带 `role="list"`，每张卡是 `listitem`，界面按命中集合（而不是已渲染的页）传 `aria-posinset` 与 `aria-setsize`：150 个命中时只挂了 120 张卡，读作「1 / 150」；搜索收窄到一个时读作「1 / 1」。
- **每个画状态的界面也把它说出来。** 用户面板（技能、快捷指令、专家）、钩子列表与预设管理现在都从各自页签与详情已在用的键提供 `stateLabel`（已启用、已停用、受限、可运行、不可用）。没有状态可说的界面（系统提示词列表，行上已有可见的状态标签）就不提供。
- **边条仍是视觉提示。** 文字只给辅助技术渲染，卡片外观不变。

## Alternatives considered

- **依赖渲染顺序、不写 `aria-setsize`。** 否决：自翻页时渲染顺序只是集合的前缀，最后一张挂载的卡会自称是最后一项。
- **把位置放进状态行而不是卡片上。** 否决：读者是在落在某张卡上时才知道位置的，那比状态行的播报更晚。
- **加可见状态徽章，省掉隐藏文字。** 否决：边条是设计好的提示，971 张未安装卡上再挂徽章只是噪音；隐藏文字服务需要它的读者，不重画界面。

## Consequences

- 读屏在搜索、筛选或翻页之后能听到列表总数与每张卡的位置。
- 每个界面的卡片状态都不用靠看颜色获得。
- 状态词由界面自己提供，不会被共享默认值标错。

- `packages/market-ui/test/resource-surface.test.ts` 与 `resource-surface-parity.test.ts` 钉住卡片的 `listitem` 角色与隐藏状态词。
