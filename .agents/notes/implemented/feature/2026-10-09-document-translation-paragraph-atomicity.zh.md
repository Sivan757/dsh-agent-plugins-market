# Agent Note: 文档译文按完整自然段发布

Status: implemented

## Problem

固定字符切片可能在上下文尚未完整时切断句子。按格式叶节点分别翻译，也会分开属于同一句话的词。把完成的切片与未翻译切片并列显示，会让只有部分译文的段落看起来已经完成。

阅读器需要稳定的语义单位，保留已完成工作的复用能力，并在失败时保持源文本不变。自然段适合作为这一单位。Provider 请求仍需限制大小和时长。

## Decision

### 放得下的自然段保持完整

[服务端变换](../../../../packages/market-translation/src/application/translation/document.ts)从 Markdown 段落、标题或表格单元格中提取正文。载荷不超过 1,600 个 UTF-16 代码单元时整段发送。这里使用插入 AST 标记之后、provider 遮蔽之前的 JavaScript 字符串长度，不是 token、字素或厂商请求上限。

更长的载荷由 `Intl.Segmenter` 识别完整句子，再在同一上限内组合句子。变换不按字符数切断句子。只要有一句超过上限，整段就保留原文并报告失败。重试未改动的文本不能消除这一长度限制。

代码、链接目标、数学内容和原始 HTML 不参与正文翻译。客户端仍用宿主 `MarkdownText` 渲染一份完整文档。本策略不增加浏览器解析器、AI 摘要或独立上下文请求。

### 只发布完整段落

[本地化器](../../../../packages/market-translation/src/application/translation/localizer.ts)在内部保存成功的传输片段，但只有全部必需片段都有缓存答案时才替换原段落。请求停止不等于成功。已经是目标语言的片段保留原文。拼接段落时恢复句子组前后的原始空白。

后续读取确认全部必需片段后，才组装并缓存完整段落，然后以整段为单位替换。当前段落保留原文时，其他已完成段落仍可显示译文。聚合键使用完整段落载荷，不使用位置，因此插入相邻段落不会让它失效。

响应的 `pending` 统计仍有排队或在途工作的段落、标题和表格单元格。可选 `failed` 统计当前无法完成的单位。同一单位中一部分在途、另一部分失败时，可以同时计入两个值。重组后的标记不合格或正文为空也报告失败。超长句和失败工作都不会被当成成功的空译文。

### 重试完整输入，不拆格式叶节点

[Provider 包装器](../../../../packages/market-translation/src/runtime/host/translation-providers.ts)对受损的结构化正文，使用同一家 provider 将原始完整传输输入重试一次。一轮非递归调用最多重试原批次中的 20 条输入，沿用原信号和外层时限。格式叶节点不会成为独立翻译请求。

只有源输入带 AST 标记、损坏答案仍有正文时才符合条件。空答案或仅有标记的答案不触发修复。混合结果在原时限内正常返回时，保留有效答案的原位置。未修复的条目保持失败，不把源文本缓存成译文。所有条目都失败时，链可以尝试下一家 provider。超时影响整批，调用方取消则终止整批，不再回退。

### 显式版本化段落缓存

完整段落使用 `paragraph-sentences-v2`，内部传输片段使用 `paragraph-transport-v2`。本地化器先组合策略与 provider 链身份，再传入未改动的持久键函数。内存文本索引使用同样的策略隔离。

旧正文切片不满足这两种 v2 策略，即使文本相同也不复用。因此，重新打开已翻译过的文档会产生一次性重译开销，可能进入配置的模型并消耗额度。旧记录留在磁盘上，直到重置缓存。描述请求不带策略，保留旧的 800 单位分块器、组块方式和缓存键。

### 重试失败状态，不删除成功结果

`retry: true` 到达 `TranslationService.translateDocument` 后，重置该文档已跟踪的重试预算和共享 provider 熔断状态，不删除成功段落或传输片段。重试预算按文本索引，因此共享的相同文本也可能受益。这不是把所有失败状态严格隔离到单个实体。

[阅读与生命周期记录](2026-10-06-translation-reading-and-lifecycle.zh.md)拥有文件名同行的控件和替换式旋转图标。失败模式提供重试，原文始终可读。警告表示段落未完成，不足以证明某一家 provider 的具体缺陷。

## Alternatives considered

**保留固定 800 单位的正文切片。** 否决：分界可能切断单词或句子，改变 provider 收到的意思。旧描述分块器为缓存兼容单独保留。

**按格式叶节点翻译以修复损坏标记。** 已被取代：叶节点边界表示格式，不表示语义。完整输入重试保留句子上下文，也不从受损答案中猜补缺失文字。

**每个传输片段完成后立即发布。** 否决：这会在同一自然段中混合原文和译文。内部片段缓存保留进度，但不把半段结果显示为完整译文。

**让新策略复用旧正文缓存。** 否决：旧记录可能来自硬切片或按叶节点修复。显式策略身份接受一次性重译成本，不把旧结果当成已确认完整的段落译文。

**强行翻译超长单句，或增加独立摘要请求。** 否决：强行切分损失句子上下文，额外模型请求则改变成本和输入含义。当前路径保留整段原文并明确报告失败。

## Consequences

段落按原子方式发布，即每段一次性改变。包含多个传输片段的段落需要等待更久，但读者仍可阅读原文。句子分组限制了组间上下文。它不保证语言质量或避免输出截断，每次尝试仍受 provider 时限约束。

1,600 单位的源上限包含 AST 标记，但不包含后续遮蔽带来的膨胀。既有目标语言批次与输出预算仍是独立保护，不是对 provider 输出的数学保证。v2 隔离会让已翻译文档重译一次，同时保留描述缓存。

## Testing
