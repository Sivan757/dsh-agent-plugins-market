# Agent Note：编辑器外壳去掉解释性文案

Status: implemented

## Problem

编辑器养成了两个习惯，占了空间却没有回答界面已经回答过的问题。

1. **每个编辑器都在标题下写明落盘目标。** `保存后写入 ~/.agents/skills/<名称>/SKILL.md` 及其五个同类文案，只是把标题、模式与下方字段已经说过的内容再说一遍，而且占的是弹窗的第一行。
2. **字段提示在向使用者解释产品。** `frontmatter 的 description 决定触发，正文写执行步骤。`、JSON 视图那句「同一份文档的两种视图」、角色路由的说明，以及来源编辑器的五条字段提示，都是挂在已经写明字段名的控件上的机制性文字。
3. **服务与来源表单在样式表的字段里嵌了平台 `Input`。** 一个值周围两道边，读起来像输入框里套了输入框；凡是服务或来源表单要名称、URL、分支、校验和，都会出现。
4. **行列表的「添加」是行下方一个带边框按钮。** 它为每个列表多付一个 26px 控件与一段间距，而这个动作属于这个列表自己的标签行。
5. **新建条目把身份行放进了左窗格。** 名称字段把编辑框压到旁边预览框之下，于是只有编辑态两个框才齐平。

## Decision

- **编辑器不再有副行。** 只有标题，然后是内容。落盘目标是新建流程自己的事，而窗格 chip、字段与面板列表都已经说明了它。
- **编辑器不再有字段提示。** 那些说明性句子是删除而不是搬家：解释产品如何工作并不属于填写字段的一部分。提示里作为示例的内容移进控件的 placeholder（URL 用 `https://github.com/org/repo.git`，分支用 `main`），字段空着时可见、填上即消失。
- **保存的后果保留。** `创建后立即生效，可在列表里停用` 与 `未保存的改动会在关闭时丢失` 留在按钮旁：它们说明用户即将执行的动作会带来什么，这是底部唯一欠用户的那点上下文。
- **编辑器内部所有控件都来自样式表。** MCP、LSP 与来源编辑器改用原生 `input`、`select`，与文档编辑器一致；平台 `Input` 留给面板自己的工具栏，那里它是整行唯一的控件。
- **行列表的「添加」以扁平图标落在标签行上。** `参数`、`环境变量`、`语言扩展名映射` 与请求头，各自在标签行右端放一个 20px 透明按钮，悬停上底色，与卡片的行内操作同规格；无障碍名称仍是「<添加> <对象>」，辅助技术仍能知道它会新增哪一行。
- **条目的身份行落在正文之上**（窗格本身后来被移除，见[单视图记录](./2026-09-16-workspace-document-editor-single-view.md)）。新建与编辑两个弹窗从此只差这一行。

## Alternatives considered

- **只在新建时保留副行。** 否决：新建弹窗自己的字段标签与面板列表已经说明条目落在哪里，而这行是读者首先要跳过的内容。
- **把每条提示搬到字段标签的 tooltip 里。** 否决：这是把机制性文字藏到悬停之后，为一句在表单里没有位置的文案再加一套机关。
- **保留平台 `Input`，改为去掉样式表的边。** 否决：12px 配 `border-l2` 边是编辑器的几何；只让内层控件带样式，会让弹窗重新混用两种控件尺寸，正是引入这套样式表要结束的状态。
- **保留行下方那个带边框的添加按钮。** 否决：为了一个动词付一整行加一段间距。原型确实那样画，这里是有意偏离——扁平图标才是「属于列表的动作」在本项目里的规格。
- **只在新建时把身份行移到窗格之上。** 否决：同一个弹窗两套布局，且窗格头部会随模式移动。
- **让 JSON 视图也改用代码编辑器。** 仍然不做：JSON 视图是旁边表单所拥有的原始文档转储，其 `aria-label` 是测试驱动文本的接缝。

## Risks

- 删掉提示后，URL 或校验和的格式不再有整句说明；placeholder 承担了示例，代价是字段一旦有值示例就不再可见。
- 添加行是一个标签行上的裸 `+`：它靠悬停与无障碍名称被发现，而不是靠可见的动词。
- 身份行移到窗格之上后，新建弹窗比编辑弹窗高一行，弹窗高度会在两种模式间变化。
