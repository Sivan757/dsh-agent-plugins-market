# Agent Note: 收纳工作区页签

Status: implemented

## Problem

插件工作区把它拥有的每个能力面渲染成一个页签：市场、技能、快捷指令、专家、MCP、LSP 与 hooks，而且还会继续增加。只在其中两页工作的用户，每次访问都要为另外五页付注意力成本，而页签行没有办法表达这一点。页签行同时还是宿主从头到尾拥有的唯一控件：`SegmentedTabs` 拥有漫游 tab stop、Left/Right/Home/End 切换与滑动指示条，所以任何加进这里的东西都必须保持这份约定不变。

## Decision

### 一个尾部控件，位于页签列表之外

`packages/market-ui/src/ui/ResourceTabs.tsx` 增加了一个可选的 `trailing` 槽位，作为 `role="tablist"` 元素的兄弟节点渲染在行容器里。这个槽位是通用的，因为这一行是共用的：预设管理器不传它，渲染结果与之前完全一致。

`packages/market-ui/src/workspace/TabStowControl.tsx` 在这个槽位里放一个宿主 `Button`、一个计数徽标，以及以它为锚点的宿主 `Menu`。菜单先列出已收纳的页签，然后一条分隔线，然后是管理入口。即使什么都没收纳，管理入口仍然渲染，所以入口不会消失。

管理对话框是宿主 `Modal`，按显示顺序为每个页签放一个宿主 `Checkbox`，每行一句简短提示，尾部是 `Show all` 操作。会把行清空的那个控件被禁用，并用文字写出同一条提示，所以原因是可读的，而不是只存在于悬浮提示里。

行的策略仍然留在 CSS 模块里：行是一条 nowrap 的 flex 线，页签占用剩余宽度并优先收缩，尾部控件保持自身尺寸，这既保住了现有的省略号行为，也没有引入横向滚动。

### 一行渲染哪些页签

`PluginWorkspace.tsx` 里的 `rowTabs` 就是 `visibleTabs(TAB_ORDER, layout, active)`：没有收纳的每个页签，加上即使被收纳但处于活动状态的那个页签。后半句正是已收纳页签的 hash 深链仍然可用的原因。这个显示是每次渲染从布局与当前选择推导出来的，从不写回，所以跟随一个链接不会改变已存的布局。

行由 `TAB_ORDER` 构建，而 `TAB_ORDER` 就是 `WORKSPACE_TAB_KEYS` 本身而不是副本，所以页签集合只有一个来源。这个来源属于契约，因为它同时也是服务端校验收纳请求所用的列表。`WorkspaceTab` 同样只是 `WorkspaceTabKey` 的别名。

因此新增页签意味着三件事，每一件没做都会编译失败：在 `WORKSPACE_TAB_KEYS` 里加键、在两份语言字典里加成对的标签、在 `renderTab` 里加内容区分支（它的封闭联合以穷尽检查收尾）。其他都不用动：`TAB_ORDER`、收纳菜单、管理对话框、路由与存储读的都是这一份列表。

收纳当前活动页签会把选择移到第一个未被收纳的页签。这个计算只读收纳列表而不读页签行，因此不依赖哪个页签被固定、也不依赖固定页签在顺序中的位置。

### 按工作区的持久化

`packages/market-runtime/src/application/state/tab-layout.ts` 拥有插件数据根下的 `tab-layout/<sha256(workspace).slice(0,24)>.json`。文档是 `{ version: 1, workspace, hidden: string[] }`，通过 `writeJsonDocument` 写入，并在 `withFileLock` 下读-改-写，与旁边的能力开关策略是同一形态。

它刻意是独立文档、独立所有者。`workspace-policy.ts` 已经有一个写入者，共用文件的第二个写入者会覆盖竞争失败的那次改动。

`TabLayoutService` 是运行时所有者：它把变更串行排在尾部 promise 上，只发布持久化已经提交的结果，并通过 `currentLayout()` 交出与内部状态无关的快照。

### 夹紧规则放在共用契约里

`packages/market-contracts/src/contracts/tab-layout.ts` 被两端同时引入，所以"什么算一份收纳列表"只由一个函数决定：

- `resolveHiddenTabs` 丢弃未知键、非字符串、重复项以及固定的 `market` 页签，并按显示顺序返回剩余项，因此同一份布局总是写出同样的字节。
- 固定的 `market` 页签就是夹紧规则本身：它永远不会被收纳，所以行里永远有页签，任何文件或任何请求都无法把它清空。
- `visibleTabs` 把显示规则集中到一处，因此乐观更新的客户端行与已持久化的布局保持一致。

路由对调用方要求的东西是拒绝而不是悄悄纠正：未知键与固定页签都返回 400 并说明原因，而收纳其余全部页签是合法的，因为固定页签还在。

### 失败时的行为

布局在挂载时读取一次。读取失败会让所有页签保持可见，并把原因写在管理对话框里，所以损坏的布局文件不会阻塞工作区。收纳是乐观的：行先渲染，写入随后进行，写入失败会恢复上一次确认过的布局，并在同一个对话框里说明原因。

`loadTabLayout` 把无法解析的文本当作"什么都没收纳"而不是失败，因为损坏的文档必须让工作区打开并被下一次写入替换。其他读取失败仍然抛出，因为权限问题必须暴露出来。

## Alternatives considered

- **每个页签上的右键菜单，右键即收纳**被否决，理由有三。它不可发现：没有任何东西告诉用户可以右键一个页签，而最需要它的人恰恰是已经对这一行失望的人。它没有可恢复的位置：页签一旦被收纳，它自己的右键菜单也随之消失，恢复的路径仍然得另想办法。它还在页签条内部放了第二个可交互元素，而遍历与选中都归宿主所有，这一行就不再是纯粹的页签列表。尾部单一菜单同时解决这三点：不需要知道任何事也能看见，把每个已收纳页签列成唯一的恢复位置，并且完全不碰 tablist。
- **拖拽重排，并让拖拽终点兼作收纳**被否决，因为宿主页签行没有拖拽交互，加入它等于用第二套交互模型替换滑动指示条与键盘切换。顺序也不是负责人反馈的问题：长行的成本在注意力，而不在次序。
- **只在设置卡片里放一个把每个页签列成布尔值的开关**被否决，因为它把每次访问都要做的决定挪到了用户两辈子才去一次的页面。成本发生在行上，所以控件就该在行旁边；设置卡片已经承载了真正全局的开关。
- **无条件隐藏所有已收纳页签，包括当前活动页签**被否决，因为指向已收纳页签的 hash 链接会选中一个不可见的东西，更糟的是渲染出一个行里并不存在的页签的内容区。显示规则守住了这条不变量，代价只是一个判断条件。
- **把布局存进现有的能力开关文档里**被否决，原因同上：一个文档一个所有者，否则两个写入者会互相覆盖。
- **按 profile 而不是按工作区存布局**被否决，因为这个维度与能力开关已经在用的维度相同。一个项目里值得收纳的页签，在另一个项目里往往值得保留。

## Consequences

工作区现在可以拥有一个与它实际工作相称的页签行，而每个页签离你只有一次菜单操作。代价是：

- 已收纳页签比可见页签多一层交互。这正是收纳的意义，但也意味着菜单必须保持可发现，这就是触发器始终渲染并带上计数徽标的原因。
- 存储变成插件数据根下每个工作区多一个文件，与能力开关文档并列。
- 页签键集合在服务端出现了第二个来源 `WORKSPACE_TAB_KEYS`。只往 `TAB_ORDER` 里加页签会让收纳写到服务端会丢弃的键，所以客户端测试里有一条漂移断言在两者不一致时失败。
- 收纳是乐观的，所以写入失败表现为行自己移动回去。对话框会解释，而另一种做法"等本地文件写入完成再渲染"让点击显得迟滞。

## Verification

`packages/market-ui/test/client-workspace-tab-stow.test.ts` 用真实工作区与真实请求助手，对着两条路由的桩服务驱动：

- `TAB_ORDER` 就是契约本身的数组，且其中每个页签都渲染标签并打开自己的内容区，
- 收纳会移除标签、增加菜单行、保持显示顺序并写入服务端，
- 从菜单选择已收纳页签会选中它并渲染其内容区，且不写入，
- 收纳当前活动页签会把选择移到第一个可见页签，
- 最后一个可见页签的控件被禁用并说明原因，
- 一份把全部页签都写进去的文档仍然把固定页签留在行里，
- 指向已收纳页签的深链会选中它、渲染其标签且不改动已存布局，
- `Show all` 恢复全部页签，
- 写入失败会回退行并在对话框中报告，
- 读取失败会让所有页签保持可见并在对话框中报告。

`packages/market-bundle/test/integration/tab-layout-service.test.ts` 覆盖存储与服务：往返读写、每个工作区一个哈希文件、六种不可用文档、丢弃未知键与固定页签、按显示顺序输出、全页签文档被固定页签夹住、三次并发变更被串行化、快照隔离、重新加载、全部显示、写入失败不影响已发布布局，以及没有工作区路径时服务把布局留在内存里。

`packages/market-bundle/test/integration/tab-layout-routes.test.ts` 覆盖传输：两个常量被注册并一起释放、一个被读取的布局与一个被提交的布局、未知键被拒绝、固定键被拒绝、其余全部页签被接受、非数组请求体被拒绝、跨源写入被拒绝、不可读请求体被拒绝。
