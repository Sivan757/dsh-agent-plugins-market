# Agent Note: 钩子详情的声明 JSON 块

Status: implemented

## Problem

钩子详情对话框把命令放在一处，也就是状态卡，任何分区都不重复它。用户要求的参考形态是宿主插件管理器的 HOOKS 块：一个分区标题，下面一条可折叠行，左侧是事件名，中间是被裁剪的命令预览，右侧是箭头。展开该行显示一个 JSON 块。想把这个声明当成一条记录来读的人，在这个对话框里没有这样一行。

## Decision

钩子详情对话框在概览网格与诊断分区之间增加一个「声明 JSON」分区。

该分区放一条折叠行，由本地 `DetailRow` 原子套在 `DetailRows` 里构成。行名是 `detail.event`，行摘要是 `detail.command`，由原子裁剪成一行，箭头也来自该原子。该行默认折叠，因为声明在读者要求看它背后的记录之前就是一行。

展开后的主体是宿主 `JsonTree` 原语，标签来自 `jsonTreeLabels(t)`。这个辅助函数已经带着另外三个 JSON 界面共用的全部标签。

`declarationJson(detail)` 在客户端用线上已携带的扫描字段组装这棵树的数据：`event`，然后是各自存在时的 `matcher`、`command`、`timeout` 与 `diagnostic`。地址字段与宿主派生的事实都不进入。超时在扫描出的 `timeout` 键下给出已声明的秒数。线上携带的是扫描出的声明，从不携带文件的原始字节，因此这个块读起来是声明，而不是其来源的副本。

该行保持折叠时，命令会读到两次。状态卡陈述它，该行预览它。这是对[钩子详情解剖与跟随套件行](2026-10-09-hook-detail-anatomy-and-suite-following-rows.zh.md)中「命令只出现一次」这一后果的有意部分反转，原因是用户要求参考行的形态。

## Alternatives considered

- **为参考形态新写一个行组件。** 否决：`DetailRow` 已经画出三列带、把摘要裁剪成一行，并提供箭头。第二个行组件会与其它详情对话框共用的那一个逐渐分叉。
- **命令只留在状态卡里，行里预览别的东西。** 否决：参考行的中列就是命令，用户要的就是这个形态。预览事件只会重复行自己的名字。
- **把声明文件的原始文本过线，直接渲染它。** 否决：扫描契约携带的是已接纳的声明字段，不是文件字节，为一个块放宽线上格式会给每一个其它读取器增加必须信任的负载。组装出的树陈述同样的已声明事实。
- **为 JSON 块新增本地 CSS。** 否决：宿主 `JsonTree` 自己画表面与颜色，取的都是平台 token，不需要本地规则。
- **该行默认展开。** 否决：参考块是折叠的，展开的 JSON 树会把诊断区与运行区挤出首屏。

## Consequences

- 对话框把一条声明当成一条记录来展示。行给出事件名并预览命令，JSON 陈述每一项已声明的事实。
- 静止状态下命令读到两次。数出现次数的读者会看到状态卡与行预览，展开树后变成三次。
- 被拒绝的声明在同一个块里显示它的诊断，因为扫描记录带 `diagnostic` 时组装出的 JSON 也带它。
- `tests/client-hooks-status-panel.test.ts` 固定静止计数为二、行的折叠状态、展开树自己的事实，以及地址字段的缺席。

## Testing

`tests/client-hooks-status-panel.test.ts` 断言分区标题、带事件名与命令预览的折叠行、带标签与已声明事实的展开 `role="tree"`，以及树中 `sourceId`、`suiteId`、`provenance`、`support`、`hookIndex` 与 `sessionId` 的缺席。
