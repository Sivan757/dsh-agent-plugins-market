# Agent Note：按任务给对话框定档，而不是所有表单一个尺寸

状态：已实现

## 问题

市场的对话框一直有三种宽度、一种高度回答：内容多高，窗口就多高。这对详情页成立，对打开期间内容会变化的流程不成立。建议对话框是最明显的失败：没有答案时，880px 的窗口里只有一个输入框；答案到达后，窗口长高到装下卡片；再改用途清空答案，窗口又缩回去。读者看到窗口在眼前移动，输入框横跨整个 880px，空态读起来像一个没加载完的表单。

另外两处小例外指向同一个缺口。预设管理器是写死的 800×800，不在宽度档位里；服务端编辑器把高度固定在遮罩的 80%，这是跟着视口走、而不是跟着任务走的尺寸。此前「所有编辑表单用同一个尺寸」的方向，同时服务不了一个单字段的建议和一个长编辑器。

## 决定

- **宽度仍用三档。** `sm` 460 用于确认，`md` 640 用于表单或建议，`lg` 880 用于详情或编辑器。市场的对话框保持一套外壳：标题栏、可滚动正文、固定底部。
- **高度也成为档位，固定档位拥有整个帧。** `auto` 跟内容；`short` 480、`regular` 640、`frame` 800 固定窗口高度，并以视口为上限；内容填满帧，滚动发生在帧内。固定档位服务于那些打开期间会到达、变化或被清空的内容。
- **预设管理器不再是尺度外的例外。** 它使用 `lg` 加 `frame`：880px 宽、800px 高，它打开的详情也骑在同一个帧上，不再各自选尺寸。
- **建议对话框使用 `md` 加 `short`。** 用途字段横跨 640px 的对话框而不是视口；预留给行的区域从一开始就占位：先显示一句「什么会落到这里」，答案到达或被清空时保持同一个 640×480 的帧，列表拿到的是帧里剩下的空间，而不是猜一个像素高度。
- **编辑器选它工作需要的那一档。** 服务端编辑器用 `md` 加 `regular`；普通详情与编辑器保持 `lg` 加 `auto`。

## 考虑过的替代方案

- **所有表单统一一个尺寸。** 方向不允许：单字段建议和 JSON 编辑器共享表单机制，但不共享所需的空间；统一高度要么浪费，要么裁掉编辑器。
- **保留 auto 高度，让视口滚动。** 否决：答案到达时窗口照样移动，这正是要修的缺陷。
- **每个对话框都固定高度。** 否决：两行高的详情会背着一个编辑器的帧，空白是成本，不是功能。
- **保留预设管理器 800×800 的特例。** 否决：尺度外的帧正是这套档位要消除的不一致，它嵌套的详情可以骑 `lg`/`frame` 这一对。

## 后果

- 一个对话框现在声明两件事：宽度档位，以及它如何回答高度。新对话框从这套档位里选，而不是各自发明尺寸。
- 建议对话框的预留行区从首帧起就稳定，长答案在区域内滚动，而不是把对话框拉高。
- 固定帧需要内容填满它：`DetailModal` 用 `fixedHeight` 标记，帧里的表单会长到拿满帧留下的空间。
- 预设管理器与它打开的详情共享 880×800 的帧；嵌套详情不能再选一个不同的宽度。
- 80% 遮罩高度不再存在：固定档位是一个尺寸，而不是读者窗口的某个比例。
