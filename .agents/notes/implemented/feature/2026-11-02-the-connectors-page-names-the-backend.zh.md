# Agent Note：连接器页点名那个会忽略其策略的后端

Status: implemented

## Problem

连接器的启动超时与工具过滤到底会不会生效，取决于挂载后端，而后端在别处固定：它来自 profile 的插件配置，不在这一页。这一页从不说明当前是哪一个，于是读者可能在这里设了工具过滤、然后看它什么也没做——唯一提到这条约束的地方是某一行的详情里，而且要等那一行的工具被展开才看得到。

## Decision

- **列表在页头下面一行说明，条件是后端为 `host`。** 用的是详情里已有的那句话（`宿主兼容后端不支持工具勾选；切换到内置客户端后即可按工具启用或停用。`），于是这条约束在配置策略的地方就被读到，而不是事后才发现。
- **只在真的成立时出现。** 内置后端两者都执行，所以常见情形下页面保持沉默；这一行是关于本工作区的事实，不是永远挂着的警告。

## Alternatives considered

- **在这里加一个切换后端的控件。** 否决：后端存在于 profile 的插件配置里，插件没有写它的路由；一个存不住的控件，正是这轮工作一直在清除的那种会说谎的界面。
- **把后端做成页头操作行里的一个胶囊。** 否决：它不是操作，而胶囊会邀请点击。

## Consequences

- 正在配置策略的读者能看到策略是否生效。
- 页面只在那一行成立的后端上多一行。

## Verification

- 类型检查、`check:refactor` 与全量测试通过；连接器渲染测试在这一行以 `payload.backend` 为条件后仍然通过。
