# Agent Note：关于一个页面能读什么、能跑什么的三问

Status: implemented

## Problem

同一次演示走查里提出三个问题，每一个指向的都是插件把规则说错了，而不是规则本身坏了：

1. 设置页列出了一个不属于它的工作区的项目级 `AGENTS.md`。
2. 扩展预设管理器只显示了部分面，于是被工作区收起的面根本进不了预设。
3. 已安装套件的输出风格在文本存在之前要人点一次，而提问的人并没有选择跳过什么。

## Decision

- **没有会话的页面只读用户级。** 设置页不属于任何工作区，于是它只回答用户自己的 Agent 根：`readInstructions(cwd, limits, 'user')` 把项目根钉在该目录上，不再向上找标记，并剔除 project 行。它原先读的是 `process.cwd()`，也就是宿主恰好启动的那个目录，还把那里的项目文件当作读者选过的报上来。项目链在会话里按该会话的工作区读，页面自己会说明这一点。
- **预设管理器列出每一个面。** 它原先用 `visibleTabs`，会把工作区收起过的页签过滤掉。收起只是「工作区页签行怎么显示」的选择，不代表这个面没有可配置的东西；预设覆盖所有面，所以编辑器现在直接按存储顺序走。
- **打开面就抓取套件风格。** 文本来自套件自己声明的程序，所以这一行原先要等**抓取文本**。现在页面在每个工作区第一次打开时跑一轮，抓取动作只作为重试留下。明确的决定往后挪了一步而没有消失：预览仍然显示抓取到的文本，只有开关会把它放进提示。

## Alternatives considered

- **不改范围，只把设置页写诚实。** 否决：设置页无法对一个它叫不出名字的工作区保持诚实。项目链的意义只在会话作用域里。
- **保留过滤，另加一个显示已收起的开关。** 否决：为一个藏起来没有好处的列表多加一个控件。预设叫不出名字的面，就悄悄配置不了。
- **启动时抓取全部套件风格。** 否决：那会为从不打开这个面的读者运行套件程序。打开这个面，是读者正在看的最小事件。
- **保留逐行点击。** 被走查否决：让读者为他已经打开来读的那一行再按一次按钮。

## Consequences

- 一个工作区第一次看输出风格面时，会为每个未抓取的套件风格运行一次它声明的程序，超时与输出上限与之前完全相同，并记录抓取结果。
- 抓取到的风格仍然没有选中就不能注入；与套件指纹不再匹配的抓取仍然被拒绝而不是重放。
- 预设编辑器可以命名每一个面，包括工作区页签行里被收起的那些。

## Verification

- 在 `market-demo` 实测：
  - 设置里的系统提示词只列 `~/.dsh/AGENTS.md`，切签读作 全部 1 / 项目 0 / 用户级 1，页面写明项目级文件在会话里按工作区读取；
  - 预设管理器的页签行显示全部九个面（原先六个）；
  - 打开输出风格，套件卡片从「未捕获」变成「未选用」，没有点任何按钮；选中后读作「使用中」（演示的选择随后已还原为 `builtin:default`）。
- 新增测试：无会话读只返回用户级、管理器不按收起过滤、挂载即自动抓取。
- 全量 2562 测试通过，门禁干净。
