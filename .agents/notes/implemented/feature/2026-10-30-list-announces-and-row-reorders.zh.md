# Agent Note：列表播报自己有多少项，页签行也能用键盘重排

Status: implemented

## Problem

无障碍评审又提了两条，都关于看不见屏幕的读者。

**搜索或筛选改变列表时没有任何提示。** 在搜索框输入、按下状态页签或让列表增长，都会静默替换集合：数量只写在页签标签里，空状态只是一段普通文字。读屏用户得不到「输入生效了」的任何信号。

**重排页签只有指针路径。** 在预设管理界面上，按住后拖动是改变位置的唯一方式。同一个组件还承载工作区页签行，而那一行早已在自己的包装层里支持 Alt+方向键；只传了 `onReorder` 的界面完全没有键盘路径（WCAG 2.1.1 与 2.5.7）。

## Decision

- **界面自带一条礼貌播报。** `ResourceSurface` 渲染一条视觉隐藏的 `role="status"` 段落，读作「显示 N / M 项」，其中 M 是命中集合而非整个清单：搜索之后读作「1 / 1」，分页时读作「120 / 971」。隐藏是因为页签与「再多显示」按钮已经在屏幕上写着同样的数字。
- **Alt+方向键在组件内部移动页签本身。** `TabRail` 在提供 `onReorder` 时处理 Alt+左右：焦点跟着页签走，所以第二次按下从新位置继续；普通方向键仍然只移动选中。两个渲染该行的界面都继承这套按键，两行不会再各自漂移。

## Alternatives considered

- **只在结果数量变化时播报。** 否决：读者还需要知道正在浏览的总量，而搜索后一句「1 / 1」同时回答了这两个问题。
- **把播报放在每个面板里。** 否决：同一句话复制六份，而真正知道数字的是共享列表。
- **像工作区行那样让每个界面自己接键盘。** 否决：那一行有、旁边这一行没有，正是这么来的。

## Consequences

- 读屏用户在搜索、筛选与翻页之后都能听到结果数量。
- 预设管理器的行可以不用指针重排，手势与工作区行一致。
- 每个界面都有一条状态段落，在第一次改变之前为空。

## Verification

- `packages/market-ui/test/resource-surface.test.ts` 搜索后断言状态行读作「N / M」且是礼貌播报区域。
- `packages/market-ui/test/tab-rail-drag.test.ts` 按 Alt+方向键断言重排回调被调用，并断言同一按键在没有 Alt 时只移动选中。
- 四个类型检查、`check:refactor` 与全量测试通过。
