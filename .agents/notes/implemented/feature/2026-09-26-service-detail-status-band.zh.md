# Agent Note: 服务详情只留一个状态容器

Status: implemented

改自 [失败报告先说出原因](2026-09-24-failure-report-with-cause-chain.md)。

## Problem

那次修好了"首句用本地化句子、原文收进折叠"，但失败报告仍然是概览表格下面的**第二块实底面板**。三个问题留了下来：

1. **两个容器、两种红。** 弹窗开头是平台的中性状态带，下面又用一整块红底面板重复同一个状态；重试回执还漂在最顶部，离产生它的按钮最远。
2. **原因排在元数据之后。** 读者要问的"能不能用、不能用该怎么办"，得先跨过四格概览表。
3. **身份是机器名。** 标题用的是挂载名（`chrome-devtools__chrome-devtools`），那也是工具命名空间，于是这一行唯一可读的名字（`serverKey`）反而没出现。

状态带当时完全没有边条色，而旁边的列表卡片带着状态色，弹窗与卡片自相矛盾。

## Decision

- **一个弹窗一个容器。** `src/client/ui/StatusBand.tsx` 把状态带做成详情弹窗唯一的状态面，顺序固定：状态点 + 标签 + 该状态唯一的恢复动作（右端）、上次操作的回执、分类后的原因句、收在 host `DisclosureRow` 里的记录诊断、以及 mono 的端点或命令。`FailureReport.tsx` 与其样式模块已删除，MCP 与 LSP 详情都渲染 `StatusBand`。
- **状态由边条表达，正文与底色不承担。** `bandTone(ResourceState)` 把卡片的状态词汇映射成边条色（active→success、warning→warn、error→error、其余 neutral），底色保持平台的软中性色。`mcpCardState` / `lspCardState` 是状态的唯一来源，卡片与详情带因此不可能各说各话。弹窗正文不用错误色，弹窗内也不再出现第二块错误色实底面板。
- **动作放在状态所在处。** 重试与重新授权从被删掉的底栏移进状态带右端；重新授权的确认紧贴状态带下方，是无底色的内联两按钮块。MCP 详情不再有底栏，也没有启用开关——卡片的开关写同一份覆盖记录，详情是只读视图（依据 [详情弹窗修正](2026-09-25-detail-dialog-fixes.zh.md)）。
- **回执只报告这次操作。** 它只说操作有没有重新连上；下面的原因来自刷新后的那一行，因此不再复述记录诊断。只有重连成功才用成功色。
- **可读身份。** 弹窗标题与卡片身份行对 plugin 行显示 `serverKey`、对 direct 行显示 `name`；挂载名在概览里保留独立一行（`mcpMountNameLabel`），卡片则以 `title` 携带它。
- **工具清单为空时按状态说话。** 失败或来源缺失且没有工具的行，提示需要连接后才能读到清单（`mcpToolsUnreachable`），不再声称没有已注册工具。

## Alternatives considered

- **给 `panel.module.css` 的共享 `.hero` 加 tone 修饰类。** 拒绝：`.hero` 是每个详情弹窗的状态带（套件、用户条目、凭据都用），在那里加边条与 tone 会改到本次不拥有的界面；独立组件让 `panel.module.css` 保持逐字节不变。
- **把状态带并进 `FailureReport`，而不是替换它。** 拒绝：那份报告自带实底容器，而"第二块容器"正是读者看到的问题；状态、动作与诊断必须由同一个组件拥有。
- **重新授权确认改用宿主 `RiskConfirmation`。** 拒绝：卸载套件继续用它是因为那会删除套件自有文件；重新授权是恢复动作，加一个勾选确认会多出一步。内联确认已写明后果并给出取消/确认。
- **沿用"已连接/已挂载读中性色"的初稿。** 拒绝，改为与卡片共用映射：同一个服务的两处界面不能对"是否健康"给出不同答案。
- **把挂载名放进弹窗标题。** 拒绝：标题是读者最先扫的一行，挂载名是命名空间细节，应放在概览里服务键旁边。

## Consequences

- 以后新增一种服务状态，只需在 `mcpCardState` / `lspCardState` 里加一次，卡片边条与状态带边条同时跟上。
- 原因句与其折叠项现在位于状态带内部，将来往带里加内容必须遵守组件固定的顺序。
- `mcpReasonLabel` 与 `lspReasonLabel` 已删除：状态带的那句话取代了带标题的原因块。

## Verification

- `pnpm run check:quick`、`pnpm run format:check`、`pnpm run check:architecture` 与全量测试全绿（97 文件；改版时 847 用例，另加复核后补的 tone 与 LSP 标题用例）。
- 用真实中文词典渲染 `mount-failed` 的 MCP 详情：收起状态首句是「找不到命令：确认它在 PATH 中，或改用绝对路径。」，记录的英文原句只在展开「诊断详情」后出现，工具区显示「服务未连接，暂时读不到工具清单」。
- 一位只读复核者按 file:line 逐条复现契约，再分别破坏折叠判断与回执，确认新用例真的会失败（5 条与 1 条），并把工作树逐字节还原。
- 边条映射最初没有覆盖——把 `bandTone` 改成常量后所有用例仍绿——复核发现后已加一条同时断言状态带 `data-band-tone` 与卡片 `data-resource-state` 的用例锁住它。
