# Agent Note: one card anatomy and host affordances across the plugin workspace

Status: implemented

Revised by [live card affordances and the workspace query container](2026-09-16-workspace-live-card-affordances.md), [the six editors' dialog chrome](2026-09-16-workspace-editor-chrome.md), and [the detail dialogs' row and document body](2026-09-16-detail-row-and-document-body.md): the container that makes the narrow rules apply, the whole-cluster reveal, the MCP/LSP enable switches, and the editors' header, pane chips, field hints and footer hints.

## Problem

The six surfaces (market, skills, commands, agent roles, MCP services, LSP services) shared a workspace shell but not a card, a dialog scale, or an editor:

1. **Six card grammars.** The suite card was `name + version / description / source · dimension + layout tag / surface-count row`; the skills-commands-persona row was `name + source badge / description / actions`; the MCP card was `dot + name + tool count / endpoint`; the LSP row was `dot + name + source + state pill / command`. Heights followed content, so no two rows lined up and the same fact (provenance, a count, a state) was drawn three different ways.
2. **Three action placements.** Market actions were top-right, entry actions bottom-right, and MCP/LSP cards had none. The market's trailing action column also cost every card 92px of text width.
3. **Five dialog widths.** Add-source was 500px, the entry editor 720px `max-width` (so it shrank with content), MCP/LSP detail 720px, suite detail 800px, and the shared `DetailModal` base 1120px. Two chromes coexisted: some dialogs showed a header close _and_ a footer cancel.
4. **One editor for three surfaces.** Skills, commands, and personas all rendered the same Markdown form with a preview/edit toggle wedged between the hint and the textarea.
5. **Seven local reimplementations of shipped host components:** a toggle switch, a confirm dialog, a status dot, the tag/chip system, the disclosure row, the JSON dump, and the filter `Pill`.

## Decision

- **One card anatomy, owned by the shared layer.** `ui/resource-card.module.css` defines the box, the row grid (`'id act' / 'body body' / 'foot foot'` in the grid, `'id foot body act'` in the list) and the slot classes every surface fills (`rowId`, `rowBody`, `rowFoot`, `rowActions`, `name`, `desc`, `monoLine`, `provenance`, `count`, `countValue`, `iconBtn`, `revealOnHover`). A surface styles only the slots inside its rows. Attribute selectors on `data-resource-state` / `data-resource-view` keep this layer above the surfaces' single-class rules regardless of stylesheet order.
- **One action cluster, on the identity row.** Secondary icon actions (refresh, edit, delete), the primary CTA for a suite that is not installed, and the enable switch all share one cluster on the identity row's trailing edge. The cluster only occupies the identity row, so the body and source rows span the full card width and the description is no longer squeezed. In the grid at the narrow container width the cluster leaves the flow, the identity row reserves its width, and the whole group — switch and primary CTA included — fades in on hover or `:focus-within`. MCP and LSP cards carry the same enable switch, so a service can be stopped without opening its detail; retry and reauthorization stay in the detail footer.
- **The source row names its source in both views.** It leads with the owning suite in the same mono face the identity row uses, then the counts the user scans for; the suite name ellipsizes before a count does. A user-panel tile shows its owning suite for a plugin-provided entry and its disk path for a user-authored one.
- **Deterministic size.** `auto-fill minmax(280px, 1fr)` columns with 122px rows for a wide container, 56px list rows, and container queries keyed on the panel rather than the viewport — the plugin always renders inside a resizable settings column, so the previous `@media` breakpoints never matched in production. The settings column hands a resource list about 560px, where a 280px track fits only one column; the narrow branch therefore forces two `minmax(0, 1fr)` columns 4px apart with content-sized rows, so a one-line card is a shorter card and the grid row is as tall as its tallest tile. The description is capped at two lines without reserving them, and the three rows stack from the top (`align-content: start`), so it sits a constant 4px above the source row. Every page that renders a resource grid has to sit inside a query container — the user-content surfaces get one from `panel.module.css .shell`, and the market page declares its own on `.market`.
- **Every row carries its area class.** A body that carried only its slot class was auto-placed by the grid into the first free cell — the empty action column of a card that has no actions — which put an MCP or LSP endpoint beside its name and squeezed the name to "j…". `rowBody` is now on every body.
- **One clamp technique.** Two lines through `max-height`, the technique `market.module.css` already documented as the one the nested-scroll compositor cannot paint outside its box; the `-webkit-line-clamp` twin in `panel.module.css` is gone.
- **Three dialog sizes on the host `Modal`:** `sm` 460 (confirmation), `md` 640 (the add-source form), `lg` 880 (details and editors), with one chrome: header, scrolling body, sticky footer.
- **Details keep their capability and gain structure.** The suite detail keeps the lazy skill-content fetch and the per-surface toggles, and renders a `插件套件 · <source>` subtitle, a title that is the name alone (the version rides the status band), the prototype's four overview cells — source suite, layout, author, and the checkout's last change, which the payload reports as an ISO timestamp — plus a block per surface whose rows are the shared `DetailRow`s with a one-line clamped summary; a surface the suite does not carry is left out, and validation diagnostics always render with a passing note when clean. JSON goes through the host `JsonTree`. A new `ui/UserEntryDetail.tsx` gives skills, commands, and roles the same read-in-place surface the suite already had.
- **The entry editor is two panes.** Source and rendered preview side by side, the mode toggle removed, and a per-kind title (`新建技能` / `新建命令` / `新建代理角色`). A subtitle names the write target or the file being edited, each pane header carries its chip (the document's file name, and `实时` on the preview), the frontmatter caveat sits under the textarea, the footer states what saving does, and a command's `参数提示` pairs with the name on the create row.
- **Host components replace the local ones:** `Switch`, `StateDot`, `Tag`, `Pill`, `DisclosureRow`, `JsonTree`, and `RiskConfirmation` (which now gates uninstall behind an acknowledgement). `ui/ToggleSwitch.tsx`, `ui/StatusIcon.tsx`, and the `SourceBadge` export are deleted, along with the filter-icon helpers the toolbar never rendered and every CSS rule those removals orphaned.
- **The repository source strip keeps its shipped behaviour.** Its capsule chips, two-row fold, hover overlay, selected-source rename control, and the duplicate `全部` label are all as shipped; the folded state additionally bounds its 6px overhang with `clip-path` and takes `z-index: 20` on hover so the overlay paints above the cards, and the module comment that contradicted the caller's chip order was corrected.

## Alternatives considered

- **Keeping a per-surface card stylesheet.** Rejected: the six grammars were the defect, and duplicated geometry is what let them drift. One shared slot layer is what makes "same height, same rows" a property of the code rather than of review.
- **Reusing `RiskConfirmation` for removing a source too.** Rejected: that dialog's single checkbox is an _acknowledgement_, while removing a source asks a _choice_ (delete the managed checkout or keep it). Folding the two into one control would have silently dropped the choice, so remove-source keeps the plain confirm with its file checkbox.
- **Showing the read-only `mcp.json` row the prototype drew for an MCP service's config.** Rejected: the service detail's configuration is editable in place through `ServerConfigDetail`, and a read-only JSON row beside it would add a second, non-authoritative view. The read-only JSON row stays where it belongs — in the _suite_ detail, which has no editor.
- **Reusing the host `SearchBlock` for the search field.** Rejected: it is a search _result_ block with a line cap, not an input.
- **Renaming the source strip's leading chip to `全部来源`.** Rejected: the strip's `全部` counts every suite and the filter's `全部` counts the selected scope, so they only coincide while no source is picked; renaming would have been a copy change with no defect behind it.
- **Unifying on `-webkit-line-clamp`.** Rejected in favour of `max-height`: the market's existing comment records that the clamping box can paint text outside its bounds when the surrounding page re-scrolls.
- **Adding install/uninstall to the suite-detail footer.** Accepted, but only as a pass-through of the card's own handlers, so the detail never becomes a second place that decides what installing means.

## Risks

- Every surface now shares one grid template, so a future per-surface layout need has to be expressed through the slots rather than by overriding the box; the shared layer's attribute selectors deliberately outrank single-class rules.
- The action cluster moved from the card's trailing column to its identity row on the suite card, which is a small visual relocation for existing users.
- `Switch` is controlled with a required `label`, so a render site can no longer ship a toggle without an accessible name; the two call sites pass the same enable/disable copy they used as a title.
- The card is smaller (122px against roughly 150–200px content-driven), so a description longer than two lines is now truncated where it previously pushed the card taller.
