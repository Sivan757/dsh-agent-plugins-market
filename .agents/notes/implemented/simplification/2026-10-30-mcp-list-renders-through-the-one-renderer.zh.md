# Agent Note：MCP 清单改由唯一资源列表渲染

Status: implemented

## Problem

MCP 服务面板仍在自建工具栏、集合与清单卡片，于是仓库里同一套句法有三份实现，迁移棘轮也一直把它留在名单上。随之而来有两个代价：删除动作放在卡上，而共享渲染器的契约写明破坏性操作属于卡片打开的详情；面板的搜索与筛选计数走一个专用视图模型，面板一迁过去，渲染器就得把同一套逻辑再写一遍。

## Decision

- **条目契约补上清单需要的字段。** `source` 作为来源行的出处标记领读，`monoBody` 让端点或命令用等宽字体，`keywords` 把卡片不渲染的文字纳入搜索，`toggleLabel` 按「按下后发生什么」命名开关，`canEdit` 与 `editDisabled` 逐行控制编辑器，`chip` 与 `surface` 承载带出处徽章、且窄容器会隐藏该徽章的行，筛选也可以带说明。它们都不是某个页面专属的，而是列表可以就一行陈述的事实。
- **面板只保留自己的领域工作。** 它把状态行映射成条目，再按 id 处理打开、启停与编辑；工具栏、筛选、搜索、视图切换与卡片都由渲染器持有。
- **删除移入详情对话框。** 卡片的点击意味着「打开」，唯一的不可逆动作放在里面一步，确认与重读仍由面板既有的确认流程负责。这与[卡片行那条记录](../bug-fix/2026-10-30-card-rows-and-the-switch-that-never-hides.zh.md)以及两个早就把破坏性操作留在详情里的页面一致。
- **被取代的视图模型删除。** `deriveMcpStatusViewModel` 失去最后一个调用方；`matchesMcpFilter` 保留，因为它是渲染器统计各标签的唯一判断，标签上的数字仍等于点开它看到的行数。
- **棘轮缩小。** `features/mcp/StatusPanel.tsx` 从单渲染器名单里移除，面板失效的工具栏与空态样式一并删除。

## Alternatives considered

- **给共享渲染器加 `onDelete` 能力。** 否决：那会让每个页面都能把不可逆动作放到卡上，而这次迁移要守住的正是这条契约。
- **只给 MCP 保留卡片删除。** 否决：会有一个页面保留旧句法，面板也就根本用不上共享卡片。
- **保留视图模型来算计数与搜索。** 否决：同一个判断写两遍必然漂移，而渲染器本来就从其渲染的条目推导这两件事。
- **在同一次改动里连用户面板与市场页一起迁。** 否决：它们各自带有破坏性操作与主操作，一次一个页面才能让失败的断言可归因。

## Consequences

- 删除用户自建服务现在多一次点击：先打开服务，再删除。
- 窄容器隐藏徽章的规则通过 `chip` 与 `surface` 继续生效，MCP 卡在来源行已经写出套件的地方仍会收起出处标签。
- 面板不再持有自己的搜索或筛选状态；渲染器的视图切换与筛选标签是唯一的。
- 用户面板与市场页随后迁到同一份契约，[那两条记录](2026-10-30-user-panels-render-through-the-one-renderer.zh.md)写明了过程。

- `packages/market-bundle/test/integration/client-view-models.test.ts` 证明留下来的筛选判断仍让停用行可按归属与停用标签触达。

- 迁移后 `check:css` 与 `check:single-renderer` 通过；客户端、测试客户端与服务端三个工程的类型检查干净。
