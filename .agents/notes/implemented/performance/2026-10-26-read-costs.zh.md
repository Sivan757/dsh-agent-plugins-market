# Agent Note: 实测的客户端与宿主读取开销

Status: implemented

## Problem

`docs/scratch/audit/performance.md` 中的性能审计测出五处日常使用付出、却没有用户可见收益的开销。每一项都是数字而不是印象：

- 每次进入市场页都会发出两次概览读取，而模块缓存从不在重新挂载后存活，
- 行缓存比需要复用它的轮询早 500 毫秒过期，于是轮询会重扫每个文档，而缓存自己的契约却说它吸收了这次轮询，
- 每个技能行把同一份 frontmatter 解析两次，
- 项目面板存储按会话作键，而项目目录是唯一变化的输入，于是同一工作区的两个会话把同样的文件扫两遍且互不共享，
- 扩展窗口轮询无条件重新武装，于是隐藏窗口每隔一个间隔就请求宿主重建整个清单，而没人在看答案。

## Decision

### 每次进入市场页只读取一次概览

`packages/market-ui/src/features/market/market-resource.ts` 新增 `peekOverview`，只读取缓存中的答案，不发起任何请求。`MarketSection` 在渲染期间用它播种状态，因此渲染不再与拥有该请求的挂载副作用竞争。`refresh` 增加 `force` 参数，只在调用方知道已存答案不再成立时失效缓存：有变更落地，或服务端解析文本所用的语言变了。挂载不属于这种情况。

`loadOverview` 中的世代守卫是旧的两连读之所以静默的原因：渲染期请求在副作用清空缓存时仍在飞，于是它的答案按设计被丢弃，再由第二个请求替代。

### 行缓存只有一个节拍契约

`packages/market-contracts/src/contracts/refresh-cadence.ts` 现在拥有 `EXTENSION_WINDOW_POLL_MS` 与 `TRANSLATION_POLL_MS`，并据此推导 `ROW_CACHE_MAX_AGE_MS`。边界严格位于两个轮询之间，两条边用户都能看到：

- 它必须长于翻译轮询，否则缓存永远吸收不到它存在的那些读取，
- 它必须在窗口轮询之前过期，否则磁盘上一次手改会跨两次轮询才可见，而不是一次。

`rowCacheMaxAgeMs` 拒绝无法同时满足两条边的三元组，并在模块加载时运行，因此将来的节拍改动会当场失败，而不是悄悄发出一个不再吸收、或悄悄开始隐藏编辑的边界。推导值正是面板此前使用的 2000 毫秒，行为不变，而这条关系现在被强制而不是被描述。

### 每个技能行只解析一次 frontmatter

`packages/market-catalog/src/scanning/skills-parse.ts` 中的 `skillFieldsFromRecord` 从调用方已解析的记录推导技能字段。`parseSkillFrontmatter` 保留自己的解析与宽松回退，用于 Claude Code 编写的 frontmatter，发现流程仍然使用它。面板行现在通过严格读取器解析一次，再从结果推导技能字段。

严格判定仍是权威。被严格解析拒绝的文档会带上校验错误并置为 `disabled`，而调用标志改变不了这一点，因此解析失败的文档永远不会走到推导出的字段。

### 每个工作区只有一个项目读取器

`packages/market-bundle/src/application/project-readers.ts` 每个工作区持有一个读取器，`session-extension.ts` 用工作区而不是智能体作键。读取器惰性构建，因此从不打开面板的会话零开销；当没有存活智能体指向该工作区时释放，因此关闭的会话无法钉住它的扫描。

### 窗口轮询在隐藏时暂停

`use-window.ts` 只在文档可见时安排下一次读取，`visibilitychange` 监听器用恰好一次读取恢复暂停的轮询。从未隐藏过的窗口保留已武装的定时器，因此焦点变化不会增加读取。间隔本身不变：审计判定该节拍对新鲜度是正确的、重建才是开销，而移动节拍只会迁移开销而不是消除它。

## Measured before and after

同一台机器、同一形状的测具，本分支改动前后。

| 测量项                            | 改动前            | 改动后                 |
| --------------------------------- | ----------------- | ---------------------- |
| 首次进入市场页的概览读取数        | 2                 | 1                      |
| 重新进入市场页的概览读取数        | 2                 | 1                      |
| 每个技能文档的 frontmatter 工作量 | 81.7 微秒         | 40.7 微秒              |
| 300 文档技能扫描，五次取最优      | 每文档 164.5 微秒 | 每文档 105 至 121 微秒 |
| 两个会话读取同一工作区的扫描次数  | 2                 | 1                      |
| 四个间隔内文档隐藏时的窗口读取数  | 5                 | 1                      |
| 四个间隔内文档可见时的窗口读取数  | 5                 | 5                      |
| 恢复可见时的窗口读取数            | 不适用            | 1                      |

frontmatter 一行是在单进程内交错五轮、取最优的对照运行，因为端到端扫描由文件读取主导且逐次波动。frontmatter 部分的百分比节省是可归因的数字，扫描一行是同一改动在整个读取路径上的体现。

## The visible poll's inventory rebuild stays

`ExtensionRuntime.window` 每次读取都会重建整个清单，审计将其记为未认领的发现。这里实测而不是假定，并决定保留，因为跳过重建无法不改变读者所见。

在跨三个面、共 60 个文档的面板集上测量，每次读取都放在上一次之后一个轮询间隔处，因此行缓存确实已过期：

| 场景                       | 清单读取次数 | 开销                             |
| -------------------------- | ------------ | -------------------------------- |
| 无变化，四次轮询           | 4 次         | 每次 22 至 94 毫秒，中位 45 毫秒 |
| 一个套件切换后，下一次轮询 | 1 次         | 15 至 119 毫秒                   |
| 同一次读取但跳过重建       | 0 次         | 0.2 至 1.2 毫秒                  |

跳过能在稳定态削减 98%，按每分钟 24 次轮询计约等于每会话每分钟 1.1 秒 CPU。放弃它的原因只有一个。

`stale` 由每一次进程内目录变更置位，因此以 `stale` 与 `dirty` 为门不会在那里丢失任何东西。它丢失的是磁盘上文档的一次编辑。`PanelResources.scan` 每次扫描都会重读每个已声明文档的文本（`packages/market-runtime/src/application/panel-resources.ts:417-424`），据此推导 `description` 与 `disabled`，而 `readExtensionInventory` 把它们作为 `description`、`available`、`globalEnabled` 带进预设管理器的行（`packages/market-bundle/src/application/extension-inventory.ts:297-328`）。2500 毫秒的轮询总是超过 2000 毫秒的行缓存，因此那次重读是手改 frontmatter 字段到达管理器的唯一路径，且能在一个轮询间隔内到达。

加门会把它从一个轮询间隔推迟到下一次进程内目录事件，而后者可能永不到来。过期标记看不见文件系统，而任何等于轮询间隔的时限都帮不上忙：轮询只在其读取完成后才重新武装，因此相邻轮询本就相隔超过一个间隔，每一次都会错过任何设为该间隔的时限。

能保住新鲜度的设计是以指纹为门而不是以过期标记为门：`stamp` 已经为它产出的每一行做过 stat，因此扫描可以先比较这些修改时间，只重读时间戳变动的文档。这完全保住了单轮询可见性，代价是在三个面都依赖的面板存储里新增一个新鲜度键。它比本波次其余改动更大，因此连同这份测量留作后续，而不在此落地。

## Alternatives considered

- **在市场页用 `loadOverview()` 播种，再让副作用加入在飞请求**被否决，因为它只在请求仍在飞时成立。请求落地后副作用会再发一个，而那正是被报告的缺陷。渲染必须根本不发请求。
- **在无过期标记时跳过窗口的清单重建**被否决，因为它会把手改文档隐藏到下一次目录事件，而轮询是重读已发现文档的唯一路径。测量见上。
- **让 `ROW_CACHE_MAX_AGE_MS` 保持字面量、用注释说明节拍**被否决，因为那恰恰是曾经漂移的状态。注释无法失败，而这两个数字分处不同包、没有任何东西把它们绑在一起。
- **只按窗口轮询推导边界**被否决，因为窗口轮询不是唯一读者。1500 毫秒的翻译轮询原本就在旧边界内，若只按较慢节拍推导就会落到边界外。因此 `rowCacheMaxAgeMs` 检查两条边，而将来只保留窗口一边的简化会悄悄把 1500 毫秒轮询排除在边界之外。
- **用拉长窗口轮询间隔代替缩短缓存**被否决，因为它迁移开销而不是消除开销。轮询间隔是新鲜度策略，而审计测出重建才是花费。
- **把两个解析器合并成一个**被否决，因为它们的分歧是刻意的。严格读取器是校验权威，技能解析带有针对被严格 YAML 拒绝的编写型 frontmatter 的宽松回退，合并后要么到处接受畸形文档，要么到处拒绝。
- **按工作区作键且永不释放**被否决，因为关闭的会话会钉住扫描直到进程结束。释放以没有其他存活智能体指向该工作区为条件，这让共享的读取器在其仍被共享时保留。
- **彻底停掉窗口轮询、只依赖提交事件**被否决，因为轮询是文档化的清单兜底。提交事件覆盖选择变更，而非没有伴随事件的目录变更。

## Consequences

一次挂载、一次轮询、一次扫描、一个会话在一个工作区中的分摊成本，现在等于工作本身所需，而不是它的若干倍。代价是：

- 隐藏窗口不再轮询，因此留在后台标签页的面板会显示陈旧清单直到再次可见。恢复时的读取发生在读者能据此行动之前。
- 行缓存边界现在是两个节拍的推论而不是可调项。想要不同陈旧边界的部署必须改节拍，这是诚实的耦合。
- 工作区读取器被共享，因此面板存储的缓存现在跨会话摊薄而不是私有。这些存储不持有会话状态，这正是共享成立的原因。
- 严格 frontmatter 判定现在也决定是否推导技能字段，因此只有严格解析通过的文档才会从该路径读取其调用标志。

## Testing

`packages/market-ui/test/market-overview-reads.test.ts` 通过计数 fetch 统计概览请求，因此每次挂载一次读取是断言，而不是墙钟测量。

`packages/market-ui/test/extension-window-poll.test.ts` 在假定时器下驱动真实钩子并替换 `document.hidden`，统计可见时、隐藏时、恢复时以及面板卸载后的读取次数。

`packages/market-runtime/test/row-cache-cadence.test.ts` 钉住推导出的边界、它必须满足的两条边、违反任一条的调度被拒绝，以及边界内的读取复用扫描而超过边界的读取重扫。

`packages/market-bundle/test/integration/project-readers.test.ts` 以 `stat` 调用次数统计扫描，因为一次扫描会为其产出的每一行盖章。同一工作区的两个会话产生一次扫描，一个会话离开时仍在使用的工作区保留缓存，最后一个会话离开后下一个会话重新扫描。

## Verification

上面五个测量数字在本分支上用一次性测具复现，测具在提交前已删除。长期测试断言的是机制，因此将来重新引入双次读取的改动会在任何机器上失败，而不是只在有人重新测量时才发现。

门禁：类型检查、lint、格式检查与完整单元套件（256 个文件、2429 个测试）在本分支通过。
