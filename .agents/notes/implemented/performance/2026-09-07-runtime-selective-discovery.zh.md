# Agent Note: 运行时按需发现来源

Status: implemented

## Problem

插件激活使用完整市场目录构建运行时挂载和技能候选。没有启用套件的大型配置源仍会在会话启动时付出完整文件系统扫描成本。

## Decision

运行时从持久化安装状态得到已启用来源，只扫描这些来源。MCP 覆盖读取接受已选套件集合。并发扫描会合并，失效后的旧扫描结果不能重新写入缓存。市场概览仍保持全量扫描，因此来源和套件清单不变。

本决策部分替代[发现缓存记录](../architecture/2026-09-02-catalog-scan-cache.zh.md)的失效机制；其中 TTL、有界缓存与 frontmatter 缓存决策继续生效。

## Alternatives considered

- **自动删除或裁剪来源缓存**被否决，因为来源内容由用户管理，之后可能仍需安装。
- **后台刷新 Git 来源**被否决，因为启动不应引入网络或代理延迟。
- **客户端延迟加载**被否决，因为运行时提供者仍需要确定性的服务端套件数据。

## Consequences

启动运行时成本随包含启用套件的来源内容增长，仍扫描被选来源内的全部套件。没有启用安装的来源仍保留在市场页面，只在请求完整目录时扫描。来源刷新和内容变更会同时失效运行时与市场发现代次。项目原生发现不变。

## Verification

`tests/catalog-runtime.test.ts`覆盖零启用冷启动、来源选择、并发合并和失效。类型检查、lint 及针对性 Vitest 测试通过。
