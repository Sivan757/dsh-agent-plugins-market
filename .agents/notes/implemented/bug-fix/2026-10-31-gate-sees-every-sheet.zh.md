# Agent Note：类名检查看得见每张样式表，工具行跟随它所在的对话框

Status: implemented

## Problem

间距审计在给出数值之后留下两条结构性问题。

**三张样式表从未被检查。** `check:css` 跳过了 `market.module.css`、`panel.module.css` 与 `source-strip.module.css`：通过计算键访问样式表的文件无法被追踪——`ExtensionPresetEntry.tsx` 在三处用拼接构造类名，`page-mode.tsx` 用运行时名字索引样式表。那三张表里的死规则全部不可见，而审计恰好在那里发现了它们。

**连接器工具表按窗口断点布局。** 它在**窗口**小于 760px 时堆叠，而同面板的列表在**容器**小于 700px 时收窄。审计把面板 shell 当成了容器，但工具表在一个 portal 到 body 的详情对话框里，面板容器并不是它的祖先，容器查询在那里同样匹配不上。

## Decision

- **给类名起名，绝不计算它。** 三处拼接改成模板字符串，`page-mode.tsx` 用一个常量映射命名它需要的那两个类，而不再索引样式表。`check:css` 现在分析全部二十张表，编译器在控制台之前就抓到改名的类，「等视觉复核再删」的登记表已经清空。
- **删掉检查器现在看得见的东西。** 十九条死规则（市场手写的卡片网格与插件卡片外框、面板的条目容器块与 `.body`、连接器的空态/页脚/详情规则、来源条在 flex 行上的 grid 声明、详情的表单对、表单的行操作与内联勾选）连同记录它们的十行登记一起删除。
- **对话框就是容器。** `.dialog[role='dialog']` 声明 `container-type: inline-size`，工具表的查询于是跟随对话框自身宽度。portal 出去的对话框没有面板祖先，这是规则唯一能解析的容器。
- **等宽值行一个字号。** 11.5px/18px，四处里已有三处如此。

## Alternatives considered

- **把死规则登记而不是删掉。** 否决：登记表是给「删除有风险」的规则用的，而三张表可读之后这些规则已无任何引用。
- **工具表保留 `@media (max-width: 760px)`。** 否决：它按窗口判断，宽窗口配窄对话框时仍挤三列。
- **媒体查询与容器查询都写。** 否决：同一个问题两个答案，而媒体查询恰好在容器查询正确的地方是错的。

## Consequences

- 任何无人引用的类在出现当天就让门禁失败，覆盖每一张样式表。
- 连接器工具行在对话框放不下时堆叠，与窗口无关。
- 四条等宽值行字号一致。
