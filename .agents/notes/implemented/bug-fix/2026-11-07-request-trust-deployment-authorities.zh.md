# Agent Note: 请求信任闸门接受部署声明的权威名

Status: implemented

## Problem

`isTrustedMutation` 拒绝一切 `Host` 不是 loopback 的请求。这条规则对只经 `127.0.0.1` 访问的服务是正确的，对本插件最常见的安装形态却是错误的：`dsh web --host 0.0.0.0` 部署在反向代理之后，由代理在公网域名上终止 TLS。

代理会保留传入的 `Host`，于是 `https://dsh.example.com` 上的浏览器把 `Host: dsh.example.com` 送到本插件。闸门对所有写路由——以及走同一闸门的两个读路由，扩展窗口与 hooks 概览——都回 403 `{"ok":false,"code":"cross-origin"}`，而宿主的 `/api` 闸门早已接受了同一个请求，因为部署方用 `--trusted-host`、或通过登记到达 Host 的插件，把这个名字声明给了宿主。

两道闸门对同一个部署给出了不同答案。宿主那道是运维配置过的；这一道无从得知。 #156 写下 loopback 规则时在源码里记录了取舍：*「一个用别的名字暴露这个端口的部署需要一份配置好的白名单，而本插件没有。」* 本记录补上缺失的清单。

## Decision

`isTrustedMutation(request, trust)` 接受一个 `RequestTrust`，`Host` 检查的来源从一处变成三处：

1. loopback 主机名，与之前完全一致；
2. 监听器自身的绑定地址，任意端口——浏览器直接拨这个字面量不会额外授予什么，Origin 与 cross-site 检查仍然生效；
3. `trustedHosts`，宿主的实时清单：带端口的条目匹配该精确权威，无端口的条目匹配该主机名的任意端口。

另外两道检查不动：`sec-fetch-site: cross-site` 照旧直接拒绝，存在的 `Origin` 仍须等于 `Host`。

`requestTrustOf(ctx)` 从 `connection.trustedHosts` 取清单、从 `webServer.host` 取绑定地址，惰性读取，每请求一次——宿主在运行期会往清单里追加条目，因此本插件挂载之后才登记的名字无需重启即可被接受。两者都取不到的上下文得到空信任，即本模块一贯的 loopback-only 规则；没有 `connection` 服务的宿主因此行为完全不变。

## Consequences

反向代理部署无需在插件里再存一份名字清单即可工作，也没有削弱 rebinding 防线：部署方从未声明的名字仍被拒绝，那正是 #156 修复的攻击。本插件的闸门与宿主的闸门现在接受同一组权威名，因为它们读同一份清单。

部署方授予的信任就是其宿主闸门已经授予的信任。一个登记所有到达 `Host` 的部署——通配条目插件实现的形态——已经把宿主闸门放宽到所有名字，本闸门跟随它，而不是充当唯一仍然拒绝「服务器刚刚发出的那个页面」的组件。那是部署方一次性、在一处做出的选择，不是本插件所做的放宽。

loopback 部署行为不变；早于 `connection` 服务的宿主行为也不变。

## Alternatives considered

**比较 `Origin` 与 `Host` 并去掉 loopback 规则。** 这正是 #156 移除掉的检查：DNS rebinding 页面在两个头里都带攻击者域名，浏览器认为请求同源，这个比较证明不了任何东西。重新引入它会重新打开经由 hook dry run 的未认证命令执行。

**插件自带的 allow-list 配置项。** 能用，但它会是宿主已经拥有的同一个事实的第二份副本，写在另一个文件里，第一次有运维只往其中一处加名字时就开始漂移。决定请求能否到达这段代码的，是宿主那份清单。

**依赖宿主的 `/api` 闸门并删掉本模块。** 宿主闸门以 `/api` 前缀路由挂载；这里的路由是精确路径，先命中，因此宿主闸门不在它们的路径上。必须有人检查这些路由，而且应当用同样的方式检查。

**保留 loopback 规则并文档化为「用 SSH 隧道」。** 那等于放弃宿主支持的远程 Web 部署形态，只为一条部署方无法通过任何受支持机制满足的规则。

## Testing

`packages/market-bundle/test/integration/request-trust.test.ts` 补上新输入的两个方向。已声明的名字配合同源 `Origin` 被接受；部署方从未声明的域名（rebinding 那一例）仍被拒绝；已声明的名字配上不一致的 `Origin`、不透明 `Origin` 或 `cross-site` 被拒绝；带端口的条目只匹配该端口，无端口的条目匹配任意端口；绑定地址在任意端口被接受而邻近地址不被接受；空信任保持 loopback-only 行为。`requestTrustOf` 对着一个假上下文驱动：首次读取之后再往清单追加一条，第二个名字无需再次读取服务即被接受——这正是实时清单的契约。
