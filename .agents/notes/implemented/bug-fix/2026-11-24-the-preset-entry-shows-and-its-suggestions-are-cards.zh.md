# Agent Note：预设入口显示出来，建议行用卡片

状态：已实现

## 问题

输入框的 Agent 预设功能上同时暴露了两个缺陷。

第一个：宿主调用 `conversation.input.left` 这个位置却没给 `sessionId` 时，入口会隐藏自己并告警一次。这条防御描述的是更早的宿主：已发布的 slot 契约给每个 session 作用域的位置都标了 `sessionId: SessionId`，0.2.3-alpha.2 也确实传了它（DOM 探针确认过）。于是这条守卫比它的理由活得更久：在遵守契约的宿主上，只要某个探针报告没有 id，读者照样会失去入口。

第二个：建议对话框把候选行渲染成表单 `.field` 里的普通 `label`。表单的文本字段规则把所有 `input` 设成 `width: 100%`，于是每行的复选框占满整整一行，名字 span 被压成零宽，12px 的文字变成一行一个字符。三行就变成读者看到的那些又高又空的盒子。

## 决定

- 只要预设设置开着，`PresetEntrySlot` 就渲染；`sessionId` 作为 session 作用域位置的必填属性。缺 id 的守卫、一次性告警标记和诊断探针全部删除。
- 建议对话框在 `ResourceCollection`（`view: 'list'`）里给每个候选渲染一张 `ResourceCard`：共用的名字行、可选的描述行、动作簇里的一个控件。控件是复选框而不是开关，因为建议是一次挑选，不是启用；卡片左侧的边条表示这一行是否保留，列表在自己的字段里滚动，长答案不会把对话框撑高。
- `e2e/presets.spec.ts` 钉住两件事：入口出现在输入框里并能打开管理器；桩住的答案渲染成一张紧凑卡片，勾选会翻转卡片状态并让创建按钮可用。

## 考虑过的替代方案

- **保留缺 session 的守卫，并用宿主的「当前会话」选择器兜底。** 否决：位置契约本来就带身份，第二个来源只是在为一个已经不存在的宿主形态写猜测路径。
- **只修 CSS 里的复选框宽度。** 否决，方向不允许：这一行是一个资源，仓库已经有一套资源卡片解剖，手写第二份列表正是设计规则要消除的重复。
- **候选行用开关。** 否决：开关说的是「现在就启用」，而建议只是读者在创建预设前勾选的提议。

## 后果

- 只要设置开着，入口在每次会话里都可见；将来某个宿主违反 session 作用域契约时会显式失败，而不是静默丢掉功能。
- 建议行与其他资源列表共享高度、边条和控制位置，对话框在长答案下仍保持有界高度。
- 测试用例用一个固定载荷回答唯一一次建议请求：模型调用是浏览器测试唯一无法真实完成的部分，返回的行才是测试判断的对象。
- 两篇仍活跃的功能笔记保留各自的决定，并加上交叉链接：[输入框入口的形状](../feature/2026-11-18-the-composer-entry-names-its-preset.zh.md)仍归它管，[推荐的勾选行](../feature/2026-11-20-a-recommendation-you-can-judge.zh.md)仍归它管「建议可编辑」这件事。这篇笔记负责入口的可见性与行的解剖。
