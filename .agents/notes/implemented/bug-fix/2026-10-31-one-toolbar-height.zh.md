# Agent Note：每个界面的工具栏同一高度

Status: implemented

## Problem

在 `market-dev` 实测：带筛选段的六个界面工具栏高 36px，**不带筛选段的两个**（系统提示词、钩子）只有 **33px**。高度来自最高的子元素——宿主的 SegmentedControl 是 36px，搜索框 33px。于是切换页签时列表会上下跳 3px，两个短界面的空状态也比邻居的卡片高 3px。

## Decision

- **工具栏行自己声明高度。** `.toolbar` 加 `min-height: 36px`（即宿主筛选控件的高度），这样没有筛选的条也保持同一行高。界面只渲染它拥有的控件，而行高不再取决于这些控件是什么。

## Alternatives considered

- **把搜索框做成 36px 高。** 否决：那是宿主的 `Input`，内容盒 22px、整块 33px，拉高会让文字在高盒子里偏上。
- **永远渲染一个筛选段，哪怕空的。** 已在筛选条重构中否决：只有一个页签的条等于什么都没说。
- **手工给短工具栏补 padding。** 否决：那是每个界面各写一个要维护的数字，而不是一条行规则。

## Consequences

- 每个页签的工具栏都是 36px，其下内容从同一偏移开始。
- 新界面不用做任何事就获得这个行高。

## Verification

- 在 `market-dev` 对九个页签实测：每个都是 36px（改前为 36/36/36/36/36/33/36/33/36）。
- `pnpm run check:css`、工具栏与列表测试、全量测试通过。
