# Agent Note：由建议生成的预设会存下它点名的那些行

Status: implemented

## Problem

报告原文是「预设建议后，点保存无法存储实际的预设数据」。建议回来了，带一个名字、一句理由和一份行清单；应用它也确实建了预设，文件里也有 id，可管理器随后把其中没有一行显示为开启。

这一个报告背后有三个缺陷。

- 建议路径存的是模型原样给出的 picks。管理器自己的开关维持着一种闭包：套件下面的行带着拥有它的套件（`resourceSelected` 只在两个 id 都在时才算这一行已选中），套件带着它下面的行。建议点了一个技能，就只存下那个技能，于是管理器读回来是「未选中」，运行时也不授予任何东西（`extensionResourceEnabled` 同样要求套件在场）。建议点了一个套件，就只存下套件，于是套件显示为开启，而它的内容是关闭的。
- 建议路径没有让名字唯一。手工路径的每个名字都过一遍 `uniquePresetName`，建议路径却把模型给的名字直接交给 `create`：名字已存在时就以 `preset-name-conflict` 失败——而这个失败无人看见，因为弹窗的 apply promise 没有 catch。建议就此丢失，而且没有任何提示。
- 可供挑选的行是有上限的（`AI_PRESET_LIMITS.candidates`，300），而客户端按清单顺序发送，于是超过上限的清单会丢掉尾巴：输出风格、指令文件以及靠后的套件，模型根本没被展示过。

## Decision

- **一个规范化函数回答两条路径。** `packages/market-ui/src/features/extension-presets/resource.ts` 里的 `canonicalPresetSelection(rows, base, changes)` 是唯一知道闭包的地方：套件下面的行带着套件，套件带着它下面的行，输出风格是单选，管理器切不动的行不进选择。管理器的 `patch()` 与建议路径都调用它，于是两者不会漂移。
- **建议路径经由它来点名。** 模型的 picks 变成空基底上的一组变更，结果就是管理器开关为同样这些行会建出的选择。
- **名字先变唯一，新预设靠「多了什么」来认。** create 之前先过 `uniquePresetName`；建成的预设按库里新出现的那个 id 定位，而不是按模型要的名字——那个名字可能已经为了腾出位置被改过。
- **被拒绝的保存会说出来。** 建议路径用 toast 报告。弹窗保持打开、答案仍在屏幕上，失败被点名，而不是消失在一个没人接的 rejection 里。
- **可供挑选的行按它们承载的东西排序。** `presetSuggestionCandidates` 先给套件和独立站得住的行，再给它们下面的行，然后按契约的上限裁剪。上限属于契约；顺序属于客户端，而顺序正是决定模型能看到哪些行的东西。

## Alternatives considered

- **在服务端规范化，放在 `create()` 里。** 否决：服务端拿到的是 id，不是行。它无从知道一个技能属于哪个套件，因此补不出闭包；闭包需要管理器渲染的那份清单。
- **照原样存下 picks，让读者自己修。** 否决：管理器只在闭包成立时才算一行已选中，所以那些 id 读回来永远是「什么都没有」。报告说的是保存存不下东西；存下一个读不回来的东西，正是缺陷本身。
- **把套件下面的行从可供挑选的行里去掉，让建议只点套件。** 否决：一个人点名要某个技能，要的就是那个技能。这些行仍然可点，套件由闭包替它们带上。
- **放宽一次建议可被提供的行数上限。** 否决：上限让请求和提示词保持小，它属于契约。决定什么能活下来的，是客户端给行排的顺序。
- **要求模型点名套件下面的行时也带上套件。** 否决：模型得学一条管理器本来就在执行的规则，而且它一旦忘了就还是错的。
- **把 create 被拒绝的失败交给弹窗自己的错误位。** 否决：弹窗只显示它自己那次建议调用的错误，而那不是这里能改的东西；toast 是唯一能在管理器之上报告的界面。

## Consequences

- 由建议生成的预设，在管理器里和运行时里都读回为它点名的那些行。
- 两条点名的路径产出同一个选择，这条规则由一个函数拥有。
- 当名字已被占用时，建议拿到的名字可能与模型写下的不同。
- 即使清单大于上限，模型看到的也是承载选择的那些行。
- 现在两条路径里输出风格都是单选，因为规则搬进了共享函数；见 [the preset row carries the prompt layer too](../feature/2026-11-01-the-preset-row-carries-the-prompt-layer.md)，本篇延续那篇的决定，而不是改写它。

## Verification

- `packages/market-ui/test/preset-selection-canonical.test.ts` 钉住闭包规则：点名的行带着它的套件，点名的套件带着它的行，独立行仍然独立，一次只有一个风格，管理器切不动的行不进选择。
- `packages/market-ui/test/preset-ai-suggestion.test.ts` 驱动管理器：建议点名一个套件下面的行，create 带上两个 id；管理器的开关把这一行读回为已选中；建议路径与开关路径为同一行产出相同的 id；已被占用的名字变成 `Research (2)`，编辑器打开的是新预设；被拒绝的保存会被报告出来，而不是凭空消失。
- `packages/market-bundle/test/integration/ai-preset-selection.test.ts` 检查运行时一侧：store 保留闭包，`captureExtensionSelection` 与 `extensionResourceEnabled` 授予建议点名的行，并拒绝「点了行却没点套件」的选择；超过上限的那些行，正是模型看不到的那些。
