# Agent Note：MCP 挂载的启动预算改为 30 秒

Status: implemented

## Problem

内置 MCP 桥接给每次连接尝试只留了十秒的启动超时：没有在这之前完成握手与首次 `tools/list` 的服务器就算不可达，挂载失败。这类服务器的工具始终不出现，owner 读到的现象是「模型找不到 MCP」——工具并没有缺失，是挂载从未完成。

对一台走公网的服务器来说，十秒很短：TLS 握手、一次 OAuth 发现往返和一份很大的工具清单都压在这个计时器上。插件的预算也比宿主对单次调用宽容度还紧——宿主的 MCP 客户端根本没有启动超时开关，单次工具调用可以跑 60 秒——于是桥接放弃了一台宿主自己还愿意等的服务器。owner 的绕法是把需要的那两台服务器手动调到 60000；默认值是其他所有服务器拿到的那个。

## Decision

- **默认启动预算是 30 秒。** `DEFAULT_STARTUP_TIMEOUT_MS` 为 30_000，两个读取方——解析后的挂载策略与桥接在连接时套用的兜底——都通过这个常量取值，所以决定只由一个数字承载。
- **预算按请求覆盖整条挂载路径。** initialize 请求与每一页 `tools/list` 各自以这个值为上限，所以一台握手及时、但列工具慢的服务器仍然能挂上。
- **30 秒是一个刻意的中间值。** 它足够覆盖公网服务器的 TLS 握手、OAuth 发现与工具清单；又足够短，让一台死掉的服务器干脆地失败而不是挂住。它仍低于 MCP SDK 自带的 60 秒请求默认值——未声明的服务器以前正落在这个默认值上，占着进程、传输与浏览器腿整整一分钟——也低于宿主 60 秒的单次调用容忍度，因此挂载一台服务器从不会被要求比「对一台已经答话过的服务器发一次调用」更紧的预算。
- **用户与套件的值仍然优先。** 解析顺序不变：用户覆盖值、套件声明、最后才是这个默认值。需要超过 30 秒的服务器依然自己声明 `startupTimeoutMs`；宿主兼容后端依然拒绝携带该声明的服务器，因为那个后端无法执行它。
- **重连预算不变。** 监督器的放弃按尝试次数计数，不按时钟计数：十次失败尝试，退避从 500ms 翻倍到 30s 上限，然后工具被注销。更长的一次尝试不改变这个次数，所以监督器依然会放弃、依然会注销工具。

## Supersession

这**部分**取代[设置与卡片复用宿主能力](../architecture/2026-09-13-settings-and-card-ride-the-host.zh.md)：那条记录的决策依然成立——每次连接尝试都受一个内建默认值约束，服务器可以声明自己的值，默认值在连接时于内置桥接内部解析——但它写下的十秒现在是三十秒。那个事实已在该记录中原地更新，决策本身没有被改写。

## Alternatives considered

- **与宿主的 60 秒工具调用超时完全对齐。** 否决：那个超时管的是对一台已经答话过的服务器的调用，而启动预算管的是一台还没证明自己会答话的服务器。挂载报失败前先沉默一分钟，就是让用户为一台永远不会起来的服务器等一分钟；桥接之所以自己设预算——干脆失败，而不是挂到 SDK 的默认超时——正是为了这一点，更短的预算更合适。
- **默认值保持十秒，让每台慢服务器自己声明超时。** 否决：需要更长时间的服务器大多是用户自己的，声明写在用户不编辑的清单里，而症状是挂载悄无声息地永不完成。
- **去掉内建默认值，改回继承 MCP SDK 的 60 秒。** 否决：那正是九月那条记录替换掉的行为。一台连不上的服务器会占着进程、传输与浏览器腿整整一分钟才失败，桥接也会失去它唯一能控制的那个预算。
- **提高重连预算来补偿。** 否决：放弃本来就是按次数计的，它照样会触发。提高尝试次数只会成倍拉长中断窗口，而不是给它设界；工具在放弃时照样被注销。
- **按传输方式给不同预算。** 否决：stdio 服务器在本地启动、毫秒级答话，公网 HTTP 服务器才要为距离付费。一个对慢场景宽容、对快场景无害的数字，比两个数字简单。

## Consequences

- 重连预算自身的算式没有变——十次尝试，退避依次是 500、1000、2000、4000、8000、16000，之后四次都是 30000，退避合计 151.5 秒——放弃点也没变：第十次失败尝试后照样注销工具。变的是它跨过的那段墙钟时间。立刻失败的服务器（例如连接被拒）仍然在约 151.5 秒后失去工具——人们心里那个两分半——这个数字没有变化；一直挂到预算耗尽的服务器每次尝试都要花满整个启动超时，所以它的工具现在能活约 451.5 秒（七分半），而不是约 251.5 秒。
- 一台死掉的服务器现在要 30 秒才判第一次挂载失败（以前 10 秒）。
- 需要 10 到 30 秒的服务器现在能挂上而不是失败——这正是重点：工具出现了，模型能调用它们。
- 编辑器里未设置启动超时的输入框以生效值为占位内容，所以现在显示 30000。没有 locale 文案、也没有面向用户的文档写出这个数字。
- OAuth 浏览器腿保留自己的五分钟预算，因此在浏览器里授权的人不会因为启动超时被缩短。

## Verification

- `packages/market-mcp/test/mcp-startup-budget.test.ts` 钉住默认值，以及让这个默认值站得住的那条关系：挂载预算低于 60 秒的工具调用超时。
- market-mcp 测试通过（6 个文件、42 个测试），market-bundle 的 MCP 测试通过（5 个文件、83 个测试）：解析后策略的默认值、server-config 模板与编辑器的占位内容都读作 30000。
