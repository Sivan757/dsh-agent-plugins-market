# Agent Note：没有落点的筛选不画

Status: implemented

## Problem

负责人问过筛选是否真的方便查询。在一个工作区里实测，有几个筛选取不到任何东西：技能面画着 全部 157 · 用户 0 · 套件 157 · 已禁用 88，连接器面画着一个空的「已禁用」。只能落到空清单的胶囊，看起来是筛选、用起来是死路；而「用户 0」紧挨着「套件 157」，也没有告诉读者任何他还不知道的事。

## Decision

- **没有落点的分支直接去掉。** `ResourceSurface` 只保留命中集非空的分支，于是这一行显示的是当前真的能查的东西。当前选中的分支无论计数都保留，避免选中项从指针下消失。
- **所有分支都被去掉时，整条筛选也不画。** 空面本来就会自我说明；只剩一个「全部 0」的页签，正是这个渲染器在别处拒绝画的装饰。
- **规则是结构性的，不是针对某份数据。** 分支仍然存在于各面板里，渲染器只是不画此刻不可能命中的那些。有用户技能的工作区会重新画出「用户」。

## Alternatives considered

- **保留 0 计数胶囊作为信息（「你没有用户技能」）。** 否决：面本身已经说明它有什么，而筛选是邀请点击；把人邀请到空清单，正是「方便查询」的反面。
- **把胶囊置灰而不是隐藏。** 否决：置灰仍然占位、仍然需要解释，而读者根本用不了这个分支。

## Consequences

- 筛选行只提供有去处的分支。
- 空面不显示任何筛选装饰。

## Verification

- 在 `market-dev` 实测：技能画 全部 157 · 套件 157 · 已禁用 88（「用户 0」消失），连接器画 全部 5 · 需处理 1（没有空的「已禁用」），而没有任何行的输出风格面完全不画筛选条。
- `client-extension-preset-v5.test.ts` 断言 0 计数胶囊不存在、其余分支仍能筛选；market-ui 套件与全量测试通过。
