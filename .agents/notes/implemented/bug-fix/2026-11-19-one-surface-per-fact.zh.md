# Agent Note: one action row, one progress surface, one acquisition

Status: implemented

## Problem

负责人逐个拍下 Agent Plugins 工作区的六个界面，每个都报「不和谐」：与插件其余部分不一致。六张里有五张是布局缺陷，第六张是它们背后的数据流缺陷。

| 界面 | 照片里看到的 | 测量 |
| --- | --- | --- |
| 用户技能的详情对话框 | 删除 停在 hero 那一行，紧挨路径与标签，离对话框底边很远 | 在 800x800 的对话框里，这个按钮占 651,188；对话框里唯一的另一个按钮是页头的关闭，在 1010,129 |
| 添加来源 | 添加对话框底部有一行转圈加一句步骤说明，而遮罩层已经在同一个对话框上说着同一件事 | 两处指示在描述同一次获取 |
| 添加来源 | 把 `https://github.com/shadcn-ui/ui` 粘贴两次，登记出两条来源 | 每一次被接受的添加都会追加一行记录并克隆一次 |
| MCP 新建对话框 | 表单停得离对话框自己的边很远，传输方式的控件读起来像一个空输入框里塞了一颗药丸 | 对话框横跨 252 到 1052，而字段止于 896；分段轨道宽 305，其中分段只有 207 |
| 钩子新建对话框 | 它的宽度是别的任何新建对话框都不用的，而且开头是一行只有它有、往里缩的起草行 | 宽 380px，而同门兄弟都是 800；起草字段从 496 起，下面的字段从 486 起 |
| LSP 新建对话框 | 同样是那条窄列，于是页脚的提交按钮站在它所提交的一切的右边 | 字段止于 896，页脚按钮在 1028 |

其中两行共用一个原因。来源是被获取之后再登记的，而没有任何地方检查同一次获取是否已经登记过，所以第二次添加写下了第二行记录、克隆出第二份 checkout，而读者分不出这两行。另一条是编辑器那条 620px 的列宽上限：它是按 640px 的 `md` 对话框量的，而预设管理器那个固定的设置框架会把在其中打开的每一个对话框都拉到 800px，于是这条上限让 156px 的对话框宽度空着，而页脚仍然横跨整个对话框。

钩子对话框那行起草控件，是唯一一处与已写下的立场相矛盾的：说明文档（[AI 辅助一页](../../../../docs/user/ai-assist.zh.md)）早就写着，钩子是人自己拥有的配置，编辑器不为他起草，而[演示走查那条记录](../feature/2026-11-04-the-demo-review-changed-four-things.zh.md)曾把表单与一个替它填表的模型配在一起。代码与自己的指南不一致，这次改动按指南的说法收尾。

## Decision

### 详情对话框只以一行操作收尾

详情正文只说事实、给文档看；对话框的动作站到页脚那一行上。插件拥有的每一个详情都照此办理：

| 详情                                           | 页脚这一行                                         |
| ---------------------------------------------- | -------------------------------------------------- |
| `ui/UserEntryDetail.tsx`                       | 删除（仅用户自建条目）· 完成                       |
| `ui/HookDetailModal.tsx`                       | 试运行（仅可运行的声明）· 关闭                     |
| `features/mcp/McpDetailModal.tsx`              | 删除连接器 · 复制诊断 · 重试连接 · 重新授权 · 关闭 |
| `features/lsp/LspStatusPanel.tsx`              | 复制诊断 · 重启服务 · 完成                         |
| `features/instructions/InstructionDetail.tsx`  | 删除 · 编辑 · 完成（本来如此）                     |
| `features/output-styles/OutputStylesPanel.tsx` | 编辑 · 删除 · 选用（本来如此）                     |
| `features/market/SuiteDetail.tsx`              | 安装 / 卸载（本来如此）                            |

`StatusBand` 去掉了 `action` 槽。状态带报告服务的状况，从不承载它的修复；两个调用方都把动作搬走之后，这个槽已经没有使用者。破坏性动作排在行首，免得挨着关闭；MCP 详情那一行是最长的五颗按钮，窄对话框靠共用页脚的换行来处理。

### 来源获取只由遮罩层报告

添加来源的对话框不再渲染任何进度行、转圈或步骤说明。遮罩层是插件唯一的进度面：它盖住当前对话框、把它标成 inert、说明有事情在跑。对话框保留自己的字段、页脚与位置。

因此删掉的：对话框里的进度块、`SourceProgressState`、轮询辅助 `startSourceProgressPolling`、客户端绑定 `fetchSourceProgress`，以及点名克隆步骤的四个文案键。失败经面板的 toast 到读者那里，那也是其他每一种变更失败落到的位置。

HTTP 路由保留：`MARKET_ROUTES.progress` 仍然作答，存储层仍为自身的 checkout 探测记录在途获取，`source-discovery.test.ts` 仍钉住那份状态。浏览器不再读它。

### 一个仓库就是一次获取

`SourceStore.add` 在任何克隆或下载开始之前，就拒绝状态里已有的获取。身份说的是这个来源做什么，不是它当初登记在哪个 id 下：

- 种类（git、archive、local），因为同一个地址换一种传输方式就是另一件事；
- git 来源用规范化后的地址（`canonicalGitUrl` 折叠 `git@host:owner/repo` 简写、`ssh:` / `git:`、结尾斜杠与 `.git` 后缀），本地来源用展开后的路径，压缩包来源用去掉首尾空白的地址；
- 分支，因为同一仓库的两个分支是两个来源，分支字段正是为此而设。

`SourceStore.update` 在补丁把某一行挪到另一行的获取上时，施加同一条规则。拒绝会带上 `code: 'source-duplicate'`，路由把它透传出来，客户端经 `clientErrorMessage` 把它变成一句本地文案 `sourceDuplicate`。

### 编辑器的列宽跟着它所在的对话框

`.editorBody` 不再设宽度上限。服务编辑器的字段现在取对话框给它的那一列，因此它们的左右边与对话框自己的页头、页脚对齐，而不是提前 156px 停下。`.seg` 增加了 `align-self: flex-start`，让手写的分段轨道按分段自己的宽度收起；被拉伸到字段列宽时，它读起来像个空输入框托着一颗药丸。

### 钩子表单和它的同门兄弟是同一个表单

`features/hooks/HookCreateModal.tsx` 从宿主的 `Modal` 换到 `DetailModal` 与共用的表单表，于是它落在与 MCP、LSP 编辑器同一个 800px 框架、同一行页脚上，字段几何也一致。意图字段与起草动作消失了，撑起它们的那条路由随之消失：`USER_HOOKS_ROUTES.draft`、`UserHookDraft`、`USER_HOOK_LIMITS.intentChars`、`createAiHookService` 模块（`application/ai-hook.ts`），以及客户端绑定 `draftUserHook`。对话框的说明文字现在讲清楚字段要填什么、保存会做什么。

## Alternatives considered

- **把 620px 那一列在框架里居中，而不是填满。** 否决：居中不与任何东西对齐。对话框的页头、页脚和滚动正文都从同一个 24px 内缩开始，居中的列会留下两道边距，而读者看到的是一页。
- **让编辑器对话框在设置框架里保留自己的 640px 宽度。** 否决：框架的存在就是为了让嵌套对话框在读者进出时不改变尺寸，把某一类豁免出去，恰好把它要消除的那种跳动请回来。而且它只能修好照片的一半：640px 下字段确实填满了对话框，但对话框就和旁边打开的详情不一致了。
- **重复添加时返回已有的来源。** 否决：静默空转会什么也不告诉读者，他已经有的那一行也就不会被提起；而一个要求了分支、种类或压缩包摘要的请求，如果那些与已有行不符，就会被用错误的来源回答。拒绝则把这个事实说出来。
- **只比较地址，把分支从身份里去掉。** 否决：分支字段会变成陷阱。读者加了 `main` 之后再要 `dev`，会被告诉仓库已经登记，第二个分支也就不可达了。
- **只去掉转圈，留下那句步骤说明。** 否决：那句话仍然把遮罩已经说过的事再说一遍，而且负责人要的是去掉这一条，不是让它的动画停下。留下它还意味着留下为它做轮询的定时器，而它带来的信息遮罩已经传达。
- **把 AI 起草藏在已经管着翻译与预设的那个设置开关后面。** 否决：指南写明钩子由人自己写，那么一条藏起来的起草路径就与产品自己的说法相矛盾。钩子就是三个字段，而模型的贡献是对其中两个的猜测。

## Consequences

- 详情正文不再带动作。想删一个用户条目的读者有两条路通向同一个确认：卡上的危险图标和对话框的页脚，而对话框这一条现在在底边，和它其余的动作在一起。
- MCP 详情的页脚在宽对话框上是五颗按钮。窄对话框会让这一行换行，共用页脚支持这一点，而这一行读起来是这个对话框的动作集，不是状态带旁边的一根工具条。
- 两个服务编辑器和一个详情块在搬进页脚行时失去了 28px 的页脚按钮；页脚统一尺寸是[页脚尺寸那条记录](../feature/2026-11-06-one-button-size-per-dialog-footer.md)的主题，而它的清单现在与出厂的实现一致。
- 800px 框架下的服务编辑器带 752px 的字段。这比表单表写就时的 620px 尺度要宽，这笔交换是故意的：一条页面边线比一个固定尺度更值。
- 正文会滚动的对话框不再因此缩短字段：[对话框外壳那条记录](2026-11-20-one-dialog-shell-and-one-radius-scale.zh.md)隐藏原生滚动条、在内容之上画一枚悬浮滑块，字段因此与页脚共享右边缘，滚动条出现时也不会挪动版面。
- [来源指南](../../../../docs/user/sources.zh.md)写明每次获取只登记一次、哪几种地址写法指同一个来源，因此拒绝的规则就写在读者添加来源的那一页上。
- 来源进度已经没有任何读者：路由、契约与存储层读取都已删除；以后想要步骤级进度的改动，必须自己引入读者。
