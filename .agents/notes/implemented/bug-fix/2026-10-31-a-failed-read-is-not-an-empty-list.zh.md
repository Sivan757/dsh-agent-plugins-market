# Agent Note：读取失败不等于列表为空

Status: implemented

## Problem

我故意把状态读取弄坏，看读者会得到什么。当 `/mcp-status` 返回 502 时，连接器面板显示：

1. **`MCP status failed: 502`**——中文面板里出现英文内部标签和裸 HTTP 码。
2. **没有匹配的连接器**——在「全部 0 / 需处理 0 / 已禁用 0」的筛选条下方，而实际上有五个连接器，只有读取失败了。读者完全可能由此以为自己 的连接器没了。

同样的两个缺陷适用于任何读失败的界面：每个 `getJson` 路由抛 `new Error('<label> failed: <status>')`，而每个列表在 payload 缺失时回落到「这里什么都没有」的文案。

## Decision

- **请求失败有了类型。** `RequestFailedError` 携带路由标签与状态码，`getJson` 抛它。`clientErrorMessage` 渲染一句本地化的话并带上状态码——宿主服务返回 502，读不到这一项。稍后重试，或在宿主日志里查看同一时刻的记录——于是告警说明了发生了什么、保留了读者唯一能转述的事实，并指出了下一步。
- **没读到不等于没有。** 连接器与语言引擎界面在列表区显示「读不到状态，稍后重试」，并且**不渲染筛选页签**，因为三个读作 0 的页签只是在重复同一个假事实。
- **有旧数据的失败刷新仍然照常渲染。** 这条规则只在「没有行且有错误」时生效；已有行时刷新失败继续显示旧行。

## Alternatives considered

- **保留原始报错、只加重试按钮。** 否决：重试本来就在旁边，缺的正是「说人话」的那一句。
- **用专门的错误面板替换列表。** 否决：列表上方的告警已经承载失败与重试，再加一层错误界面会把仍然可用的搜索与视图控件藏起来。
- **失败时干脆不显示空文案。** 否决：空着不写一行会被读成渲染 bug；一句中性的话说明状态未知，而不是空。

## Consequences

- 传输失败现在读作一句本地化的话，带状态码与下一步。
- 任何界面都不会因为「本该填满它的请求失败了」而声称集合为空。
- 这个类型错误是所有路由本就要经过的接缝，后续新界面自动继承。

## Verification

- 在 `market-dev` 里只让 `/mcp-status` 失败模拟：告警读作「宿主服务返回 502，读不到这一项…」，列表区读作「读不到状态，稍后重试」，工具栏不渲染筛选页签（实测：0 个页签、3 个工具子元素）。
- `packages/market-ui/test/client-api-timeout.test.ts` 断言带状态码的那句话取代了原始消息。
- `packages/market-ui/test/mcp-status-render.test.ts` 断言读失败时显示「读不到状态」而不是 `mcpEmpty`，且不渲染筛选页签。
- 四个类型检查、`check:refactor` 与全量测试通过。
