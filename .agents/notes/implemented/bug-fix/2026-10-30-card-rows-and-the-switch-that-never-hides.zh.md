# Agent Note：卡片的行是组件，开关不再隐身

Status: implemented

## Problem

合并后的资源渲染器只用槽位类拼出每张卡。`CardIdentity` 自带行，但描述、计数与来源行是以裸 `p` 与 `span` 发出的，没有网格区域。网格不会报错：它把没有定位的子元素自动排进第一个空位，也就是没有操作的卡片那个空的 act 列。因此在 760px 的预设弹窗里，描述坐进了名称旁边的操作列、标题被裁成首字母、开关压在描述上；计数与来源行落进了正文格。同一张卡只有在容器窄到单列分支时才画对，这就是这个缺陷看起来只属于某一个页面的原因。

同一个区域里还有两个缺陷。资源列没有受限高度，于是预设弹窗把最后一行裁掉而不是让它滚动。而窄容器分支里整簇操作连同启用开关一起脱离文档流、悬停才淡入，静止时读者看不出某个条目是否已启用。

## Decision

- **行是组件。** `CardBody`、`CardFoot`、`CardActions` 与 `CardIdentity` 一起落在 `ui/ResourceCard.tsx`，各自发出自己的区域类和 `data-card-row` 标记。页面写的是行，而不是信任一个字符串类名，测试因此可以断言句法。
- **任何宽度只有一套句法。** 身份行、两行正文、来源行、操作簇。窄容器分支沿用宽分支的 `'id act' / 'body body' / 'foot foot'` 模板，只改列数、间距与行高。
- **开关不再隐身。** 操作簇始终在文档流里，每个条目的启用状态不用悬停就能读到。次要图标保留 `revealOnHover`；名称在簇旁省略，全文留在身份行的提示里。原先用来盖住浮动簇压到文字上的不透明底板及其扩散阴影一并删除。
- **每个页面填同一套行。** 市场套件卡、MCP 状态卡与用户内容卡片用共享行替换各自手写的行 `div`，这套句法只留一种写法。
- **行高在任何宽度都随内容。** 宽分支固定的 122px 行会在单行描述下留下空条、并裁掉更高的卡；`grid-auto-rows: max-content` 让一行和该行最高的卡一样高。
- **高度由资源列自己持有。** `.surface` 是可裁剪的纵向 flex，`.results` 盒承载筛选面板，列表在其中滚动。裁掉外框的弹窗现在是滚动列表，而不是切掉最后一行。
- **来源行可以为空。** `CardCount` 增加 `first`，来源为空的卡片不会以分隔符开场。

## Alternatives considered

- **保留类名字符串、把行类写进文档。** 否决：这次改动的前提就是契约在调用点不可见，注释拦不住它。
- **让开关压过浮动簇。** 否决：子元素无法把淡出它的父级的透明度抬起来，而静止时仍可见的底板会盖住名称。
- **悬停簇里只让开关常显。** 同样否决：隐藏它的正是簇自身的透明度。
- **保留固定 122px 行、把描述裁得更狠。** 否决：那是靠藏内容去保一个 `max-content` 加栅格拉伸本来就能给的对齐。
- **只迁移共享渲染器。** 否决：三张手写卡会继续保留同一句法的第二种写法，而这正是本次要消掉的漂移。

## Consequences

- 名称比以前更早省略，因为身份行在任何断点都预留操作簇的宽度；全文由悬停提示承载。
- 同一网格行里的卡片与最高的卡同高，而不是固定 122px。
- 新增槽位就必须在共享模块里新增一行；页面无法私自加一个而不被句法测试拦下。
- [统一卡片句法](../feature/2026-09-14-workspace-card-anatomy-and-host-affordances.zh.md)与[卡片的实时交互](../feature/2026-09-16-workspace-live-card-affordances.zh.md)的盒模型、槽位与容器决策仍然有效；这里只取代窄分支里那套浮动、悬停才显形的操作簇。

## Verification

- 仓库外的预览夹具用真实 `ResourceSurface`、卡片样式与宿主设计令牌，在 760px 与 560px 下渲染六条预设式条目与系统提示词卡片。改动前描述在名称旁、开关压在描述上；改动后每张卡都是身份行、两行正文、来源行与常显开关。300px 高的帧证明列表在滚动而不是被裁掉。
- jsdom：句法测试断言行顺序、描述填正文行、开关收在操作簇末尾、来源填来源行；空条目不会渲染空行；对等测试比较两个页面的行清单。
- `vitest run packages/market-ui/test` 43 个文件 / 288 个测试通过；客户端类型检查干净；`check:css` 与 `check:single-renderer` 通过。
