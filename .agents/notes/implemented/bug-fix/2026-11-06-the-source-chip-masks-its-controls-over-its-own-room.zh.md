# Agent Note：来源胶囊用自带的余量遮住自己的控件

Status: implemented

## Problem

胶囊末尾的控件被重做成「名字永远不会压在它们下面」，代价是控件打开时胶囊会变宽：控件在胶囊内部占位，于是悬停一颗胶囊就宽出控件的宽度，后面的胶囊全被挤开。老板看过运行中的应用，要求恢复发布版的形式——控件在悬停时以一整块板盖在胶囊的尾缘，用内部遮罩（不透明的板加一圈羽化边缘的扩散阴影），而且胶囊不展开。

但发布版的形式有一个缺陷，不能跟着一起回来。发布版的样式里板不吃点击，而它的按钮吃：`opacity: 0` 不会取消命中测试，于是看不见的编辑与删除按钮是压在名字上的活靶子。本想点名字的那一下落在控件上，而那个看不见的删除按钮离「移除来源」的确认只差一次点击。

只把遮罩恢复回来也不够。运行中的应用里板宽 51px，而最短的来源名是 54px（`ponytail 1`），所以盖在尾缘的板几乎盖住了整个名字：读者只看到控件，看不到名字。

## Decision

- **控件又是发布版的那块板。** `.srcTabControls` 绝对定位盖在胶囊尾缘，不透明底加一圈羽化边缘的扩散阴影，悬停或键盘聚焦时显形（绝不用普通的 `:focus-within`）。板不在流内，所以胶囊打开时不会变宽。
- **名字止于板之前，而余量在胶囊上，不在标签上。** 带控件的胶囊在自己的尾部内边距里为板预留所需的空间：`.srcTab:has(.srcTabControls)` 拿到 `padding-right: calc(10px + var(--src-tab-controls-room))`，这个余量是 **47px**——板盖住内容盒的 41px（板宽 51px，贴着内边距盒摆放），遮罩的羽化再往左够 6px。于是板盖住的是胶囊自己的内边距，任何长度的名字都不会有一个字母落在它下面。没有控件的胶囊保持左右对称的 10px。
- **余量不能放在标签上，这正是要点。** 标签承担胶囊 220px 的文字预算；给它加内边距会让最长的名字比发布版早 47px 省略，而发布版里它们是完整显示的。把余量放在胶囊的内边距里，标签的预算原封不动，于是最长的名字依然完整显示。
- **看不见的控件是惰性的。** 板仍然 `pointer-events: none`，按钮在板打开之前也是 `pointer-events: none`，打开时才把指针事件还给按钮。收起状态的控件永远抢不走本该给名字的点击；显形后的控件站在自己的余量里，而不是压在名字上。
- **整颗胶囊都是选来源的靶子。** 胶囊的根节点带着选中处理，名字按钮阻止冒泡，于是来源恰好被选中一次，名字也仍然是给键盘和辅助技术用的真控件。
- **胶囊仍然用读者认得的名字称呼来源。** 那条决策记在[限定来源名](../feature/2026-11-05-qualified-source-name.zh.md)里；这次改动保留它，不在此重述。

## Supersession

这构成对[来源胶囊把名字留在自己的控件之外](../bug-fix/2026-11-05-the-source-chip-keeps-its-name-clear.zh.md)的取代：它的决策——控件在胶囊内部占位、打开时胶囊变宽——被遮罩板加预留余量替换。那条记录的其他事实依然成立：胶囊根节点负责选中、名字按钮阻止冒泡、限定名领在胶囊前面。

它同时**部分**取代[胶囊按 id 宽度排布](../feature/2026-10-30-source-chips-hug-their-ids.zh.md)：胶囊仍然有多宽的标签就多宽、同一个 220px 上限，但带控件的胶囊还要加上这些控件需要的余量，因此同样两行里能看到的来源比那条记录里量的少。折叠、渐隐、浮层展开与选后收起都没有动。

## Alternatives considered

- **保留变宽。** 否决：老板要求发布版的形式，而读者一指就变宽的胶囊会把它后面的每一颗都挤开。
- **把发布版的板盖在名字上，认了尾巴被盖住。** 否决：板盖住 54px 名字里的 51px，最短的那颗胶囊整个名字都没了；所有短于约 100px 的名字都会丢掉尾巴。
- **把余量放在标签的内边距里。** 否决：标签承担 220px 的文字预算，余量就从名字自己的宽度里出，三个最长的名字比发布版早 47px 省略，而发布版里它们是完整显示的。
- **把不透明遮罩换成半透明的veil，让名字透出来。** 否决：两个图形字仍然压在名字上，名字的尾巴仍然在它们下面消失，点击仍然落在控件上。
- **量出名字长度，只在板会吞掉名字时才预留余量。** 否决：每颗胶囊一个 ResizeObserver，宽度在首帧之后还会变，一条来源条里出现两种胶囊形状。
- **把板做窄。** 否决：板的宽度就是遮罩的样子，而且再窄也窄不过那两个图形字。
- **把控件挂到胶囊外面。** 否决：它们会盖住下一颗胶囊，并吃掉它的点击。

## Consequences

- 控件打开时胶囊不变尺寸：最短的那颗悬停前后都是 123px，实测。
- 任何长度的名字都完整可读、也可点击，控件站在自己的余量里：运行中最短的名字（54px）结束在板开始前 7px。
- 控件不可见时仍然是惰性的，所以看不见的控件永远抢不走点击。
- 带控件的胶囊比它的名字宽出一个余量，因此同样两行里能放的来源比[胶囊按 id 宽度排布](../feature/2026-10-30-source-chips-hug-their-ids.zh.md)那次量的少。
- 最长的名字仍然完整显示，和发布版一样：余量出在胶囊的内边距里，而不是标签的文字预算里。

## Verification

- 在 `market-demo` profile（link 本仓库、用构建出的客户端包）实测，悬停最短的胶囊 `ponytail 1`：
  - 名字宽 54px，板宽 51px；
  - 悬停前胶囊宽 123px，悬停时仍宽 123px——不变宽；
  - 板的左缘在名字右缘右侧 7px，名字没有一个字母在它下面；两个按钮位于 1241-1256 与 1262-1273，都在名字的框（1191-1245）之外；
  - 板收起时按钮是 `pointer-events: none`，打开时是 `pointer-events: auto`；
  - 点名字会选中来源（胶囊变成选中态并移到 `全部来源` 旁边），也不会弹出任何确认框。
- 每颗带控件的胶囊与板之间至少留出 7px；来源条的 19 颗胶囊占 8 行。
- 最长的名字完整显示：`claude-code-plugins-plus-skills 438` 的字迹宽 207px，`label.scrollWidth === label.clientWidth`（207），没有被省略；胶囊宽 276px，比它的名字宽出的 47px 与发布版一样。
- `packages/market-ui/test/source-chip-legibility.test.ts` 钉住样式表的约定（板又是那块遮罩板、按钮在打开前惰性、显形用 `:focus-visible` 且绝不用 `:focus-within`、余量在胶囊的内边距而不在标签上、余量至少 47px）与 DOM 的约定（名字不在控件里面、点名字只选中一次、点胶囊自己的区域也选中、点控件不会选中来源）。
