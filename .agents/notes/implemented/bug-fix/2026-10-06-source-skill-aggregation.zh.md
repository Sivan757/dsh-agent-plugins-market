# Agent Note: 聚合未声明插件的纯技能源

Status: implemented

## 问题

[jeecgboot/skills](https://github.com/jeecgboot/skills) 这类仓库包含多个独立技能目录，但没有插件声明。每个技能一张卡片会把资源边界误当成安装边界。

## 决策

[根目录发现](../../../../src/catalog/scan-resolvers.ts)将通过校验、未声明插件的纯技能目录聚合为一个源级套件。市场条目、显式插件根目录和带有其它运行面的目录保留各自身份。已经以 checkout 根目录解析的套件保持不变。

聚合套件使用按源限定的保留 ID `@skills`。经过清理的子目录 ID 不会与其冲突，因此单个技能的安装不会静默启用其它技能。显示名称来自 checkout 目录名。

每个技能保留原始文件和资源目录。同名技能保留首先发现的资源。无效技能继续被排除并给出诊断。

## 考虑过的替代方案

**只聚合界面卡片。** 安装和详情查询仍会分散在独立套件上。可安装单元必须由 catalog 统一定义。

**以 checkout 目录名作为 ID。** 同名子目录可能已经安装并启用。复用该 ID 会授权原本未选中的其它技能。

**从 checkout 根重新扫描所有组件。** 这会改变命令相对路径，并纳入无关的根目录组件。复用已校验技能，让非技能根目录保持独立。

**新增解析器或修改宿主。** 现有套件发现已经提供校验后的技能和资源路径。本次改动不需要新增依赖或宿主能力。

## 影响

用户需要单独安装聚合套件。现有单技能安装记录保持不变，不授权聚合套件。包含其它运行面的集合仍显示独立卡片，因为其相对路径依赖原始根目录。

## 测试

[聚合测试](../../../../tests/skill-source-aggregation.test.ts)覆盖用户和项目发现、旧 ID 冲突、同名去重、诊断、安装、重新加载及运行时资源路径。八个专项测试文件的 164 项测试通过，仓库重构门禁也通过。

在 macOS 上，`jeecgboot/skills` 的 `12760b936b0a083ce70905021ea82149f36537d4` 真实 checkout 产出一个套件、14 个技能，无诊断。上游两个文件使用小写 `skill.md`，因此区分大小写的文件系统可能得到不同数量。本次改动保留现有文件名处理行为。
