# Agent Note：一种读取失败呈现，以及和面板对齐的预设管理器

Status: implemented

## Problem

负责人一次指出三处不一致，其中两处各是一个缺陷，第三处其实是两个。

**读取失败在每个界面长得都不一样。** 连接器与语言引擎画一行红字加一个 ghost 按钮的重试；系统提示词画错误行（原始消息一条、payload 报告的错又一条）；输出风格加了一个标题前缀；钩子用的是 `role="status"` 而不是 `role="alert"`；市场弹一个会消失的 toast、列表却空着；用户面板干脆什么都不显示，只在列表区说明「没有数据」。首次读取就没回来时，两个界面又是第三种形状（标题塞在空占位里），而只有两个界面在列表里说「读不到状态」。

**预设管理器不像设置页面。** 它是模态，所以没有设置页的页签行；但它也没有副标题，读取失败藏在了一个下拉菜单的菜单项里，状态行是自己写的 `inlineStatus`。

## Decision

- **一个失败带组件。** `ui/panel.tsx` 的 `ReadFailed` 输出 `role="alert"`、本地化原因，旁边是重试；样式只有 `panel.module.css` 里一条规则。每个会读取的界面都用它：连接器、语言引擎、系统提示词、输出风格、钩子、技能/快捷指令/专家，以及市场（它的 toast 改成常驻的一行加重试）。
- **一条占位规则。** 读取失败没有行，因为什么都没读到，所以列表说 `statusUnreadable`，而不是它自己的「这里没有」文案。从没拿到 payload 的界面画同一个带与同一个占位，不再自创形状。
- **重试文案共享。** `mcpRetry` 改名 `readRetry`，因为现在每个界面都用这个词。
- **预设管理器获得面板页头。** 它带上每个设置页面开头那行副标题（「每个预设保存一组启停选择，选中的那个用于本会话。」），读取失败时画共享的带，而不是把失败藏进菜单。

## Alternatives considered

- **市场继续用 toast。** 否决：会过期的 toast 留下一个空市场和零解释，正是这一轮要去掉的缺陷。
- **保留各界面自己的措辞、只统一样式。** 否决于「标题 + 原始消息」那一类：读者需要的是原因，而页头已经说明他在哪个界面。
- **把预设管理器重做成设置分区。** 暂时否决：它属于会话、从输入框上方打开，因此仍是模态；它缺的是面板页头行与共享失败行，不是页签行。

## Consequences

- 失败在每个界面上读起来一样：一行、一个颜色、原因、重试。
- 读失败的界面不再声称自己的集合为空，任何界面都不会。
- 预设管理器会解释自己，并在其它面板的位置报告失败。
