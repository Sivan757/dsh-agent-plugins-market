# Agent Note: Schema 组件资源与真实仓库覆盖

Status: implemented

## Problem

多布局仓库扫描通过，可能只是高优先级方言生效。清单声明其它命令、hooks 或服务路径时，计数仍来自约定目录。Kimi Code 的主清单与运行时指令虽已写入 schema，却未被消费。

## Decision

文件/目录/内联组件一次性归一化为套件资源，运行时消费者与详情投影共享它们。没有资源表的旧式/项目套件保留默认路径；显式为空或无效的组件不能复活默认目录。Kimi 启动/系统指令使用已有的 Agent 作用域提示 API。配置读取检查 realpath 归属并诊断无效声明。

固定提交号的 README 仓库快照包含原文、哈希与许可证。测试扫描原始目录和每个套件根的单方言变体，验证真实 schema 并运行组件消费者。扫描器直接报告实际产出结果的 marketplace。见[审计表](../../../../docs/layout-coverage.zh.md)。

## Alternatives considered

**只验证 schema 或非空扫描结果**无法证明实际读取的方言与资源。**复制组件到运行时约定目录**会破坏源文件归属。**每个消费者分别解析路径**会导致发现、执行和编辑不一致。

## Consequences

快照增加约 2 MB 测试数据，但回归无需网络。测试不执行上游不受信任脚本，也不认证所有厂商原生运行时行为。[布局注册表决策](2026-09-09-layout-registry.zh.md)被部分扩展：来源/身份/作用域决策保留，现在还消费声明式组件文件与 Kimi 指令。[报告流程](../process/2026-09-08-compatibility-report.zh.md)继续负责来源获取和报告，本记录负责隔离测试与归一化资源契约。
