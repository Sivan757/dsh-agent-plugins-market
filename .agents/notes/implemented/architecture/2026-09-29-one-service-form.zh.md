# Agent Note: One form for a service, created or edited

Status: implemented

## Problem

MCP 与 LSP 的新建弹窗各自搭了一套外壳：自己持有文档、名称、有效性与错误的状态，自己的底栏，以及自己那次带 `createMode: true` 的 `ServerConfigEditor` 调用。编辑弹窗挂的是 `ServerConfigDetail`。同一张表单的两种写法在三处走散了。

**字段分组不同。** `createMode` 把参数与环境变量从主体移进了**高级设置**折叠区，于是新建时看到的表单比同一个服务存在之后短，而编辑表单的主体一直带着这两个字段。

**文档形状不同。** 编辑操作的是规范给服务的那个文档（`mcpServers` 加本客户端的命名空间），定义从中读回。新建却用同一个助手函数去写一个当时还不存在的声明键，于是第一次表单编辑就把定义改写成 `{"mcpServers":{"":{…}}}`：JSON 视图在用户眼前变了形状，新增接口把这个 wrapper 当服务定义存了下去。

**每处改动有两个家。** 名称字段、空文档、新建动作与字段错误各写了两遍，一个弹窗一遍。

## Decision

**一个组件同时服务两处。** `ServerConfigDetail` 增加 `create` 模式：不读取，名称成为表单里的一个字段，起始文本是该 kind 的空文档，保存时用输入的名称加定义调用新增接口。两个新建弹窗（`McpAddModal`、`LspAddModal`）只剩外壳——标题、宽度、高度、底栏那句「创建后生效」——围绕这一张表单；`ServerConfigEditor` 去掉 `createMode`，一个服务的字段永远按同一种方式分组。

**没有声明键的服务，文档就是定义本身。** `server-form.ts` 里空 `key` 表示这个服务还不存在：`parseServerDocument` 把整条记录读成定义，`composeServerDocument` 原样写回定义、不加 wrapper，于是新建表单与它的 JSON 视图描述的是新增接口存下的同一个对象。

**高级设置折叠区只属于表单视图。** 它的输入是文档与策略本来就有的座位的视图，而 JSON 视图展示整份文档，因此折叠区只在表单视图渲染。它的超时草稿也不再阻塞从 JSON 视图发起的保存——那里它被隐藏，拒绝保存会没有任何可见理由；切回表单视图时校验重新生效。

## Alternatives considered

**保留两套外壳、手工对齐。** 这是最省的改法，也正是这次走散的来源。否决：字段、空文档、名称字段与新建动作仍要写两遍，下一次改动只会落在其中一处。

**抽出一个纯展示表单，保留两个容器。** 一个只接 text、onChange 与 nameField、不碰数据的 `ServerConfigForm` 能把共享布局与两条流程分开。否决：新建流程真正的差别**就在数据访问**——文档从哪来、往哪去——这样拆只会把这个差别搬进第二个容器，而它照样要重复同一段标记。

**新建继续写 wrapper，让新增接口学会拆它。** 接口改为从 `mcpServers[<name>]` 里读定义。否决：新增调用本来就把名称作为自己的参数，wrapper 不承载任何信息；而一个接受两种文档形状的接口，比一份「写的是什么就是什么」的文档更难保持诚实。

**新建时也显示两个超时行。** 它们需要有地方可存：新增接口存的是定义，而本客户端的策略存在自己按服务分的存储里，于是这两个字段会静默丢掉用户输入的内容。这两行在服务存在之后才出现。

## Consequences

- 新服务与已有服务显示同一张表单、同一种次序；新建多一个名称字段，因为声明键来自它。
- 新建表单从定义本身开始，它的表单视图与 JSON 视图描述同一个对象，新增接口永远不会收到 wrapper。
- 超时是编辑有、新建无法有的唯一一块：新增接口存定义，没有座位的值就不提供。
- LSP 新建弹窗失去自己的状态、编辑器调用与底栏按钮；两个面板现在打开的弹窗只差文案，以及表单投进底栏的那个动作。

## Testing

- `tests/client-server-config-policy.test.ts` —— 新建弹窗显示编辑弹窗的字段、不发起读取、以名称与可用文档作为新建动作的门槛，并把 `{ type: 'stdio', command: … }` 挂在输入的名称下提交。
- `tests/client-detail-editors.test.ts` —— 没有声明键的编辑器编辑定义本身，绝不组出空键 wrapper；高级设置折叠区只在表单视图渲染。
- 编辑流程的保存载荷、策略往返与表单 / JSON 往返沿用既有覆盖，未改动。
