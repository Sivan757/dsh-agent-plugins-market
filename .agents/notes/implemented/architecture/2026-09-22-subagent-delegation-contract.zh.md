# Agent Note: 委派约定随角色目录一起发布

Status: implemented

## Problem

注入目录原来把角色名单和调用 `subagent_run` 的机制塞在同一条消息里，对「拿到结果之后怎么办」一个字都没写。目录消息是动态的：角色集合一变就重新发布，消息离开可见范围就从提示里消失，压缩隐藏它之后还会补发，因此它不是存放操作规则的稳定位置。

对这台机器会话日志的调查（598 份日志，按子会话标识去重）找到 393 次唯一委派：351 次走宿主的 `subagent`，29 次走 `subagent_run`（分布在 6 个会话），13 次走 `subagent_fork`。每次 `subagent_run` 调用都成功，29 次里有 28 次的提示词本来就是含路径与预期产出的完整交底，因此交底质量并非失守之处。调查暴露的是说明从未覆盖的部分：

- 有一次父代理在子代理还没写出任何内容时，就读取并呈现了一份早于本次委派的 34 行文件，交付后结束本轮；结算通知是在它下一轮进行到一半时注入的。目录缺少的规则正是：结算通知到达之前，不得交付任何依赖子代理的产物。
- 父代理多次通过自己核对文件推翻子代理的断言：一处成本估算错了一个量级，一处评审推断被历史提交证伪，一处凭据意见不成立。
- 两个子代理在收尾答复里描述了自己的配置，两份描述都是错的；父代理只能去读子代理的会话日志，才确认角色指令确实装入了。子代理看不到自己的角色指令是如何装入的。
- 唯一一次并行 21 个角色子代理的会话里出现三处协作缺陷：一个子代理的 shell 默认目录落在主检出而不是被指定的工作树；一个子代理在自己负责范围之外留下未跟踪文件；一个子代理越界改了别的代理负责的文件，需要追加指令纠正。
- 运行期间向父代理提问的子代理从未得到回答：调查里 4 条这样的请求，没有一条在子代理运行期间被回复，每个子代理都自行判断兜底。运行时的回报指引会要求子代理在结束前回报，58% 的已结算子代理确实先给父代理发过消息，但没有任何地方写明「运行期间的提问不会被回答」。

角色行还带上了一条模型不会据此行动的配置路由，变更摘要把模型从来不读的标题字段也算在内，于是只改显示标题就会重新发布整份目录。

## Decision

目录把角色名单和操作约定一起发布，组织方式与 Claude Code 的子代理提示词一致，分三节：使用说明、提示词的写法、不该使用角色子代理的场景。约定随它所约束的名称一起到达，完整替换会重新声明它，而不是让模型去推断上一版。

文本由 `src/runtime/subagent-catalog.ts` 的模块常量构成，经持久化 `subagent-catalog` 来源注入。它固定为英文，从不查询宿主翻译器，因此约定不会随操作者的界面语言变化；`src/runtime/host-locale.ts` 现在只保留给人读的界面文案。角色行采用宿主技能目录的反引号形式 ``- `名称`: 描述``，一行给出可调用名称与说明何时使用它的描述。配置路由不再进入模型可见的正文，仍保留在持久化条目中用于执行与变更检测。

宿主的通用委派工具只在需要时由工具描述点名，不在目录里被仲裁：每个工具自己说明后台行为、参数与限制，因此目录既不重复它们的清单，也不重复它们的选择顺序。

工具名为 `subagent_role`，除第一个参数外参数面与宿主的 `subagent` 一致：第一个参数 `agent` 指定目录角色，宿主对应位置是展示用的 `description`；`prompt`、`provider`、`model`、`reasoning_effort`、`run_in_background` 沿用宿主的名称与语义。调用侧给出的 `provider` + `model` 覆盖卡片路由，并从所选模型的默认思考强度起步；调用侧不给路由时使用卡片路由；两者都没有时子代理继承父代理路由。省略 `run_in_background` 时经 `startContinuable` 返回 `{ kind: 'continuable', subagentId }`；传 `true` 时经 `ctx.get('jobs')` 把同一个子代理注册到宿主 jobs 注册表并返回 `{ kind: 'background', jobId }` 供 `job_output` 与 `job_kill` 使用；传 `false` 时经宿主的一次性 `start` 运行一次并返回 `{ kind: 'foreground', runId, output }`。没有注册表服务调用方时，任务通道会明确报错并点名需要加载的两个包，不会静默降级到别的通道。

说明覆盖：准确名称规则；子代理需要的交底；运行期间的提问不会被回答，因此交底要一次说清，子代理也应自行决断并在报告里写明缺口；父代理要把等待时间用来推进独立工作；通知前不得预测；答复按报告对待；不得重复子代理已经在做的工作；以及并行子代理各自的工作树与文件范围。`src/runtime/agent-role-router.ts` 的工具描述保持简短，只承载目录不在视野时模型也需要的信息：子代理是什么；调用立即返回 ID、不等待结果；子代理通常运行数分钟，父代理应继续干活；结算通知到达之前不得交付任何依赖该答复的产物；通知到达后要对照文件核对并把结果转述给用户；以及没有匹配角色时改走通用委派通道。

变更检测覆盖名称、持久化角色身份、描述与配置的路由。角色标题是从不进入模型的持久化身份信息，因此不再计入摘要：只改标题不会让已发布的目录失准。

对同一语料的交互调查（598 份日志，同样去重）重建了父代理的真实做法：157 个委派回合里 147 个在启动后继续调用工具而不是等待；93 个回合并行发起两个以上子代理；377 条结算通知里 364 条落在父代理回合进行中，没有一条被搁置。子代理会自己回报——58% 的已结算子代理在结束前给父代理发过消息——父代理很少中断，也从不回答运行中子代理的提问。因此说明把工作推向等待期，并把结算通知当作结果可用的起点；它补上的两处遗漏正是「运行期间提问无人回答」与「fork 在嵌套父代理下的行为」。

## Alternatives considered

**操作说明只放在工具描述里。** 否决：那样目录消息会单独到达，模型看到一串角色名单，却在工具描述不在视野时读不到约束它们的规则。

**把角色名单移进工具描述。** 做不到：`defineTool` 在注册时固定描述，而角色会在会话运行期间变化，这正是目录必须是持久注入消息的原因。

**什么都不注入，全部交给工具描述。** 否决：模型就无从知道存在哪些角色，而角色名称是猜不出来的。

**继续在目录里发布委派通道清单与选择顺序。** 否决：宿主的每个委派工具已经说明自己的后台行为、参数与限制，目录等于维护另一份别人包的合同。它只保留自己才能说清的那条规则——没有匹配角色时改用通用通道，而不是名称相近的角色。

**摘要继续覆盖条目的每个字段。** 否决：只因为显示标题变了就重发完整目录，花掉一条消息和一次完整替换，却什么新信息都没说。

**为没有角色匹配的工作另造一个通用子代理。** 否决：宿主已经自带 `subagent` 与 `subagent_fork`，调查实测 `subagent` 承接 351 次委派而 `subagent_run` 只有 29 次。在说明里点名宿主工具，比再造一个启动器更省。

**通过 `prompt` 参数限制子代理再委派。** 由负责人否决：深度上限归宿主执行，把每次交底都变成一段关于子代理自身工具的提醒，等于让父代理为运行环境已经握住的规则分心。

**把目录文案留在宿主语言词典里。** 否决：随界面语言变化的约定无法一次性推导，而宿主自己的工具描述都是英文，固定英文让目录与它们读作同一份文本。

## Consequences

- 目录消息承载角色名单加操作约定，注入成本更高，而且每次替换都会重新声明约定。
- 约定出现在模型正考虑委派时已经在看的位置，替换也不会把名称与规则分开。
- 换来这份长度的是简短的工具描述：机制与通用通道的退路留在每一次请求中，说明随名称一起到达。
- 删掉通道清单后，目录不再依赖另一个包的工具集与参数名；代价是不再在一处点名宿主的通用通道，而各工具自己的描述已经覆盖这一点。
- 文案固定为英文，让约定成为单一产物，角色目录也就从宿主语言词典里彻底消失。
- 上面这些实测行为现在都有了明确指令，其中两条是运行时回报指引也没有的：运行期间的提问不会被回答；`subagent_fork` 在嵌套父代理下等于从零开始。模型是否遵守是另一个问题；测试固定的是措辞，不是行为。
- 调查自身的限制也界定了这条决策：它记录的是工具流量，不是上下文占用与费用，因此能证明父代理交付过陈旧产物，不能证明委派节省了多少 token。去重后 393 次委派里，29 次角色调用仍只落在 6 个会话，按角色统计的比例仍属个例。
- 只改角色卡标题不再重新发布目录。
- 没有匹配角色的任务不再被整体劝离委派：目录说明改用通用通道，工具描述也点名了通用退路。

## Testing

`tests/subagent-catalog.test.ts` 在真实的宿主会话与工具注册表上断言：角色行按反引号形式转义渲染，一行只有名称与描述、不含路由；描述或路由变化会重新发布，只改标题不会；同一文本在不同宿主 locale 下逐字节相同；三节说明与运行期间提问规则都在，被删除的通道清单不再出现。`tests/host-locale.test.ts` 断言界面文案在两种语言下都能翻译，并断言模型可见的角色目录已不属于该词典。`tests/agent-role-router.test.ts` 断言注册的 `subagent_role` 参数面、调用路由优先于卡片路由、可继续通道的请求形状、任务通道的注册与取消、缺少注册表时的明确报错，以及前台路径的返回与释放。
