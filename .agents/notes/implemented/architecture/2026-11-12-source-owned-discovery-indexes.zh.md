# Agent Note: 来源拥有发现索引，运行时按安装集合读取

Status: implemented

## Problem

目录发现与安装策略的变化频率不同。来源 checkout 在获取、刷新或编辑内容时变化；安装或启用套件只改变策略。按维度缓存发现结果，却让这两类变化承担相同的成本与生命周期。保温定时器会在无人需要新内容时重复遍历，而运行时准备仍可能经套件声明和清单查询读取完整市场。

由此产生的成本随全部已配置来源的规模增长，而非随会话能使用的已安装资源增长。延长 TTL 只能推迟工作，到期或重启后仍需同样的冷扫描。

## Decision

每个来源拥有自己的发现结果。[ADR](../../../../docs/developer/decisions/2026-11-12-source-indexed-catalog.md)定义读取与失效规则。`SourceIndexStore` 在 `<dataRoot>/catalog-index/` 下保存带版本且经过 schema 校验的来源记录。托管发现结果由市场、已安装和已启用投影共享；可变用户来源的记录保存路由提示，不保存缓存声明。安装状态继续保存在原状态文档中，在发现之后应用。

托管 Git 来源在索引载入进程时校验配置、checkout 与 HEAD。托管压缩包和 tarball 回退使用配置的 checkout，并在显式获取内容时失效；配置了压缩包摘要时，摘要参与身份校验。这些索引跨重启复用。本地、收编和项目树采用由读取触发且有界的内存新鲜度，因为其所有者可以不经插件操作而编辑文件。用户维度默认窗口为 30 秒，项目维度为 5 秒；项目 TTL 为零时逐次观察项目发现结果。发现读取不会安排保温定时器。

本地与收编来源持久保存套件身份与根目录、选中的 marketplace 路径和条目索引，以及受支持根路由候选的内容签名，不保存可执行声明。新的已安装读取重新打开选中的 marketplace 条目，以 `marketplaceEntryHint` 调用 `readSuite`，重放完整发现所用的组件解析规则。内联 LSP 等组件声明从当前条目读取，不只根据套件目录重建。

读取器核对真实根目录仍位于 checkout 内，并确认选中条目仍通过本地路由包含绑定根。签名变化、条目或根目录缺失、身份无法复现时，回退到完整 resolver。签名只覆盖受支持的有限根清单与目录索引候选，包括共享的 `marketplace.json`，因此即使旧目录仍存在，也能观察到同 id 改路由与条目移除。浏览市场解析完整来源，项目发现不持久保存声明。

发现内存表超过 64 个条目时淘汰最久未使用的条目。路由提示表单独限制为 64 个来源。可变来源将过期时间交给每个派生快照，因此请求另一种投影不能延长新鲜度。已安装快照在可复用期间保持对象身份，从而保留面板行缓存。追加策略诊断前先复制扫描说明。

`readInstalledCatalog` 与 `installedOverview` 服务运行时声明和清单。MCP 与 LSP 的仅已安装查询使用相同的来源选择。全局停用的已安装套件仍作为会话显式选择的候选；`enabledUserSuites` 应用全局启用状态，并保留用户直接声明的 MCP 与 hooks。浏览市场时，才按需发现全部已配置来源。没有可用索引或路由提示时，某来源未命中仍需发现该来源内的全部套件。

来源变更在修改 checkout 文件前持久化受影响索引的失效状态，阻塞这些来源的读取，并在释放读取者前重建发现结果。代次防止旧扫描重新填充内存状态；同源写入顺序防止较早的原子替换覆盖较晚的失效记录。变更失败后，等待中的读取者从已失效内容重新读取。目录销毁在存储清理前等待读取和索引写入完成。

JSON 无效、schema 不受支持或身份不匹配的索引会重建。checkout 缺失时不提供缓存中的运行时声明。其他索引 I/O 错误使读取失败。当前来源中找不到的已安装套件通过 `scanNotes` 报告，其安装元数据保留。新发现的替代套件不会被静默安装，远程引用仍不能挂载到运行时。

[实测读取成本记录](../performance/2026-10-26-read-costs.zh.md)继续持有概览请求合并、行缓存节拍、严格解析、项目读取器共享及隐藏窗口轮询的决策。本决策取代其中每次可见轮询都必须遍历完整发现结果的前提。行级文件检查仍保留已有文档编辑的可见性。

## Alternatives considered

**保留按维度的 TTL 扫描并延长 TTL。** 更长的窗口减少扫描频率，却保留重复全量扫描、到期延迟，以及对只有插件会修改的托管来源也施加的陈旧折衷。按来源复用才能遵循实际内容归属。

**递归计算每个来源的指纹。** 可变树的正确内容戳必须观察嵌套文件编辑，目录 mtime 无法做到。递归打戳会重复大部分扫描成本。托管 HEAD 在索引载入时校验，成本较低；可变树保留有界的按需发现。

**持久保存可变来源的声明。** 即使目录未变化，复用保存的声明仍会漏掉外部编辑。持久保存目录与清单条目位置可以缩小工作范围，同时在新读取中解析当前文件和内联配置。有限路由清单的内容检查保留目录索引的新鲜度。该检查变化或提示无法复现已安装身份时，完整发现继续作为恢复路径。

**删除或裁剪大型来源 checkout。** 按安装集合读取的运行时不需要无关来源，但用户仍可浏览并安装其中的套件。移除来源内容会改变这一行为，也可能损坏用户拥有的工作树。checkout 获取与存储继续独立于发现优化。

**把索引迁入宿主存储服务。** 目录已拥有自己的文件根，并且无需 Cordis 上下文即可运行。服务型缓存仍需来源 schema、HEAD 策略、读取屏障与按源失效，同时增加激活依赖和另一套存储布局。因此按现有[文件持久化决策](../../../../docs/developer/decisions/2026-09-13-plugin-persistence-stays-file-backed.md)复用 `readJsonFile`、`writeJsonDocument` 与 `@deepseek-ai/dsh-atomic-write`。宿主原子写入器提供安全替换和文件模式；插件只拥有发现语义。

## Consequences

未变化的托管来源不会因新鲜度窗口到期或重新打开目录而重复遍历套件。没有已安装套件的来源不参与运行时发现。没有可用持久索引或路由时的首次发现，以及显式刷新，仍需承担所选来源的扫描成本。打开市场也可能扫描尚未索引的来源。

托管 checkout 在驻留内存期间按插件维护的内容处理。用户自己编辑的工作树应使用本地或收编来源；显式刷新托管 Git checkout 保留现有的拉取并重置行为。可选的六小时后台来源更新独立于发现复用。

本次改造保留现有 checkout 目录和获取行为。显式删除来源仍移除其安装登记，并可在指定 `deleteCheckout` 时删除该来源的 `.sources/<id>/` 目录，包括收编的 checkout。外部本地路径会保留。本次优化不引入安装版本目录、下载裁剪或自动来源裁剪。索引文件是可重建的派生数据；schema 或发现语义变化需提升索引版本。即使来源已不再包含某个套件，其安装身份与元数据仍归用户所有。

## Verification

### 合成目录准备

[基准报告](../../../../docs/reference/performance/2026-11-13-catalog-index-benchmark.json)在 Node v24.21.0 中对比基线 `b23faa92` 与改造后的目录。每个负载有两个来源，每个来源 600 个套件，只安装一个套件。数值为三次样本的中位数，按毫秒取整。第二阶段将注入时钟推进 60 秒；重开阶段在同一进程中创建新的 `Catalog`。测量不含夹具创建、模块导入、网络、宿主挂载和浏览器工作。

| 来源模式 | 阶段           | 墙钟改造前（毫秒） | 墙钟改造后（毫秒） | Node CPU 改造前（毫秒） | Node CPU 改造后（毫秒） |
| -------- | -------------- | ------------------ | ------------------ | ----------------------- | ----------------------- |
| 托管     | 首次目录准备   | 1272               | 445                | 3210                    | 1087                    |
| 托管     | 新鲜度窗口过后 | 1210               | 1                  | 3021                    | 1                       |
| 托管     | 新目录实例     | 1216               | 15                 | 3027                    | 18                      |

这些对比在每种来源模式内使用相同的目录准备负载，测量来源选择、发现复用与可变来源绑定读取，不代表完整应用启动或运行时服务挂载的成本。

### 宿主启动与空闲重扫

用 DSH 0.2.2-rc.2 自带的 CLI 启动独立的 `market-demo` profile。两个合成托管来源各含 600 个套件，仅安装并启用一个。项目布局发现、来源自动更新和翻译均关闭。npm 版 0.14.5 在扫描启用来源的同时，为读取已安装声明又做了一次全量发现。第一次读取约 24 秒后，保温定时器再次全量扫描，此时没有浏览器连接。

| 插件构建                   | 启动时访问 checkout 的文件系统调用次数 | 空闲重扫窗口内的调用次数 | 每个采样秒的进程 CPU 峰值 |
| -------------------------- | -------------------------------------- | ------------------------ | ------------------------- |
| npm 0.14.5                 | 122,539                                | 80,493                   | 2,468 毫秒                |
| 索引版，无已有索引         | 40,848                                 | 0                        | 1,362 毫秒                |
| 索引版，复用持久化索引重启 | 2                                      | —                        | 517 毫秒                  |

每行来自一次宿主启动，前两行各观测约 30 秒。索引版冷启动没有访问未安装任何套件的来源。索引版重启后，市场接口仍返回全部 1,200 个套件和同一个已安装套件。Web 界面能打开市场并搜索到未安装的套件。实验复现了宿主 CPU 峰值，并验证了空闲时的重扫已消失。持续的 Electron 渲染进程卡死原因未定。

### 当前配置来源

对当前 23 个来源树的只读探针发现了 1,023 个套件，并将派生索引写入临时目录。44 条安装记录中，30 条匹配当前套件，14 条历史未匹配记录被保留。[原始报告](../../../../docs/reference/performance/2026-11-13-catalog-index-benchmark.json)未记录来源索引失败。

| 操作                                     | 样本         | 墙钟耗时（毫秒） | Node CPU（毫秒） |
| ---------------------------------------- | ------------ | ---------------- | ---------------- |
| 导入全部当前来源                         | 1            | 1504             | 2685             |
| 重开 `SourceIndexStore` 并读取已安装套件 | 3 次，中位数 | 41               | 55               |
| 新鲜度窗口过后读取已安装套件             | 3 次，中位数 | 6                | 12               |

每次已安装读取调用 227 次 `stat`、74 次 `readFile`、48 次 `realpath` 和 56 次 `readdir`。探针在同一进程内创建新的存储实例。两行已安装查询使用相同的当前安装集合。全量导入与仅已安装读取是不同负载，因此不能将这些行当成前后速度对比。Node CPU 与文件系统计数不含 Git 子进程内部开销和宿主启动。

## Testing

来源索引测试覆盖持久复用、来源身份与版本校验、可变来源新鲜度、绑定目录重扫、重开后的内联 LSP 等价性、同 id 目录索引改路由与移除、resolver 回退、native MCP OAuth 元数据往返、缺失 checkout、损坏文档与代次顺序。运行时目录测试覆盖按安装集合选择来源及并发读取。面板与项目测试保护快照身份、文档新鲜度与项目隔离。停用资源与共享需求测试保护会话显式选择及授权撤销。
