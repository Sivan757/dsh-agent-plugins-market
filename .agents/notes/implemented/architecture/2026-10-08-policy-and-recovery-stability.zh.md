# Agent Note: 串行策略状态与排队用户输入恢复

Status: implemented

## Decision

ResourceFilterService 拥有一份工作区策略快照。旧 surface 门面委托给该负责人。更新和重载共用队列，只有持久化成功后才发布已提交状态。

现有宿主文件锁负责跨进程串行读改写。单项更新合并最新文档，预设和重置操作则有意一次替换两个区段。全局收藏使用独立锁定文档，并在等待前捕获输入。

显式会话恢复还原已验证的持久选择。如果首次捕获尚未记录选择就失败，可按原分类重试。成功恢复或忙碌重试只继续 neutral user 来源的排队消息。加载插件不会自动执行恢复的输入。

恢复标记不进入模型输入。其他生产者的上下文，包括没有 form 的上下文，不会启动新工作。历史 started 字段保留更宽的定义，因为它报告进度而不是授权新模型请求。

宿主投影注册表增量维护进度字段。读取器拥有注册和注入 fiber。注册表缺失时回退原有扫描。清理后到达的注册表不会重新激活注册。

运行时清理尝试所有负责人并等待全部结果。失败仍向等待调用方拒绝，分离的产品调用方负责记录错误。一个失败不会跳过其他负责人。

## Alternatives considered

独立服务快照导致了已复现的更新丢失。只共享文件、不共享负责人并不足够。进程内队列也不能保护竞争文件写入。

无需新造锁，已发布 atomic-write 包已有有界写入协调。锁只覆盖文件操作，不包含运行时刷新。

唤醒所有上下文消息会产生非预期模型请求。显式 neutral user 判断更保守，保留用户工作而不把缺少 form 当作用户输入。

自定义事件缓存重复宿主投影归属。已发布注册表已提供重放、增量折叠和注销语义。

吞掉清理失败会误报成功。因此等待全部负责人结束后汇总失败，并在装配根观察分离调用的拒绝。

## Consequences

保留工作区路径及 v1/v2 读取兼容。新工作区写入使用既有 v2 格式。全局收藏保留 v1 格式，不向项目目录写入工作区策略。

策略提交后的运行时刷新仍然串行。慢刷新通过现有阶段期限形成有界背压。独立进程快照在重载时收敛，不新增文件监听。

[审查台账](../../../../docs/reference/refactor-review-ledger.md)记录复现、纠正、测试与产物验收。[完成契约](../../../../docs/developer/design/refactor-completion.md)定义最终范围。
