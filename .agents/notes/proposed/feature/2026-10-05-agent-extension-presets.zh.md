# Agent Note: 从工作区扩展预设建立会话独立选择

Status: proposed

## Problem

同一工作区可能同时存在前端、后端和调研会话。工作区级挂载开关会让这些会话互相影响。用户需要复用扩展能力选择，而不是切换宿主基础 Agent 预设，或在工作区之间复制凭据。

## Proposal

已确认的产品模型将工作区私有预设库与会话独立能力选择分开。新会话默认只是预设指针，不是已有会话的实时父级。[下一轮选择](../../implemented/architecture/2026-10-08-shared-surfaces-and-next-turn-selection.zh.md)替代发起编辑会话的编辑隔离规则。其他会话保留独立副本。显式会话调整只在安全执行边界生效。全局硬停用或卸载的能力仍不可用。

空白和进行中的会话统一在「权限」右侧使用 28px 图标按钮。单色线性图标组合 Agent 头部与能力接入模块。原型约束行为和大致布局，不构成独立的视觉系统。管理窗的页签、来源标签、字体、资源卡片、计数和操作均复用当前设置页的组件与样式。宿主 Modal 提供按视口收缩的固定 800×800 外框。单击卡片修改所选预设，详情保留为独立操作。剪贴板仅传递版本、名称和可移植资源标识。

预设库复用现有私有 JSON 写入器与已发布 atomic-write 锁，通过乐观版本检查拒绝过期编辑。会话选择使用宿主支持的持久化消息信封，记录待处理和已提交检查点。按 Agent 装配的贡献者将暂存注册与已提交的执行授权分开。活体验收仍是交付要求。

## Alternatives considered

- 原生项目分组和用户 Hooks 使用独立的本地配置页签。删除父级记录会破坏已保存的选择，并使 Hooks 无法控制。展示元数据将它们与市场套件分开，不改变授权或已持久化的标识。

- 先前的[项目资源窗口](../../implemented/feature/2026-10-04-project-resource-window.zh.md)与[工作区开关](../../implemented/feature/2026-10-03-per-workspace-surface-toggles.zh.md)在迁移落地前仍是实现依据。其工作区实时挂载语义仅部分被替代，运行时仍在使用时不归档。
- 不复用宿主基础预设：基础模式与扩展选择是独立概念。在单组件 hero Agent-preset 槽注册新组件会替换原有选择器，而不是追加相邻入口。
- 宿主设置命名空间面向配置，不面向任意工作区预设库。既有私有 JSON 持久化适合预设库；已发布 atomic-write 提供本机跨进程写入协调。这不构成另建会话日志的理由：会话选择应使用宿主支持的持久化消息信封。
- 继承禁用掩码不是通用覆盖机制。本作用域工具不受该掩码限制，全局指令无法直接相减，LSP 工作区进程共享。运行时必须按会话落实选择，不能停止其他会话仍在使用的共享资源。

## Acceptance criteria

- 同工作区两个会话在预设或默认编辑后保留独立选择；显式空选择与无历史状态不同。
- 剪贴板输入失败关闭；预设不携带凭据或服务配置。过期并发写入不覆盖新版本。
- 首次请求必须等待选择恢复或已确认的修改完成。工具发现与执行一致。
- 首次与进行中入口使用宿主支持的装配接口，不替换基础模式、不修改宿主代码。
- 技能、指令、角色、MCP、LSP 和套件 Hooks 都有明确会话行为与真实运行证据；不能把无效控件显示为已生效。
- 复用完整详情，用户文案双语，独立 profile 通过浏览器及运行时验收。

## Risks

已发布 rc.2 在权限及计划控件后提供会话作用域列表 conversation.input.left，没有可追加的 hero 相邻入口。用户要求空白和进行中的会话都在该槽使用图标。真正尚未建立会话的草稿没有受支持的扩展元数据传递口。自定义 SVG 将 Agent 扩展与宿主 Agent 预设及通用设置区分开。已发布图标集中没有这种组合，其描边复用公开的 ICON_MEDIUM_STROKE 常量和 currentColor。

原生用户技能复用公开的作用域技能注册表：同名候选控制调用状态，提供器加载时再次检查已保存的选择。普通全局停用是默认值，不是硬性不可用；无效文档仍被拒绝。宿主或其他插件提供的 MCP 工具保持独立管理。共享 MCP 与 LSP 覆盖需要明确挂载所有权，避免一个会话停止另一会话正在使用的资源。

辅助模块与集成测试不能证明活体交付。验收必须在独立 profile 中运行构建后的插件，覆盖两种入口和生命周期转场，并区分崩溃恢复与宿主正常关闭；后者会取消待处理输入。

[逐项 Hook 决策](../../implemented/bug-fix/2026-10-07-hook-selection-enforcement.zh.md)明确用户和项目 Hook 行的执行授权。已安装市场套件的 Hooks 保留父级选择。
