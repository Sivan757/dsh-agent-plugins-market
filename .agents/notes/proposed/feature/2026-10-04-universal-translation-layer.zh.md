# Agent Note: 横跨六个面的通用翻译层

Status: proposed

## Problem

市场渲染的上游 catalog 以英文撰写，因此 `zh` 部署看到的是中文界面里嵌着英文数据。套件名称与描述，技能、快捷指令、专家三者的名称与描述，MCP 服务名与工具描述，以及 LSP 服务器名，全都原样进入面板。[描述本地化 note](../../implemented/feature/2026-10-03-description-localization.md) 只补上了一个面上的一个字段；同一个缺陷在其余五个面、以及所有名称上依然存在。

catalog 不归我们编辑。一个 source 是别人仓库的 checkout，每次更新都会刷新，所以翻译不能写回 manifest。它必须放在 catalog 旁边，在输出的路上应用。

三条约束决定了答案的形态。它必须零配置可用——全新安装、没有代理、没有 API key、没有配置模型路由，也要能收敛到中文。它绝不能让面板比它所替换的英文更差，因此每一条失败路径都终止于上游原文。它还必须避开模型读到的那一份：进入模型上下文的 system prompt 与工具描述，和人在屏幕上看到的是两种不同的产物。

## Proposal

本地化成为市场渲染时经过的一层，而不是某张卡片代码路径里的一步。一条 translation unit 描述一个可翻字段；一条有序 provider 链为它作答；一份按内容寻址的缓存记住答案；每个面渲染译文，同时把上游原文保持为它一直以来的那个标识。

### 一条单元，六个面

单元携带面（`market`、`skills`、`commands`、`agents`、`mcp`、`lsp`）、实体在该面内的稳定 id、角色（`name` 或 `description`）与上游原文。六个面汇入同一个收集器，因此跨面重复的文本——既是套件名又是其 MCP 服务名的那个字符串——只入队一次。在本机 catalog 上，这次去重把 8,041 条字段、1.19M 字符收敛为 4,775 条唯一文本，少发 28% 的字符。每批最多 20 条文本、同时最多 3 批，因此一次慢调用不会扩散成数百个请求。

| 面       | 名称     | 描述                     |
| -------- | -------- | ------------------------ |
| 市场     | 套件名   | 套件描述                 |
| 技能     | 技能名   | 技能描述                 |
| 快捷指令 | 命令名   | 命令描述                 |
| 专家     | 角色名   | 角色描述                 |
| MCP      | 服务名   | 每个工具一行             |
| LSP      | 服务器键 | 无 —— 该条目没有描述字段 |

### 有序回退链

provider 按固定顺序运行：Google Translate、Microsoft Translator、用户自己的默认模型、上游原文。第一个作答的胜出；抛错、超时或返回条数不符的 provider 被跳过。两个公开端点都不需要 key、不需要配置，这正是该能力开箱即用的来源；模型留在链上，作为配置了它的部署可用的最高质量档。

Google 先试、给 3 秒；Microsoft 给 15 秒；模型给 30 秒。失败的 provider 在本次进程内被记住——一个不可达的端点每个会话只付一次超时，而不是每批一次，因为被阻断的网络会把连接挂住而不是拒绝它。本机实测：Google 走代理 0.26 秒作答，无代理时挂过 4 秒；Microsoft 无需任何认证、直连 0.38 秒作答。

### 缓存与键

译文以目标 locale、单元的面、id、角色与原文，以及 provider 链的标识，共同做 SHA-256 摘要作为缓存键。按内容寻址意味着重写了文本的实体会重新翻译，而只是提升版本号的实体保留译文。条目七天过期，因此一次上游编辑不会把过期译文永久钉住。

provider 标识放进键里是刻意的。换了引擎的部署必须让旧引擎产出的文本失效，而不是把它当作新引擎的产出继续供出；另一种做法——给每条记录一个「可升级」标记——是第二套状态机，而它买不到键已经给不了的东西。记录里的 `provider` 字段仍然保留，那是给翻看文件的运维人员看的，不参与判定。

### 遮蔽

两个公开引擎都会破坏技术文本：它们改写裸尖括号、转义 HTML、吞掉字面换行。一批文本发出之前，行内代码、URL、尖括号片段、`${VAR}` 引用和一份固定术语表（`MCP`、`LSP`、`DSH`、`CLI`、`API`、`JSON`、`HTTP`、`URL`、`SDK`）会被替换成引擎原样透传的占位符。答案返回后还原占位符，且每一个都必须恰好出现一次；没通过这项校验的一批直接丢弃，不入缓存。

### 渲染：名称即标识

译文只用于展示。搜索、排序、复制、斜杠调用以及每一个 `aria-label` 继续使用上游原名，原文通过卡片的 `title` 属性保持可达。名称是可调用的标识——一个流进过滤器或斜杠命令的译名，会破坏它本要改善的东西。描述没有这重身份，因此直接渲染译文。

### 设置与作用域

只有 `zh` 部署会翻译；英文面板显示的本就是作者原文，为它排队调用等于花额度复现输入。一个设置开关可以关掉这一层：链清空后，所有面渲染上游原文。这一层从不触碰模型读到的那一份：注入会话的 system prompt 与工具描述保持作者撰写时的语言。

## Alternatives considered

**在客户端翻译。** 因分层被否。`src/client/**` 不得 import `node:**`，也不持有持久缓存；浏览器侧翻译器会在每次页面加载时重新调用 provider，且无法跨重启记住结果。浏览器这一半渲染 node 这一半算好的译文，不自己算。

**只做两个免费机器翻译端点。** 被否：术语保真度是通用机器翻译引擎的弱项——`skill`、`suite`、`surface` 回来的译法前后不一致，专有名词在两次调用之间漂移。用户自己的模型留在链上，作为可以被告知如何呈现本领域词汇的那一档；只有部署配置了它，链才会走到它。

**把 provider 从缓存键里去掉。** 被否：键就只剩内容，换了引擎的部署会永远继续供出旧引擎的文本。手工失效或靠版本号失效是伪装的版本标记；把 provider 标识折进键里让未命中自动发生，旧条目由 TTL 自然淘汰。

**按来源分片缓存。** 本轮不做。设计文档提议一个来源一个文件，因为单文件每次 flush 都要整份原子重写；在本 catalog 的体量下整份文档只有几兆，七天 TTL 已能在不分片的情况下约束增长。分片会引入多文件迁移与并发写问题，而这份代价目前还没有被测量到。

## Acceptance criteria

- 全新安装、无代理、无 key、无模型路由时，六个面在首次打开面板后的一次刷新内渲染中文。
- 断网时每个面板渲染的与上游原文完全一致——没有报错、没有转圈、首屏不被阻塞。
- 第二次启动进程用零次 provider 调用供出同样的文本，跨面重复的同一文本只翻译一次。
- 搜索、排序、复制、斜杠调用与 `aria-label` 仍命中上游原名。
- 注入会话的 system prompt 与工具描述保持不变。
- `pnpm run check:refactor` 与全量 `pnpm run test` 通过。

## Risks

- **公开端点无 key，因此没有承诺。** 限流或端点下线会静默降级到下一级，既不通知用户，也没有「当前生效 provider」的读数可供诊断。
- **机器翻译质量低于模型。** 遮蔽层保护代码、路径与固定术语表，模型档仍是配置了它的部署的质量上限。
- **被阻断的网络下首次调用要付一次超时。** 熔断把它限制为一次；Google 让位后 Microsoft 在半秒内作答。
- **缓存随 catalog 增长。** 按内容寻址的键只增不减；七天 TTL 是阻止增长的那一环，而单文件每次 flush 都要整份重写。
