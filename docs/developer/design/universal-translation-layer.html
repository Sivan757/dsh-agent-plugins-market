通用翻译层

把当前只覆盖市场套件描述的本地化，扩展为横跨六个面的通用层：市场、技能、快捷指令、专家、MCP、LSP 的 名称与描述，跟随宿主语言，开箱即用，翻译一次即缓存。

2026-10-04 状态 · proposed 基线 · dsh 0.2.0-rc.2 部分取代 · 2026-10-03 描述本地化

01问题与目标

上游 catalog 是别人仓库的 checkout，每次更新都会刷新，翻译不能写回 manifest。现状只覆盖了套件描述这一条路径。

现状

只有 suite.manifest.description 走本地化。技能、快捷指令、专家、MCP、LSP 的名称与描述全部原样渲染英文。

目标

六个面的名称与描述都跟随宿主 locale.preference；名称只翻展示，调用标识保持原名。

硬约束

开箱即用（零注册零配置）、翻译只出现在 UI 层、注入模型上下文的那一份保持英文。

体量（本机实测）

8,041 条 / 1.19M 字符；去重后 4,775 条唯一文本，省 28%。增量只来自新装或更新的 suite。

02回退链

四级有序回退，任一级失败或超时即降级到下一级，全部失败时静默渲染原文。延迟为本机实测值。

第 1 级 · 优先
Google Translate
translate-pa.googleapis.com/v1/translateHtml
走系统代理时 暖 0.26s / 冷 1.28s；无代理时 4s+ 超时。
3s 超时 + 进程级熔断：一次超时后本次会话不再尝试。
第 2 级 · 兜底
Microsoft Translator
edge.microsoft.com/translate/translatetext
零认证、零配置、无需代理，直连 0.38–0.45s。支持数组批量，换行安全。
开箱即用的保证由这一级提供。
第 3 级 · 质量
用户默认模型
agentDefaultModel.currentSelection()
质量最高，术语可控。走用户额度，当前部署 402 余额不足。
保留为最高质量档，余额恢复后自动参与。
第 4 级 · 降级
渲染原文
upstream text as authored
面板永远可用。静默降级，不弹提示；当前生效的 provider 只在设置页显示。
为什么必须熔断 无代理网络下 Google 不是快速失败而是挂住 4 秒以上。没有熔断，每次冷启动面板都要先等一次超时；有了熔断，整个会话只付一次代价。

03分层架构

沿用既有边界：contracts 不 import 任何东西，application 不 import runtime，client 不 import 服务端层。所有网络效应留在 runtime/host/，通过 port 注入 application。

src/contracts
不 import 任何模块
translation.ts
src/application
用例 · port · 纯逻辑
translation/unit.ts translation/chain.ts translation/localizer.ts state/translation-cache.ts ports.ts catalog.ts panel-resources.ts mcp-service.ts
src/runtime/host
唯一持有网络效应的一层
machine-translator.ts llm-translator.ts translation-providers.ts text-masking.ts
src/client
只读缓存结果，不发起翻译
ui/use-translations.ts ui/UserPanelSurface.tsx features/market/SuiteCard.tsx features/market/SuiteDetail.tsx features/mcp/StatusPanel.tsx features/lsp/LspStatusPanel.tsx locales.ts
边界为什么这样切 client 不得 import node:* 也不持有缓存，因此浏览器侧不能翻译；翻译结果由服务端算好、随既有 API 一起下发，客户端只负责渲染与轮询。

04数据流

读路径永不等待模型或网络。缓存命中即刻返回，未命中返回原文并计数，客户端轮询到计数归零。

1
扫描产出翻译单元
catalog / panel-resources / mcp-service 各自把可翻字段交给 TranslationUnit 收集器。
2
同步查缓存
命中 → 直接返回译文；未命中 → 返回原文 + pending，并把工作入队。
3
批处理与去重
跨面共享的文本只入队一次（省 28% 字符）；每批打包 N 条，一次请求。
4
遮蔽 → 送翻 → 还原
占位符替换代码块、URL、尖括号标签、包名；按链逐级尝试；还原后再入缓存。
5
落盘
按 sourceId 分片写入，带 TTL 与来源标记（哪个 provider 翻的）。
6
客户端轮询
1.5s 重读直到 translationPending 归零；出错即停，不无限轮询。

05缓存设计

内容寻址，provider 进 key：换引擎自动 miss 重翻，不需要额外的「可升级」状态；旧条目由 TTL 回收。

// key = sha256 的输入，用 NUL 连接避免 id 含分隔符时互相别名
targetLocale \0 surfaceKind \0 surfaceId \0 role \0 sourceText \0 providerIdentity

// 落盘记录
{
  "text": "…译文…",
  "provider": "google" | "microsoft" | "llm",   // 已进 key，此处仅供诊断
  "at": 1759500000000,
  "expiresAt": 1759500000000            // TTL = 7 天
}
维度 决定 理由
key 组成 含 providerIdentity 换引擎后旧译文质量差，进 key 会自动 miss 重翻，省掉一套版本管理状态。
role 名称与描述分开 同一实体的 name 与 description 是两条独立文本，共用 key 会互相覆盖。
TTL 7 天 + 24h 定时清理 内容寻址 key 只增不减；上游改一次描述就多一条永久垃圾。现状缺这一层。
分片 按 sourceId 一个文件 现状整份原子重写已 243KB；全量约 3MB，单文件重写代价随目录增长。
写入时机 1.5s 批量 flush 沿用现状，避免每条译文一次写盘。

06遮蔽层

两个 MT 引擎都会破坏技术文本：Microsoft 把裸尖括号融进伪标签，Google 会转义并吞掉字面换行。送翻前统一遮蔽，回来后还原。

// 遮蔽顺序即还原的逆序；占位符用引擎不会改写的形态
行内代码        →  ⟦C1⟧
尖括号标签      →  ⟦T1⟧
URL             →  ⟦U1⟧
路径变量        →  ⟦V1⟧
MCP / LSP / DSH →  ⟦K1⟧   // 术语表，防止被意译

// 还原后校验：占位符数量必须一致，否则本次结果作废、不入缓存
与术语表是同一层 遮蔽同时解决三件事：防止标签腐蚀、保护代码与路径、固定术语译法。一次实现，三个收益。

09风险与验收

公开 key 被吊销

Google 级静默降级到 Microsoft，用户无感。设置页显示当前生效的 provider，不做打扰式提示。

MT 质量低于模型

技术术语保真度明显更差。遮蔽层缓解；模型级保留为最高质量档。

无代理网络的首次代价

每个会话一次 3s 超时。熔断后不再重试；Microsoft 级 0.4s 立即接管。

缓存体积

全量约 3MB，按 sourceId 分片 + 7 天 TTL；条目数不再单调增长。

验收标准

  • 开箱即用：全新安装、无代理、无模型配置时，六个面在首次打开后一次刷新内显示中文。
  • 降级可见：断开网络时面板与改动前完全一致，渲染原文，无错误提示、无卡顿。
  • 只翻一次：重启进程后二次打开零请求；同一文本跨面只翻译一次。
  • 标识不变：搜索、复制、斜杠调用全部命中原名。
  • 上下文不受影响：注入模型的 system prompt 与工具描述仍为英文（既有测试断言）。
  • 门禁：pnpm run check:refactor 与全量 pnpm run test 绿。
