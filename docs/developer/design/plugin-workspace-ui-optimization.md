视觉基准：`workspace-redesign/preview-a.png`、`workspace-redesign/preview-a-detail.png`；本轮追加的截图（工具栏分段控件、五个详情弹窗）与该原型一致，直接作为验收对照。原型文件已移出仓库，临时存放于 `/tmp/dsh-proto-shots/prototype/prototype-a-unified-grid.html`，全状态截图见同目录 `README.md`。

## 范围

六个页面（插件市场 / 技能 / 命令 / 代理角色 / MCP 服务 / LSP 服务）共用同一个设置工作区。本清单只覆盖表现层：布局、卡片句法、组件组合、样式与文案。

不改路由、契约、schema、持久化、定时器，也不挂载新能力——下面提到的能力全部已经存在（来源条与来源增删改、未纳管目录纳入、各页面增删改查、套件详情逐条展开、MCP 与 LSP 的单服务配置编辑）。入口、处理函数与请求负载保持不变。

## 二、改动清单

### C1 统一卡片句法（差异 1、2、6、7、8）

六个页面统一成三行，页面只换填进去的内容：

| 行     | 内容                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------- |
| 身份行 | 名称（套件带版本）+ 一个归属标签（`用户` / `插件`）+ 非健康时才出现的状态胶囊；**操作簇在右侧** |
| 正文行 | 该页面的主体：套件、技能、命令、角色是描述，MCP 是端点，LSP 是命令；两行                        |
| 来源行 | 套件 id（等宽）· 计数 · 状态                                                                    |

- 落点：`features/market/SuiteCard.tsx`、`ui/UserPanelSurface.tsx`（`UserEntryRow`）、`McpStatusPanel.tsx`（`McpCard`）、`LspStatusPanel.tsx`（`LspRow`）、`ui/ResourceCard.tsx`；样式在 `market.module.css`、`panel.module.css`、`mcp-status.module.css`。
- 保留 `ui/resource-card.module.css` 的 3px 左边条作为唯一启停与健康信号；左边条已经说过的话不再用文字徽章重复。
- 计数统一为「标签 + 等宽数字」，用 · 分隔，不再用描边方框。
- 描述截断统一用 `max-height`；删掉 `panel.module.css .entryDesc` 的 `-webkit-line-clamp`。
- 归属标签只说归属，不说层级：套件来自用户目录是 `用户`、来自项目目录是 `插件`，与技能、命令、角色卡现有的 `用户` / `插件` 同一套写法；`用户级` / `项目级` 不再出现在卡片上，编辑来源弹窗里那格只读的「作用域」同样改成 `用户目录` / `本地目录`。
- MCP 与 LSP 的过滤栏现在写英文 `Plugin`（`mcpPlugin` / `lspPlugin` 的中文值），改成 `插件`，与另外四个页面的过滤栏、卡片标签、详情弹窗一致。
- 六个面板的副标题统一不用句号：技能、命令、角色三个面板描述去掉句尾的 `。`，与市场、MCP、LSP 对齐。
- 验收：窄面板下同一行卡片等高（`grid-auto-rows: 122px`）；切换页签只换内容、不换句法。

### C2 栅格几何与列数（差异 3、4）

- 三处网格改 `repeat(auto-fill, minmax(280px, 1fr))`；网格行高 `grid-auto-rows: max-content`——卡片贴着内容收尾，固定行高会在两行描述的卡片底部留出一截空白；列表行 56px。
- 窄面板（620px）下网格保持 2 列：`@container (max-width: 420px)` 才退 1 列。
- 窄卡（287px）的操作簇固定在右上角、与名称同一行：身份行右侧按操作簇宽度留位，正文行与来源行拿整卡宽。留位是一个固定值、与开关状态无关，点开关不会产生横向位移；整簇（含启停开关）默认隐藏，hover 或键盘聚焦才作为一组淡入，不额外铺底。名称单行、超出用省略号，不折行（折行会让同行卡片高度不齐）。
- 卡片间距与卡片内部间距同一个值（4px）：卡片内身份行 / 正文行 / 来源行之间是 4px，卡片与卡片之间也是 4px，不另起一套节奏。
- 网格卡片描述保持两行（`-webkit-line-clamp: 2`），卡片上下内边距一致且收到 10px；MCP / LSP 卡的归属标签是「插件」、而来源行已经写着套件名，窄卡里删掉这颗重复标签，把宽度让给 `jetbrains__jetbrains` 这类长名称。
- MCP / LSP 卡补上启停开关（与另外四页一致）；开关也是操作，与同簇的图标、主操作一起显隐，不单独常显——卡片上不再有「半簇常显」的割裂感。开关开态用 `state-business-primary`。
- 市场与 MCP 的视口断点改容器查询，与 `.shell`、`.entryGrid` 已有的写法对齐。
- 列表布局提示：现在套件列表把 `.meta` 与 `.tagRow` 各自占一整行（`flex-basis: 100%`），一行约等于三行文字高；要压到 56px 必须先把计数并进来源行。
- 验收：620px 面板下网格 2 列（每卡 287px）、间距 4px、描述两行、卡片底部不再留空（网格实测：两行描述卡 108px、MCP/LSP 单行端点卡 91px）；hover 任一卡片名称零位移；点开关前后名称与操作簇宽度不变；六页无一条标题被截断、无内容越过卡片右边界——原型实测值。
- 原型实测中发现两处计数与内容不符，产品侧同样要按此对齐：市场的「已安装」按 `state === 'active'` 算，不能把未安装的卡片算进去；LSP 的 `kind` 缺失时会被归成「用户」，插件来源必须显式带 `kind: 'plugin'`。

### C3 操作按钮统一到右上角（差异 5，追加要求 2）

- 六个页面的操作簇都放在卡片**右上角、与名称同一行对齐**；不再有独立操作列，也不放右下角。窄卡里身份行右侧按操作簇宽度留位（固定值，与开关状态无关），正文行与来源行拿整卡宽。
- 它只占身份行右侧；正文行与来源行各自整宽，所以描述不会被挤压（原型实测 373px 卡内描述 344px，等于整卡内容宽）。
- 顺序：次要图标操作（刷新、编辑、删除）→ 未安装套件的主操作（安装、添加源）→ 开关放最后。整簇在 hover 或聚焦时一起淡入，位移为零；默认不显示任何操作。
- MCP 与 LSP 卡片不放卡片操作，重试连接留在详情底部——与现状一致。
- 图标按钮统一成宿主几何：24px 方形、无外框。现在插件有两套尺寸（`market.module.css .iconBtn` 26px、`panel.module.css .iconBtn` 32px）。
- 操作簇的颜色跟随仓库源选中胶囊：图标与「安装」用 `brand-primary`（选中胶囊的填充色），开关开态同色、关态用 `border-l3`（未选中胶囊的描边色）；这样亮暗两套都由同一个 token 翻转，不写主题分支。
- 验收：hover 任意卡片无位移、无文字回流；名称与操作簇在同一水平线上；默认态看不到任何操作（含开关）；点开关不改变名称与操作簇宽度。

### C4 仓库来源条保持现状（差异 16，追加要求 3）

来源条已经实现，本轮**不做任何样式改动**，只保留一条「不要碰」的约束和一条过期注释的修正：

- 保持：等宽胶囊（`auto-fill minmax(118px, 1fr)`）、`全部 <总数>` 在最前、每个来源 `id 数量 ⚠`、选中来源才出现改名、每个来源都有移除、超过两行折叠并在 hover 或键盘聚焦时就地展开为浮层、选完立刻折回、底部渐隐露出下一行的边；添加源仍在页头按钮上，不放虚线 chip 进来源条。
- 保持：胶囊只带 `本地` / `压缩包` 维度徽章，远程来源只有 `id 数量`——原型此前多写的 `用户级` / `项目级` 已删掉。
- 窄面板（620px）要多露几行：折叠时来源行上边溢出 6px、下边探出 6px，窄面板下探出的那截会压到「未纳入来源」那一行，所以折叠态把条裁到比自身高 6px（保留渐隐的半行），展开时撤掉裁剪并把条抬到列表之上，浮层与投影才不被切、也不被卡片盖住。
- 保持：选中来源排到 `全部` 之后第一位；未纳管目录行（未纳入来源的本地目录 … 纳入）原样保留。
- 只修注释：`SourceTabsRow.tsx` 模块头写着「选中来源不会被移到最前」，但 `MarketSection.tsx` 实际会移到最前（`[selectedSource, ...sorted.filter(...)]`），而这正是 props 文档描述的行为。行为不动，注释改对。
- 原型已按线上实现重做（含折叠与展开行为），落点仅用于对照：`features/market/SourceTabsRow.tsx`、`SourceTab.tsx`、`market.module.css`。
- 验收：视觉与行为与当前线上一致；这一块只有注释产生 diff。

### C6 详情弹窗（差异 11、12、13，追加要求 1 的弹窗部分）

按追加截图实现，五个详情弹窗规格一致：

- 外壳：标题栏（左侧标题 + 一行副标题「种类 · 来源」，右侧一个关闭）、可滚动正文、固定底部操作。宽度 lg 880。
- 顶部信息带：状态圆点 + 状态胶囊（非健康才带颜色）+ 归属标签 + 版本（套件才有）；第二行是端点、命令或磁盘路径（等宽字体）。整块用 `interactive-bg-hover` 做浅底。
- 概览：四列等宽，字段按页面区分——套件是「来源套件 / 布局 / 作者 / 最近变更」；技能与命令是「来源套件 / 类型 / 磁盘路径 / 最近变更」；MCP 是这四项再加「传输方式」；LSP 是「来源套件 / 类型 / 声明文件 / 最近变更」。不再重复标题栏已给的状态与路径。
- 描述：正文段落；套件详情另有「根目录」等宽代码块。
- 分组内容：套件详情按表面分组列出「技能 (N)、MCP 服务 (N)、命令 (N)、Hooks (N)、代理角色 (N)、校验诊断 (N)」，每组是可展开行（名称 + 灰色说明 + 右侧箭头），点开就地渲染——技能、命令、角色用 Markdown，MCP、LSP、Hooks 用 JSON。技能超过 3 条时补一行「其余 N 个技能」。技能详情是「技能文档 SKILL.md」一行，命令详情是「命令文档 <name>.md」一行，角色详情是「角色定义 <name>.md」一行，MCP 详情是「工具清单 (N)」逐条加「服务配置 mcp.json」一行，LSP 详情是「语言扩展名 (N)」逐条（`.ts` → `typescript` 两列）加「服务配置 lsp.json」一行。
