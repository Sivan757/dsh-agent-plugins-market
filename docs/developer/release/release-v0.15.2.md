## 一、修复内容

用户在市场里关掉某行之后，**曾经捕获过它的会话仍然继续授予它**：恢复的会话照样运行该套件的 hooks、注入它的指令，而每个界面都显示该行已关闭。根因是捕获（capture）存的是 id 集合，读的时候只看 id 在不在，从不看总开关现在的状态。

四处改在同一处读边界上：

| 位置                         | 改动                                                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `extension-authorization.ts` | 授权判定增加 `capture` 语义：捕获是"总开关的当前快照"，因此不授予目录已关掉的行；显式命名该行的预设仍然授予——这正是此前开关无法区分的差别 |
| `extension-runtime.ts`       | 刷新跟随改为对称：删掉目录公布为已关闭的行，保留库存未列出的每一个 id，因此一次读不全不会缩小选择                                         |
| `extension-inventory.ts`     | 已安装套件的 hook 行上报**套件的开关**而不是常量，默认捕获不再携带一个所属套件已关闭的声明                                                |
| 恢复路径                     | 提交的捕获在任何读取之前生效，因此捕获早于开关关闭的会话也会立刻停止授予；存储里的 id 由下一次目录读取剪掉，在此之前它不授予任何东西      |

新增四个测试（两个集成、一个授权、一个库存），覆盖：捕获早于开关关闭后不再授予且跟随会删掉该 id；预设显式命名时仍然授予。
