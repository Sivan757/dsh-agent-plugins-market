## 它做什么

有两个面向模型要一个建议，两者都以文本作答，而且都是你先读完才可能有事发生：

| 面         | 它答什么                                     |
| ---------- | -------------------------------------------- |
| 市场页头   | 按这个工作区的用途，**推荐要安装的套件**     |
| 预设管理器 | 一个预设：名字、理由，以及它应当打开的那些行 |

失败了的连接器或语言引擎，在它的详情弹窗里有自己的动作：**让 AI 解释这次失败**。它发出这一行本来就展示的事实——状态、代码、原因、归因——然后回答最可能的原因和一到三步可尝试的操作。它不能重试、重启或修改任何东西。

技能、快捷指令、专家、输出风格与系统提示词文件的编辑器不再替你起草。风格、角色或钩子是人自己拥有的配置，一个替人写它的编辑器和「一个会收窄自己的列表」不是同一件事。

## 市场推荐的做法

说明这个工作区要用来做什么，模型就从本次部署已经扫描到的市场里挑。它从不看浏览器手里的那份清单，而且它给出的每个 id 都要对照市场校验。应用答案会把列表收窄到这些套件。安装仍然是每张卡片本来就有的确认步骤。

## 预设建议的做法

说明一个配置用来做什么，模型给出名字、理由，以及从管理器正在展示的行里挑出的选择。三者都摆在你面前之后才有「创建」这一步——走的是管理器本来就有的创建路径。

服务的配置**故意不在这里**。从一句话起草 MCP 或语言服务器声明是另一件事、另一种复核：答案是配置而不是散文。

## 用哪个模型

部署自己的**默认模型**，也就是宿主用于辅助工作的那一个。插件从不自选模型、从不索要 API key：如果部署还没有默认模型，这一面会如实说它无法作答，而不是退回到一个你没选过的东西。

调用在插件这一侧完成。浏览器从不接触凭据，提示词也不是页面能决定的：你发的是「想要什么」，不是「怎么问」。

## 边界

- 每次请求一份答案，最多 1500 输出 token，60 秒后放弃。
- 意图上限 2000 字符；更长的请求在调用模型之前就被拒绝。
- 答案整块返回，所以你读的是一份完成的建议，而不是盯着文字流进来。

## 什么时候不能用

缺少默认模型时回答没有配置模型；提供方失败时回答提供方自己的消息；一份什么都没选中的答案会作为不可用被拒绝，而不是被应用。任何情况下列表都保留它原本展示的内容。

## 代价

每按一次一次模型调用，用你本来就在付费的那个模型。插件不新增服务、不加缓存、不后台调用：你不按按钮，什么都不跑。
