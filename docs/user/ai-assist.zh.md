## 它做什么

每一个持有「可撰写文档」的面，在正文上方都多了一行：**AI 起草**。你用自己的话描述想要什么，模型给出成品，成品落进你正在看的编辑器。

草稿是建议，不是写入。你不点保存就什么都没发生，文本也始终可改，所以一份你不喜欢的草稿只值一次撤销。

## 出现在哪里

| 面         | 起草的成品                                                          |
| ---------- | ------------------------------------------------------------------- |
| 技能       | frontmatter 的 description 加技能本身的指令                         |
| 快捷指令   | 一条命令：description、参数提示，以及用 `$ARGUMENTS` 指代参数的正文 |
| 专家       | 一个角色：description 加该角色的常驻指令                            |
| 输出风格   | 一个风格：description 加塑造模型回答方式的文本                      |
| 系统提示词 | 一段给 `AGENTS.md` 的 Markdown                                      |

服务的配置**故意不在这里**。从一句话起草 MCP 或语言服务器声明是另一件事、另一种复核：答案是配置而不是散文。

## 用哪个模型

部署自己的**默认模型**，也就是宿主用于辅助工作的那一个。插件从不自选模型、从不索要 API key：如果部署还没有默认模型，这一行会如实说它无法起草，而不是退回到一个你没选过的东西。

调用在插件这一侧完成。浏览器从不接触凭据，提示词也不是页面能决定的：你发的是「想要什么」，不是「怎么问」。

## 边界

- 每次请求一份成品，最多 1500 输出 token，60 秒后放弃。
- 意图上限 2000 字符；更长的请求在调用模型之前就被拒绝。
- 答案整块返回，所以你复核的是一份成品，而不是盯着文字流进来。

## 什么时候不能用

缺少默认模型时回答*没有为起草配置模型*；提供方失败时回答提供方自己的消息；草稿触到 token 上限时会明说，而不是把截断的成品存下来。任何情况下编辑器都保留你原有的内容。

## 代价

每按一次一次模型调用，用你本来就在付费的那个模型。插件不新增服务、不加缓存、不后台调用：你不按按钮，什么都不跑。
