页签管理 · 四个方案

两个目标：页签行的可用空间不再被常驻按钮吃掉；收纳与排序都要有。四个方案都去掉了行尾按钮， 区别只在「入口藏在哪种手势里」以及「排序怎么下手」。每页可切深色、可重放引导。

方案 D · 长按抬升 → 排序 / 拖出收纳推荐

一个手势管两件事。长按 260ms 整行浮起，横向拖动改顺序，继续拖过右缘就收纳。点击仍然是切换页签。

排序 ✓收纳 ✓零常驻控件触屏成立
 方案 A · 边缘磁轨 + 长按排序组合

行尾 10px 留白的磁轨负责成段收纳与取回（每次一格，34px 磁吸）；长按页签做横向排序。两种手势各管一件事。

排序 ✓收纳 ✓磁吸回弹成段收纳最快
 方案 C · 长悬停气泡 + 右缘渐隐长悬停

悬停 620ms 弹气泡，气泡里给 ← → 挪位、收纳、在列表中看；溢出页签化成渐隐 + 数字。

排序 ✓（按键）收纳 ✓入口最容易被发现
 方案 B · 长按抬升 + 拖出收纳仅收纳

长按抬升后拖到右缘收纳。第一版没有排序，留作手势原型的参照。

排序 ✗收纳 ✓纯手势

排序能力的四种做法

方案 排序入口 键盘等效 代价
D 长按 → 横向拖动，2px 竖线示位 ⌥+←/→ 长按与「长按选中文字」有冲突，需位移阈值
A 同上，另有一套成段收纳的磁轨 ⌥+←/→、⌫ 两种手势要各教一次
C 气泡里的 ←→，一次挪一格 同一对按钮就是键盘路径 挪远要靠连点，长距离排序慢
B 无 — 不满足需求

排序的存储（四个方案共用）

  • 布局文档从 { hidden } 扩成 { hidden, order }：order 是全部九键的完整排列，未知键被丢弃、缺失键按默认顺序补齐。
  • market 固定第一位：任何拖动、任何手写文件都把它拨回首位，因此排序与收纳一样不可能把行弄空。
  • 收纳不动 order：收起再放回时页签回到原来的位置，而不是队尾。
  • 一次手势结束只写一次盘；同一次拖动里既排序又收纳时合并成一次写。

共同约束

  • 入口与排序都不进 role="tablist" 的焦点序列；编辑态不改变 ←/→ 的切换语义。
  • 每个鼠标手势都有键盘路径，Esc 退出编辑态并放弃本次手势。
  • prefers-reduced-motion 下去掉位移、倾斜与弹入，只保留透明度与描边。
  • 长按阈值 260ms、位移超过 8px 立即进入拖动并取消长按计时，避免与文本选择打架。
