# 页签收纳：三个方案

当前实现的问题，逐条对应到方案里的修正：

| 问题               | 观察到的现象                                       | 为什么是问题                                     |
| ------------------ | -------------------------------------------------- | ------------------------------------------------ |
| 菜单项点击语义错位 | 点已收起的页签，它出现在行内；切到别的页签它又消失 | 那是“选中”，而选中项永远渲染，所以看起来像“显示” |
| 收起后无处可查     | 只剩一个数字角标，看不出收起了哪些                 | 用户要回忆自己收过什么                           |
| 三步才能改一个状态 | 角标 → 菜单 → 管理页签… → 弹窗里勾选               | 二态控件藏在一个弹窗后面                         |
| 拖动不可发现       | 只有一个悬停提示气泡                               | 新用户不会去悬停                                 |

## 方案 A · 就地收纳（推荐）

`a-inline-stow.html`

所有页签留在同一行，收起的排在右侧分隔线之后、淡显并带“已收起 N”。点淡显项即放回；拖过分隔线即收起，拖回即放回。

- 状态与位置合一：看一眼就知道自己收起了什么，不需要菜单。
- 二态操作一步完成。
- 代价：行更长，需要横向滚动；收起的占位始终存在。
- 键盘：分隔线可聚焦，`Alt`+方向键移动焦点页签，右侧区域用 `Home`/`End` 进入。

## 方案 B · 溢出折叠

`b-overflow.html`

行内只保留可见页签，收起的进“»”按钮（带数量）；点开是勾选清单，勾选即在原位置显示或收起。

- 行最短，最像浏览器标签页的溢出处理。
- 代价：收起的内容看不见，要再点一次才知道；仍有一个弹层。
- 与宿主其它“溢出菜单”模式一致，认知负担最低。

## 方案 C · 整理模式

`c-organise-mode.html`

普通状态行内只有“整理”按钮；点开后所有页签一律显示，带复选框和拖动手柄，退出时保存。

- 误操作最少，适合页签多、顺序讲究的场景。
- 代价：多一个模式，日常切换多一次点击；整理态与普通态视觉差异大，需要额外样式。

## 我的建议

A。理由：这个控件的核心是“我收起了什么”，A 是唯一把状态本身长期可见的方案，而且把“选中”和“显示”两件事分开了——现在的缺陷正是这两件事挤在一起。B 更省空间，但把答案藏在第二次点击之后；C 最稳，但为一个低频操作引入模式。

如果选 B，改动最小：现有菜单换成行尾按钮 + 勾选清单，选中语义保持不动。如果选 A，需要重写行的布局（分隔线、淡显态、跨分隔线拖动）和键盘穿越。

## 三份稿子的共同前提

- 主题 token 用宿主真实定义的（`bg-layer-1`、`interactive-bg-hover`、`label-secondary`），不写死颜色；这三份 HTML 里的颜色只是近似值，不是实现。
- 收纳状态继续由“一行一份、两处共用”的布局存储持有；预设管理那行只显示对它成立的页签，但隐藏集合是同一份。
- 键盘路径与拖动并存，不引入第二套模式。
