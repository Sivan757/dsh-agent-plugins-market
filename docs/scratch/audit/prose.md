# Prose that has drifted from the code

Axis: every document and comment in this repository is a claim about behaviour. This pass checked the highest-value claims first: `docs/reference/`, `README.md`, `README.zh.md`, `docs/user/`, module JSDoc, and the implemented Agent Notes. Every finding below was confirmed by opening the producer. Nothing is reported from a search hit alone.

Baseline: `dev` at `3853273`. Read-only pass.

Severity means the harm a reader suffers from believing the sentence, not the size of the edit.

## 1. D2 — The hooks guide says seven events run on the retired bridge

**Claim** (`docs/user/services.md:29`, mirrored at `docs/user/services.zh.md:29`):

> Hooks use the bridge's mapped command-hook subset at SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SubagentStart and SubagentStop.

**Contradicted by**

- `packages/market-runtime/src/runtime/surfaces/extension-hooks.ts:40-51` — `HOOK_RUNTIME_POINTS` lists ten events, adding `PostToolUseFailure`, `PreCompact` and `SessionEnd`.
- `packages/market-runtime/src/runtime/host/scoped-contributors.ts:158-172` — the per-agent hook executor is `ExtensionHooks`, built on `@deepseek-ai/dsh-hook-protocol`.
- `packages/market-bundle/src/index.ts:312` — `runtime.setAgentScopedContributors()` makes the reconciler call `this.hooks.reconcile([])` (`packages/market-runtime/src/runtime/core/reconciler.ts:252`), so the `dsh-hooks-claude-code` mount registry receives an empty suite list and mounts nothing.
- Two sibling documents already state the shipped behaviour: `docs/user/resources.md:49` ("run on ten events") and `README.md:78` ("Ten events apply what the hook returns"). `docs/user/install.md:12` correctly says session hooks "use the published hook protocol".

**Corrected sentence**

> Hooks run on the published hook protocol, on ten events: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `SubagentStart`, `SubagentStop`, `PreCompact` and `SessionEnd`.

**Why it ranks first.** The sentence is the only place a user is told the event list, and it understates the product by three events while naming a bridge this composition never mounts. [Hook event coverage](../../reference/hooks-event-coverage.md) is the owning reference and disagrees with it.

## 2. D2 — The install guide quotes a range the manifest no longer uses

**Claim** (`docs/user/install.md:10`, `docs/user/install.zh.md:10`, and the generated copies `docs-site/guide/install.md:18`, `docs-site/guide/install.zh.md:18`):

> The current package declares the DSH host packages it needs in the `^0.2.0-rc.2` range.

**Contradicted by** `package.json:104-130` and `:148-154`: every `@deepseek-ai/dsh-*` peer and dependency carries `>=0.2.0-rc.2 <0.3.0-0`. No entry uses a caret. The window replaced the caret deliberately, and the reasoning is recorded in [the host support window note](../../../.agents/notes/implemented/process/2026-10-17-host-support-window.md): a caret on a prerelease matches only its own `major.minor.patch`, so it excludes the next candidate the host ships.

**Corrected sentence**

> The current package declares the DSH host packages it needs in one support window, `>=0.2.0-rc.2 <0.3.0-0`. This is a dependency declaration, not a verified minimum version for every feature or historical Web shell.

**Owner to edit.** `docs/user/install.md` and its zh pair. `docs-site/guide/install.md` is generated by `docs-site/scripts/copy-guide.mjs` from those files; regenerate, do not hand-edit.

**Why it ranks second.** A consumer reading this sentence to decide compatibility is told a range that rejects `0.2.1-rc.x`, which is exactly the drift the gate exists to prevent.

## 3. D2 — The README names five tabs that the UI does not show

**Claim** (`README.md:83-95`, mirrored at `README.zh.md:83-95`): "The workspace has nine tabs:" followed by a "Tab" table naming **Instructions**, **Commands**, **Agent personas**, **MCP services** and **LSP servers**.

**Contradicted by** `packages/market-ui/src/locales.ts:932-938, 1062, 1100`, which is where the row reads its labels (`packages/market-ui/src/workspace/PluginWorkspace.tsx:116-126`): `Market`, `Skills`, `Shortcuts`, `Experts`, `Connectors`, `Language Engine`, `Hooks`, `Rules`, `Output styles`. Five of the nine README names match nothing in the row. `docs/user/workspace.md:21` uses the shipped names ("**Rules** (the AGENTS.md chain), **Language Engine**, and **Hooks**"), so the repository already contradicts itself.

**Corrected table** — replace the first column with the rendered label and keep the description:

| Tab             | Use it to                                                                           |
| --------------- | ----------------------------------------------------------------------------------- |
| Market          | Add sources, preview suites, install or remove them, and switch them on or off.     |
| Rules           | See the AGENTS.md chain a session injects, and create, edit or delete those files.  |
| Output styles   | Choose the instruction block that shapes how the model answers, and preview it.     |
| Skills          | Browse skills and create or edit your own reusable instructions.                    |
| Shortcuts       | Manage prompt templates invoked as `/name`.                                         |
| Experts         | Save role instructions and model settings, then delegate to them.                   |
| Connectors      | Add a service or configure an installed one, its credentials and its authorization. |
| Language Engine | Add and configure language servers, and read their runtime status.                  |
| Hooks           | Read each configured hook with its event, matcher and timeout.                      |

**Why it ranks third.** The README is the front page. A new user hunts for a "MCP services" tab and finds "Connectors".

## 4. D3 — The workspace guide counts five owner-filtered surfaces; there are six, and one does not filter by owner

**Claim** (`docs/user/workspace.md:7`, mirrored at `docs/user/workspace.zh.md:7`):

> The market filters by install state; the other five surfaces filter by owner — user, plugin — and by switched-off entries, whose count is the number of rows that filter shows.

**Contradicted by** `packages/market-contracts/src/contracts/tab-layout.ts:15` — nine tabs, six of which are resource surfaces (skills, commands, personas, mcp, lsp, hooks). And `packages/market-ui/src/features/hooks/StatusPanel.tsx:50-72` — the Hooks surface filters by support verdict, `All` / `Supported` / `Limited`, with no owner segment.

**Corrected sentence**

> The market filters by install state. Skills, Shortcuts, Experts, Connectors and Language Engine filter by owner — user or plugin — and by switched-off entries, whose count is the number of rows that filter shows. Hooks has its own three filters: all, supported, and limited to events the host cannot apply yet.

## 5. D3 — A module JSDoc describes a mount path no shipped composition reaches

**Claim** (`packages/market-runtime/src/runtime/surfaces/hooks-mounts.ts:1-10`):

> Claude Code hook compatibility: each enabled suite's `hooks/hooks.json` mounts one live `dsh-hooks-claude-code` bridge on the harness's canonical interception points (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SubagentStart, SubagentStop).

**Contradicted by**

- `packages/market-runtime/src/runtime/core/reconciler.ts:252` — the registry is reconciled with `this.agentScopedContributors ? [] : captured`, and `packages/market-bundle/src/index.ts:312` sets that flag unconditionally. The reconciler's copy therefore always mounts nothing.
- `packages/market-runtime/src/runtime/surfaces/project-runtime.ts:59` — `mountProjectHooks` is the only other constructor caller, and it has zero callers in `packages/` outside its own definition.

**Corrected JSDoc**

> Claude Code hook compatibility for the legacy `dsh-hooks-claude-code` bridge: one live bridge per suite `hooks/hooks.json` on the seven events that package maps. The shipped composition does not mount this registry: `setAgentScopedContributors` routes suite hooks to `ExtensionHooks` on `@deepseek-ai/dsh-hook-protocol`, which runs ten events. What remains here is the bridge config path helper (`hookConfigPath`) and a registry kept for compositions that still mount it.
