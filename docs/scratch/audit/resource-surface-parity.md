本文件是"合并成一个渲染器"的**交付物 1**。只做测量与判断，不改产品代码。

## 2. 决定性发现：点击卡片是什么，三套里有两套答案不同

| 表面 | 卡片点击 | 开关 | 查看详情 |
| --- | --- | --- | --- |
| A | 打开详情（`UserPanelSurface.tsx:453` `onClick: props.onOpen`） | 卡片上的 `Switch`，`stopPropagation`（`:497`） | 同左，点击即详情 |
| B | **切换启用状态**（`ResourceList.tsx:209` `interactiveCardProps(() => onToggle(row, !selected(row)))`，带 `aria-pressed`） | 卡片本身即开关 | 另设信息按钮（`:233`，`aria-label: epView`） |
| C | 打开详情 | 无 | 同左 |

这不是样式偏差：同一张卡片在 A 里是"打开详情的按钮"，在 B 里是"开关"，屏幕阅读器拿到的控件类型（`button` vs `button[aria-pressed]`）和键盘语义也不同。要求"可证明一致"，第一件事必须是把这条契约统一。按任务约束：**点击 = 打开详情；选择/启用是独立动作；破坏性操作只在详情内** —— 因此 B 需要改。

## 3. 卡片结构的重量差（29 条真实规模）

用同一批原语按各自卡片组成复现，jsdom 挂载 29 张卡（预热后第二次计时）：

| 组成                                                        | DOM 节点 | 每卡节点 | 挂载耗时 |
| ----------------------------------------------------------- | -------- | -------- | -------- |
| C：identity + 标签 + 描述 + meta                            | 175      | 6.0      | 5.07 ms  |
| A：identity + 开关/编辑/删除 + 描述                         | 262      | 9.0      | 8.99 ms  |
| B：identity + 版本 + 标签 + 信息按钮 + 开关 + 描述 + 计数器 | 378      | 13.0     | 7.41 ms  |

B 的每卡节点是 C 的 2.2 倍。合并时若保留 B 的全部装饰（版本、信息按钮、计数器），"统一渲染器"会变成最重的那一个；这些装饰应当由**能力开关**声明，而不是默认携带。

## 6. 合并口径（可执行）

1. 新建唯一渲染器 `ResourceSurface`，把 A/B/C 的列表外壳合并：
   - 输入：条目数组 + 一个 `capabilities` 声明（`toggle` / `detail` / `create` / `delete` / `badges`）；
   - 固定交互契约（类型表达）：`onOpen` 必填，`onToggle` 可选且**不与卡片点击共用命中区**。
2. A/B/C 退化为**适配器**：只负责取数、把行映射为条目、提供动作回调；不再渲染工具栏与卡片。
3. 删除 `ResourceList` 与 `UserPanelSurface` 中的列表脚手架；`presets.module.css` 的列表规则删除， `card-list-surface.module.css` 并入渲染器。
4. B 的"整卡开关"改为：卡片点击 = 详情；开关为卡片内的独立控件；信息按钮删除（其内容进详情）。
